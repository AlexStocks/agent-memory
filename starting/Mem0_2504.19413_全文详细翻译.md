## 摘要

大语言模型（LLM）在生成上下文连贯的回复方面展现出了卓越能力，然而其**固定的上下文窗口**给在长时间、多轮次（multi-session）对话中维持一致性带来了根本性挑战。我们提出 **Mem0**——一种**以记忆为中心的可扩展架构**，通过从进行中的对话里动态地**抽取、整合与检索**显著信息来解决这一问题。在此基础上，我们进一步提出一个增强变体，它利用**基于图的记忆表示**来捕捉对话元素之间复杂的关系结构。

我们在 **LOCOMO** 基准上进行了全面评估，系统地把我们的方法与六类基线进行比较：（i）已有的记忆增强系统；（ii）具有不同分块大小与 k 值的检索增强生成（RAG）；（iii）处理完整对话历史的全上下文（full-context）方法；（iv）一种开源记忆方案；（v）一个专有模型系统；（vi）一个专门的记忆管理平台。实证结果表明，我们的方法在**单跳（single-hop）、时序（temporal）、多跳（multi-hop）与开放域（open-domain）**四类问题上，一致地优于所有现有记忆系统。

值得注意的是，Mem0 在 LLM-as-a-Judge 指标上相比 OpenAI 取得了 **26% 的相对提升**，而带图记忆的 Mem0（Mem0ᵍ）的整体得分比基础配置又高出约 **2%**。除准确率收益外，相比全上下文方法，我们还显著降低了计算开销：具体而言，Mem0 的 **p95 延迟降低了 91%**，并节省了**超过 90% 的 token 成本**，在先进推理能力与实际部署约束之间提供了极具吸引力的平衡。我们的发现凸显了**结构化的、持久化的记忆机制**对长期对话连贯性的关键作用，为更可靠、更高效的 LLM 驱动 AI 智能体铺平了道路。

## 1. 引言

人类记忆是**智力的基石**——它塑造我们的身份、指导决策，并使我们能够学习、适应以及建立有意义的关系（[Craik and Jennings, 1992]）。在记忆的诸多角色中，它对**沟通**至关重要：我们回忆过去的互动、推断偏好，并为我们交往的对象构建不断演化的心理模型（[Assmann, 2011]）。这种在长时间跨度上保留与检索信息的能力，使得跨越数天、数周乃至数月的连贯且语境丰富的交流成为可能。

由大语言模型驱动的 AI 智能体，在生成流畅、语境恰当的回复方面取得了显著进展（[Yu et al., 2024]；[Zhang et al., 2024]）。然而，这些系统从根本上受制于它们对**固定上下文窗口**的依赖，这严重限制了它们在长时间交互中维持连贯性的能力（[Bulatov et al., 2022]；[Liu et al., 2023]）。这一局限源于 LLM 缺乏能够**超越其有限上下文窗口**的持久化记忆机制。人类会自然地随时间积累并组织经验，形成连续的交互叙事；而 AI 系统无法天然地在相隔的会话之间、或在上下文溢出之后保存信息。

**缺少持久化记忆，会在人机交互中造成根本性的断裂。** 没有记忆，AI 智能体会忘记用户偏好、重复提问、并与先前已确立的事实相矛盾。试想图 1 所示的一个简单例子：用户在初次对话中提到自己是素食者并且不吃奶制品。在后继会话中，当用户询问晚餐推荐时，一个**没有**持久化记忆的系统可能会推荐鸡肉，完全违背已确立的饮食偏好。相反，一个**具备**持久化记忆的系统会跨会话地保留这一关键用户信息，并推荐合适的素食、无奶制品选项。这一常见场景说明：记忆失效会如何从根本上损害用户体验与信任。

除对话场景外，记忆机制已被证明能显著提升智能体在交互式环境中的表现（[Majumder et al.]；[Shinn et al., 2023]）。装备了过往经验记忆的智能体，能更好地预判用户需求、从先前的错误中学习，并跨任务地泛化知识（[Chhikara et al., 2023]）。研究表明，记忆增强的智能体通过利用**行动与结果之间的因果关系**来改进决策，从而在动态场景中实现更有效的适应（[Rasmussen et al., 2025]）。**分层记忆架构**（[Packer et al., 2023]；[Sarthi et al., 2024]）以及能够自主演化的**智能体式记忆系统**（agentic memory systems，[Xu et al., 2025]）进一步表明：记忆能够在多个对话会话之间支持更连贯的长期推理。

> **图 1**：记忆在 AI 智能体中的重要性的示意图。**左**：没有持久化记忆时，系统会在会话之间遗忘关键用户信息（素食、无奶制品的偏好），导致不恰当的推荐。**右**：有了有效的记忆，系统会跨交互地维持这些饮食偏好，从而给出与先前确立的约束相一致的、语境恰当的推荐。

与人类不同——人类会动态地整合新信息并修正过时的信念——LLM 一旦信息落出上下文窗口，实际上就"**重置**"了（[Zhang, 2024]；[Timoneda and Vera, 2025]）。即便 OpenAI 的 GPT-4（128K token）（[Hurst et al., 2024]）、o1（200K 上下文）（[Jaech et al., 2024]）、Anthropic 的 Claude 3.7 Sonnet（200K token）（[Anthropic, 2025]），以及 Google 的 Gemini（至少 10M token）（[Team et al., 2024]）不断推高上下文长度的边界，这些改进**只是推迟而非解决**了这一根本限制。

在实际应用中，即便这些被扩展的上下文窗口也仍然不够，原因有两点，**第二点尤其重要**：

1. 随着有意义的人机关系在数周或数月中发展，对话历史不可避免地会超出即便是最宽裕的上下文上限。
2. **真实世界的对话很少保持主题连续性。** 用户可能先提到饮食偏好（是素食者），接着进行数小时与编程任务无关的讨论，然后又回到关于晚餐选择的食物类问题。在这种场景下，全上下文方法需要对**大量无关信息**进行推理，而关键的饮食偏好可能埋藏在数千 token 的编程讨论之中。

此外，仅仅提供更长的上下文并不能确保对过往信息的有效检索或利用，因为**注意力机制会随着 token 距离变远而退化**（[Guo et al., 2024]；[Nelson et al., 2024]）。这一限制在医疗保健、教育与企业级支持等**高风险领域**尤其成问题——在这些领域中，维持连续性与信任至关重要（[Hatalis et al., 2023]）。

为应对这些挑战，AI 智能体必须采用**超越静态上下文扩展**的记忆系统。一个健壮的 AI 记忆应当：*有选择地*存储重要信息、整合相关概念，并在需要时检索相关细节——**镜像人类的认知过程**（[He et al., 2024]）。通过集成这类机制，我们可以开发出这样的 AI 智能体：维持一致的人设、追踪不断演化的用户偏好，并在先前的交流之上继续构建。这一转变将把 AI 从**短暂的、健忘的应答者**变成**可靠的长期协作者**，从根本上重新定义对话智能的未来。

在本文中，我们针对 AI 系统的一个根本局限：它们**无法在跨会话的长时间对话中维持连贯推理**，这严重制约了与用户之间有意义的长期交互。我们提出 **Mem0**（读作 *mem-zero*），一种新颖的记忆架构，能够从进行中的对话里动态地**捕获、组织与检索**显著信息。在此基础上，我们开发了 **Mem0ᵍ**，它用**基于图的记忆表示**增强基础架构，以更好地建模对话元素之间的复杂关系。

我们在 LOCOMO 基准上的实验结果表明：我们的方法在多样化的问题类型上一致地优于现有记忆系统——包括记忆增强架构、检索增强生成（RAG）方法，以及开源与专有方案——同时**所需的计算资源显著更低**。延迟测量进一步显示，Mem0 的运行响应时间比全上下文方法**低 91%**，在复杂推理能力与实际部署约束之间取得了最优平衡。这些贡献向着"能够在长时间跨度上维持连贯、具备语境感知的对话"的 AI 系统迈出了有意义的一步——它镜像了人类的沟通模式，并为个性化辅导、医疗健康与个性化助理等应用开启了新的可能。

## 2. 所提出的方法

我们为 AI 智能体提出两种记忆架构：

1. **Mem0** 实现了一种新范式：通过专门的**记忆抽取**与**记忆更新**模块，从对话中抽取、评估并管理显著信息。系统处理的单位是两条参与者之间（两个用户参与者之间，或一个用户与一个助手之间）的一对消息。
2. **Mem0ᵍ** 在这一基础上扩展，引入了**基于图的记忆表示**——记忆被存储为**有向带标签图**，实体为节点、关系为边。这种结构使得对实体之间联系的理解更加深入。通过显式地同时建模**实体**与**关系**，Mem0ᵍ 支持跨互联事实的更高级推理，尤其适用于那些需要**穿越复杂关系路径**、跨越多条记忆的查询。

### 2.1 Mem0

我们的架构遵循**增量处理范式**，使其能够在进行中的对话里无缝运作。如图 2 所示，完整的流水线架构由两个阶段组成：**抽取**（extraction）与**更新**（update）。

> **图 2**：Mem0 系统架构总览，展示抽取阶段与更新阶段。抽取阶段处理消息与历史上下文以创建新记忆。更新阶段把这些抽取出的记忆与相似的已有记忆进行评估比对，并通过 **Tool Call（工具调用）机制**施加适当的操作。数据库作为中枢存储库，既为处理提供上下文，也存储更新后的记忆。

**抽取阶段**在摄入一个新的消息对 (m_{t-1}, m_t) 时启动，其中 m_t 表示当前消息、m_{t-1} 表示前一条消息。这一对消息通常由一条用户消息与一条助手回复组成，构成一个完整的交互单元。

为了给记忆抽取建立恰当的上下文，系统采用两种互补的来源：

1. 从数据库中检索的**对话摘要 S**——它封装了整个对话历史的语义内容；
2. 对话历史中的**近期消息序列** {m_{t-m}, m_{t-m+1}, ..., m_{t-2}}，其中 m 是控制"近因窗口"大小的超参数。

为了支持具备语境感知的记忆抽取，我们实现了一个**异步摘要生成模块**，周期性地刷新对话摘要。该组件独立于主处理流水线运行，确保记忆抽取始终受益于最新的上下文信息，而**不会引入处理延迟**。

- **S** 提供跨整个对话的**全局主题理解**；
- **近期消息序列**提供细粒度的**时间上下文**，其中可能包含尚未被整合进摘要的相关细节。

这种双重上下文信息与新的消息对一起，构成一个综合提示 P = (S, {m_{t-m}, ..., m_{t-2}}, m_{t-1}, m_t)，供一个通过 LLM 实现的抽取函数 φ 使用。函数 φ(P) 随后抽取出一组显著记忆 Ω = {ω₁, ω₂, ..., ωₙ}——**专门来自这次新的交流**，同时保持对对话更广阔语境的感知——从而产生供潜在纳入知识库的**候选事实**。

**更新阶段**在抽取之后，把每条候选事实与已有记忆进行评估比对，以维持一致性并避免冗余。该阶段为每条抽取出的事实 ωᵢ ∈ Ω 决定恰当的记忆管理操作（算法 1，见附录 B）：

- 对每条事实，系统首先**利用向量嵌入**从数据库中检索出 top s 条语义相似的记忆。
- 这些检索到的记忆连同候选事实一起，通过我们称为 **"工具调用"（tool call）** 的函数调用接口呈现给 LLM。
- **由 LLM 自己**决定执行四种不同操作中的哪一种：

| 操作 | 含义 |
|---|---|
| **ADD** | 当不存在语义等价的记忆时，创建新记忆 |
| **UPDATE** | 用互补信息**增补**已有记忆 |
| **DELETE** | 删除被新信息**矛盾**掉的记忆 |
| **NOOP** | 该候选事实不需要对知识库做任何修改 |

我们**没有**使用单独的分类器，而是利用 LLM 自身的推理能力，基于候选事实与已有记忆之间的语义关系直接选择适当的操作。在做出判定之后，系统执行所给出的操作，从而维持知识库的**连贯性与时间一致性**。

**实验配置**：在我们的实验评估中，系统配置为——**m = 10** 条先前的消息作为上下文参考，**s = 10** 条相似记忆用于比较分析。所有语言模型操作均使用 **GPT-4o-mini** 作为推理引擎。向量数据库采用**稠密嵌入**，以便在更新阶段进行高效的相似度搜索。

### 2.2 Mem0ᵍ

Mem0ᵍ 流水线（图 3）实现了一种基于图的记忆方法，能够有效地从自然语言交互中捕获、存储与检索上下文信息（[Zhang et al., 2022]）。在该框架中，记忆被表示为一个**有向带标签图 G = (V, E, L)**：

- **节点 V** 表示实体（例如 Alice、San_Francisco）
- **边 E** 表示实体之间的关系（例如 lives_in）
- **标签 L** 为节点赋予语义类型（例如 Alice → Person，San_Francisco → City）

每个实体节点 v ∈ V 包含三个组成部分：（1）**实体类型分类**（对实体归类，如 Person、Location、Event）；（2）**嵌入向量 eᵥ**（捕捉实体的语义）；（3）**元数据**，包括创建时间戳 tᵥ。

系统中的关系被结构化为三元组形式 (v_s, r, v_d)，其中 v_s 与 v_d 分别是源实体节点与目标实体节点，r 是连接它们的带标签边。

> **图 3**：Mem0ᵍ 的基于图的记忆架构，展示实体抽取与更新阶段。抽取阶段使用 LLM 把对话消息转换为实体与关系三元组。更新阶段在把新信息整合进现有知识图时，采用**冲突检测与消解机制**。

**抽取过程**采用一个两阶段流水线，利用 LLM 把非结构化文本转化为结构化的图表示：

1. **实体抽取器**（entity extractor）处理输入文本，识别出一组实体及其对应类型。在我们的框架中，实体代表对话中的关键信息元素——包括人物、地点、物体、概念、事件与属性——凡是值得在记忆图里表示出来的东西。实体抽取器通过分析对话中元素的**语义重要性、独特性与持久性**来识别这些多样化的信息单元。举例来说，在一场关于旅行计划的对话中，实体可能包括目的地（城市、国家）、交通方式、日期、活动与参与者偏好——本质上是任何**离散的、未来可能供参考或推理的信息**。
2. **关系生成器**（relationship generator）推导这些实体之间的有意义连接，建立一组捕获信息语义结构的**关系三元组**。这个基于 LLM 的模块分析抽取出的实体及其在对话中的上下文，以识别语义上重要的连接。它通过考察语言模式、上下文线索与领域知识，来判断实体之间如何关联。对每一个潜在的实体对，生成器评估是否存在有意义的关系；若存在，则用恰当的标签对这一关系进行分类（例如 'lives_in'、'prefers'、'owns'、'happened_on'）。该模块采用**提示工程**技术，引导 LLM 对对话中的显式陈述与**隐式信息**都进行推理，最终产出的关系三元组构成我们记忆图中的边，并支持跨互联信息的复杂推理。

**整合新信息时**，Mem0ᵍ 采用一套精密的存储与更新策略：对每一个新的关系三元组，我们为源实体与目标实体分别计算嵌入，然后搜索**语义相似度超过设定阈值 t** 的已有节点。根据节点的存在情况，系统可能创建两个节点、只创建一个节点，或直接使用已有节点，然后再以适当的元数据建立关系。为维持知识图的一致性，我们实现了**冲突检测机制**——当新信息到达时，识别可能存在冲突的已有关系。一个基于 LLM 的**更新消解器**（update resolver）判定某些关系是否应当作废，并把它们**标记为无效**（invalid）而不是物理删除，以便支持**时间推理**。

**记忆检索功能**在 Mem0ᵍ 中实现了**双路策略**，以获得最优的信息访问：

1. **以实体为中心的方法**（entity-centric）：首先识别查询中的关键实体，然后利用语义相似度在知识图中定位对应节点；接着系统地探索这些锚节点的**入边与出边**关系，构建出一个捕获相关上下文信息的综合子图。
2. **语义三元组方法**（semantic triplet）：采取更整体的视角——把整个查询编码为一个稠密嵌入向量，然后把这一查询表示与知识图中**每个关系三元组的文本编码**进行匹配。系统计算查询与所有可用三元组之间的细粒度相似度分数，只返回超过可配置相关性阈值的那些，并按相似度降序排列。

这种双检索机制使 Mem0ᵍ 能够**同等地**处理好针对性的、以实体为中心的问题，以及更宽泛的概念性查询。

**实现层面**：系统使用 **Neo4j** 作为底层图数据库。基于 LLM 的抽取器与更新模块利用具备函数调用能力的 **GPT-4o-mini**，从而支持从非结构化文本中进行结构化信息抽取。通过把基于图的表示与语义嵌入、以及基于 LLM 的信息抽取结合起来，Mem0ᵍ 同时实现了复杂推理所需的**结构丰富性**与自然语言理解所需的**语义灵活性**。

## 3. 实验设置

### 3.1 数据集

**LOCOMO**（[Maharana et al., 2024]）数据集旨在评估对话系统中的长期对话记忆。它包含 **10 段长对话**，每段平均约 **600 轮对话、26,000 token**，分布在多个会话（session）中。每段对话记录两个人讨论日常经历或过往事件。在这些多会话对话之后，每段对话平均配有 **200 个问题**及对应的标准答案（ground truth）。这些问题被分为多类：**单跳（single-hop）、多跳（multi-hop）、时序（temporal）与开放域（open-domain）**。

该数据集原本还包含一个**对抗性问题**类别，用于测试系统识别"不可回答问题"的能力。但我们在评估中**排除了**这一类别，因为标准答案不可用；而对于这类问题，期望的行为是智能体应当把它们识别为不可回答。

### 3.2 评估指标

我们的评估框架采用一套综合方法来评估对话系统的长期记忆能力，同时考虑**回复质量**与**运行效率**。我们把指标分为两组，二者合起来提供对系统性能的整体理解。

#### （1）性能指标

对话式 AI 的既往研究（[Goswami, 2025]；[Soni et al., 2024]；[Singh et al., 2020]）主要依赖诸如 **F1 分数（F1）**与 **BLEU-1（B1）**这类词汇相似度指标。然而，在对话语境中评估**事实准确性**时，这些指标存在显著局限。

试想这样一个场景：标准答案是"Alice 出生在三月"，而系统生成的是"Alice 出生在七月"。尽管在出生月份上包含了**关键的事实错误**，传统指标却会因为剩余 token（"Alice"、"出生"等）的词汇重叠而给出相对较高的分数。这一根本缺陷会导致**误导性的评估结果**，无法捕捉语义正确性。

为弥补这些不足，我们使用 **LLM-as-a-Judge（J）** 作为补充评估指标。该方法利用一个独立的、能力更强的 LLM，从多个维度评估回复质量，包括**事实准确性、相关性、完整性与语境恰当性**。裁判模型会分析问题、标准答案与生成的答案，给出更细致、更贴近人类判断的评估。

由于 J 评估具有随机性，我们对每种方法在整个数据集上进行了 **10 次独立运行**，并报告**均值 ± 1 个标准差**。关于 J 的更多细节见附录 A。

#### （2）部署指标

除回复质量外，对 AI 智能体长期记忆的真实部署而言，实际部署考量至关重要。我们系统地追踪：

- **Token 消耗**：使用 tiktoken 的 `cl100k_base` 编码，度量在检索时抽取出的、作为回答查询上下文的 token 数。对我们的基于记忆的模型而言，这些 token 代表从知识库中**检索到的记忆**；对基于 RAG 的模型而言，它们对应**检索到的文本分块的总 token 数**。这一区分很重要，因为它直接影响运营成本与系统效率——无论处理的是**简明的记忆事实**还是**更大的原始文本片段**。
- **延迟（Latency）**：（i）*搜索延迟*：搜索记忆（基于记忆的方案）或分块（基于 RAG 的方案）所需的总时间；（ii）*总延迟*：生成恰当回复的时间，由检索时间（访问记忆或分块）与使用 LLM 生成答案的时间两部分组成。

这些指标之间的关系揭示了系统设计中的重要**权衡**。例如，更精密的记忆架构可能获得更高的事实准确性，但代价是 token 消耗与延迟的增加。我们的多维度评估方法，使研究者与从业者能够基于其具体需求做出明智决策——无论是对关键应用优先保证回复质量，还是对实时部署场景优先保证计算效率。

### 3.3 基线

为全面评估我们的方法，我们与代表当前对话记忆系统水平的**六类不同基线**进行比较。这些多样化的基线共同提供了一个稳健的框架，用于在事实准确性、计算效率以及面向长对话的可扩展性等多个维度上评估不同记忆架构的有效性。在适用的情况下，除非另有说明，我们把 **temperature 设为 0**，以尽可能确保运行可复现。

#### 已有的 LOCOMO 基准方法

我们首先通过在 LOCOMO 数据集上评估此前已被基准测试过的方法，建立比较基础。这包括五种已有方法：**LoCoMo**（[Maharana et al., 2024]）、**ReadAgent**（[Lee et al., 2024]）、**MemoryBank**（[Zhong et al., 2024]）、**MemGPT**（[Packer et al., 2023]）与 **A-Mem**（[Xu et al., 2025]）。这些既有基准不仅提供了与已发表结果的直接比较点，也代表了对话记忆架构在不同算法范式下的演进。在我们的评估中，我们选取那些**使用 gpt-4o-mini 进行评估**的指标。关于这些基准的更多细节见附录 C。

#### 开源记忆方案

第二类由前景良好的开源记忆架构组成，例如 **LangMem**（Hot Path）——它们在相关对话任务中已展现出有效性，但尚未在 LOCOMO 数据集上被评估过。通过把这些系统适配到我们的评估框架中，我们拓宽了比较视野，并识别出可能提供有竞争力表现的替代方案。我们用 gpt-4o-mini 初始化 LLM，并使用 `text-embedding-small-3` 作为嵌入模型。

#### 检索增强生成（RAG）

作为基线，我们把**整个对话历史**视为一个文档集合，并应用标准 RAG 流水线：

- 首先把每段对话切分为固定长度的分块（**128、256、512、1024、2048、4096、8192** token），其中 8192 是我们的嵌入模型支持的最大分块大小。
- 所有分块使用 OpenAI 的 `text-embedding-small-3` 嵌入，以确保各配置间向量质量一致。
- 在查询时，按语义相似度检索 **top-k** 个分块并拼接为答案生成的上下文。
- 在整个实验中我们设定 **k ∈ {1, 2}**：k=1 时只使用最相关的单个分块；k=2 时拼接两个最相关的分块（最多 16384 token）。我们**避免使用 k > 2**，因为平均对话长度（26000 token）会被完全覆盖，从而使选择性检索的收益消失。

通过变动分块大小与 k 值，我们系统地评估 RAG 在长期对话记忆任务上的表现。

#### 全上下文处理（Full-Context Processing）

我们采用一种直截了当的方法：把整个对话历史传入 LLM 的上下文窗口内。该方法利用模型处理序列信息的固有能力，无需额外的架构组件。虽然概念上简单，但随着对话长度增加，这种方法面临实际限制——最终导致 token 成本与延迟上升。尽管如此，它为理解"更精密的记忆机制相比直接处理可用上下文的价值"建立了一个重要的参照点。

#### 专有模型

我们评估 OpenAI 在其 ChatGPT 界面中提供的 **memory** 功能，为保持一致性同样使用 gpt-4o-mini。我们把完整的 LOCOMO 对话配合一个提示（见附录 A）输入到单个聊天会话中，提示模型生成**带时间戳、参与者姓名与对话文本**的记忆。然后，这些生成的记忆被用作回答每段对话相关问题的**完整上下文**——我们**有意地**授予 OpenAI 这一方案访问**全部**记忆的特权，而非只访问与问题相关的记忆。这样做是为了适应 OpenAI 系统缺乏可用于选择性记忆检索的外部 API 这一限制，以便于基准比较。

#### 记忆服务提供商（Memory Providers）

我们纳入 **Zep**（[Rasmussen et al., 2025]）——一个为 AI 智能体设计的记忆管理平台。我们使用其平台版本，在 LOCOMO 数据集上进行系统评估，并通过**保留时间戳信息**与对话内容一起来维持**时间保真度**。这种时间锚定确保了：对时间敏感的查询可以通过具备恰当语境的记忆检索得到解决——这对评估那些需要**时序感知**的问题尤为重要。该基线代表了专门为 AI 智能体设计的记忆管理的重要商业实现。

## 4. 评估结果、分析与讨论

### 4.1 跨记忆增强系统的性能比较

表 1 报告了我们的两种架构——Mem0 与 Mem0ᵍ——相对一整套有竞争力基线（见第 3 节）在**单跳、多跳、开放域与时序**问题上的 F1、B1 与 J 分数。总体而言，我们的两个模型在**大多数问题类型的全部三项评估指标上都创下了新的最先进水平**。

#### 单跳问题表现

单跳查询需要定位包含在**单个对话轮次内**的一个事实片段。借助其自然语言文本形式的稠密记忆，Mem0 取得了最强结果：**F1 = 38.72，B1 = 27.13，J = 67.13**。用图记忆增强自然语言记忆（Mem0ᵍ）相较 Mem0 产生了**轻微的性能下降**，这表明：当检索目标只占据单个轮次时，关系结构提供的效用有限。

在现有基线中，**全上下文的 OpenAI 运行**取得了次优的 J 分数，反映出把整个对话保留在上下文中的收益；而 **LangMem 与 Zep** 在 J 分数上都比我们的模型**相对低约 8%**。此前的 LOCOMO 基准方法如 A-Mem 在 J 上落后**超过 25 个点**——这凸显了即便对于简单的检索任务，**细粒度的、结构化的记忆索引**也是必要的。

#### 多跳问题表现

多跳查询需要综合分散在**多个对话会话**中的信息，对记忆整合与检索提出了重大挑战。Mem0 以 **F1 = 28.64、J = 51.15** 的成绩明显优于其他方法，反映出它高效检索与整合跨会话存储的不同信息的能力。

有趣的是，在 Mem0ᵍ 中加入图记忆**在此并未带来性能增益**——这表明：相比单纯的稠密自然语言记忆，结构化的图表示在复杂的整合任务中可能存在**效率低下或冗余**。LangMem 等基线表现出有竞争力的性能，但其分数大幅落后于 Mem0，凸显了我们精炼的记忆索引与检索机制在复杂查询处理上的优势。

#### 开放域表现

在开放域设置中，基线 **Zep** 取得了最高的 F1（**49.56**）与 J（**76.60**）分数，以**微弱优势**压过我们的方法。具体而言，Zep 的 J 分数 76.60 仅比 Mem0ᵍ 的 75.71 高出 **0.89 个百分点**，比 Mem0 的 72.93 高出 **3.67** 个百分点——凸显出它在"把对话记忆与外部知识整合"方面**持续但轻微**的优势。

Mem0ᵍ 仍是强劲的亚军，J = 75.71 反映出很高的**事实检索精度**；Mem0 以 72.93 紧随其后，展现出稳健的连贯性。这些结果说明：尽管结构化的关系记忆（如 Mem0 与 Mem0ᵍ 中的）大幅改善了开放域检索，**Zep 仍保持着小幅但有意义的领先**。

#### 时序推理表现

时序推理任务取决于对**事件序列、它们的相对顺序与持续时间**的准确建模。我们的架构在所有指标上都展现出显著改进，其中 **Mem0ᵍ 取得最高的 F1（51.55）与 J（58.13）**——这表明：在自然语言记忆之外**加上**结构化的关系表示，能显著帮助**基于时间的判断**。

值得注意的是，基础变体 Mem0 也给出了不错的 J 分数（55.51），说明**仅靠自然语言**也能辅助基于时间的判断。在基线中，**OpenAI 表现明显不佳**，分数低于 15%，主要原因是尽管已明确提示要在 ChatGPT 中抽取带时间戳的记忆，其生成的大多数记忆**仍然缺少时间戳**。其他基线如 A-Mem 取得了可观的结果，但我们的模型显然推进了最先进水平，凸显了**同时准确利用自然语言语境化与结构化图表示**对时序推理的关键优势。

### 4.2 跨类别分析

跨不同问题类别的综合评估显示，我们提出的架构 Mem0 与 Mem0ᵍ **一致地**取得了优于基线系统的表现。

- 对于**单跳查询**，Mem0 表现尤其强劲，受益于其高效的稠密自然语言记忆结构。尽管 Mem0ᵍ 中基于图的表示在这些较简单查询的**词汇重叠指标**上略微落后，但它们显著增强了**语义连贯性**——这一点由有竞争力的 J 分数所证明。这表明：图结构在涉及**微妙关系语境**的场景中更有助益，而非用于直截了当的检索。
- 对于**多跳问题**，Mem0 展现出明显优势，能够有效地综合跨多个会话的分散信息，证实了自然语言记忆为这类整合任务提供了**足够的表示丰富性**。令人意外的是，Mem0ᵍ 预期中的关系优势**并未转化为更好的结果**，这暗示在多步推理场景中导航更复杂的图结构时，可能存在**开销或冗余**。
- 在**时序推理**方面，Mem0ᵍ 大幅优于其他方法，验证了结构化的关系图在捕获**时间顺序关系与事件序列**上的卓越能力。显式的关系语境显著增强了 Mem0ᵍ 的时序连贯性，使其胜过 Mem0 的稠密记忆存储——凸显了在追踪**时间敏感信息**时精确关系表示的重要性。
- **开放域表现**进一步强化了关系建模的价值。Mem0ᵍ 受益于基于图的记忆所带来的关系清晰性，与表现最好的基线（Zep）**势均力敌**。这一竞争性的结果凸显了 Mem0ᵍ 在通过关系清晰性整合外部知识方面的**稳健性**，暗示了结构化记忆与开放域信息综合之间的**最优协同**。

总体而言，我们的分析表明 Mem0 与 Mem0ᵍ 在不同任务需求上具有**互补的优势**：稠密的、基于自然语言的记忆为较简单的查询提供了显著的效率；而显式的关系建模则成为那些需要**微妙的时间与语境整合**的任务的必要条件。这些发现强化了"在 AI 智能体部署中，应针对特定推理语境定制**可适配的记忆结构**"的重要性。

### 4.3 Mem0 与 Mem0ᵍ 相对 RAG 方法与全上下文模型的性能比较

聚焦于表 2 中的 **"Overall J"（整体 J）** 列可以发现：Mem0 与 Mem0ᵍ **一致地优于所有 RAG 配置**——无论其分块大小（128–8192 token）如何变化，也无论检索一个（k=1）还是两个（k=2）分块。

即便是最强的 RAG 方法，其 J 指标的峰值也只有约 **61%**；而 Mem0 达到 **67%**（约 **10% 的相对提升**），Mem0ᵍ 超过 **68%**（约 **12% 的相对增益**）。这些进步凸显了"**只捕获最显著的事实**存入记忆"相对于"检索大块原始文本"的优势：通过把对话历史转换为**简明的、结构化的表示**，Mem0 与 Mem0ᵍ 降低了噪声，并向 LLM 呈现更精确的线索，从而得到由外部 LLM（J）评判的更好答案。

尽管有这些改进，一种把约 **26,000 token** 的整块内容塞进上下文的**全上下文方法**仍然取得了最高的 J 分数（约 **73%**）。但如图 4(b) 所示，它也带来了**极高的总 p95 延迟——约 17 秒**，因为模型必须在每次查询时通读整个对话。

相比之下，Mem0 与 Mem0ᵍ 显著降低了 token 使用，因而实现了更低的 p95 延迟，分别约为 **1.44 秒（降低 92%）** 与 **2.6 秒（降低 85%）**。虽然全上下文方法能提供轻微的准确率优势，但基于记忆的系统提供了**更实用的权衡**——在保持接近竞争力的质量的同时，只施加一小部分的 token 与延迟成本。

随着对话长度增加，全上下文方法会遭受**计算开销的指数级增长**（这一点在表 2 中很明显：总 p95 延迟随 k 值或分块大小的增大而显著上升）。输入块的增加导致更长的响应时间与更高的 token 消耗成本。相比之下，像 Mem0 与 Mem0ᵍ 这样**以记忆为中心**的方法，其性能**不随对话长度变化**——这使得它们在效率与响应性至关重要的**生产规模部署**中明显更可行。

### 4.4 延迟分析

表 2 全面比较了各种检索与记忆方法的性能，给出了在 LOCOMO 数据集上**搜索阶段**与**总回复生成**的中位数（p50）与尾部（p95）延迟。我们的分析揭示了由架构选择决定的不同性能模式。

**以记忆为中心的架构**展现出不同的性能特征：

- **A-Mem** 尽管记忆库更大，却产生了可观的搜索开销（p50: 0.668s），导致总中位数延迟为 1.410s。
- **LangMem** 表现出甚至更高的搜索延迟（p50: 17.99s，p95: 59.82s），使其**不适用于交互式应用**。
- **Zep** 取得中等表现（总 p50: 1.292s）。

**全上下文基线**处理整个对话历史而不做检索，与基于检索的方法有着本质区别。通过把整个对话上下文（26000 token）直接传给 LLM，它消除了搜索开销，但产生了**极端的总延迟**（p50: 9.870s，p95: 17.117s）。

类似地，**OpenAI 的实现**并不执行记忆搜索，因为它处理的是从其 playground 中手动抽取的记忆。虽然这种方法实现了令人印象深刻的回复生成时间（p50: 0.466s，p95: 0.889s），但它**需要预先抽取**相关上下文——这一成本并未反映在报告出的指标中。

我们提出的 **Mem0** 方法在所有方法中实现了**最低的搜索延迟**（p50: 0.148s，p95: 0.200s），如图 4(a) 所示。这一效率源于我们的**选择性记忆检索机制**与基础设施改进——它动态地识别并只检索最显著的信息，而非固定大小的分块。因此，Mem0 保持了最低的总中位数延迟（**0.708s**），且 p95 值被出色地控制在 **1.440s**，这使其特别适合**延迟敏感型应用**，如交互式 AI 智能体。

**图增强的 Mem0ᵍ** 变体以适度的延迟代价引入了额外的关系建模能力，其搜索时间（0.476s）**仍然优于所有现有记忆方案与基线**。尽管有这一增加，Mem0ᵍ 保持了有竞争力的总延迟（p50: 1.091s，p95: 2.590s），同时取得了所有方法中最高的 J 分数（**68.44%**）——仅次于在计算上令人望而却步的全上下文方法。这一性能剖面证明了我们的方法能够**平衡回复质量与计算效率**，为"这两个因素都是关键约束"的生产级 AI 智能体提供了极具吸引力的解决方案。

### 4.5 记忆系统开销：Token 分析与构建时间

我们度量了实现每个系统的长期记忆库所需的**平均 token 预算**：

- **Mem0** 以自然语言表示编码完整的对话轮次，因此每段对话平均只占用 **7k token**。
- **Mem0ᵍ** 由于引入了包含节点与对应关系的图记忆，占用量大致翻番至 **14k token**。
- 形成鲜明对比的是，**Zep 的记忆图消耗超过 600k token**。这种膨胀源于 Zep 的设计选择：它在**每个节点缓存一份完整的抽象摘要**，同时还在连接边上存储事实，导致整个图中存在**大量冗余**。
- 作为参照：把**整个原始对话上下文**直接提供给语言模型（不做任何记忆抽象）平均约为 **26k token**——相比 Zep 的图**少了 20 倍**。

除 token 低效之外，我们的实验还揭示了 Zep 的**显著运维瓶颈**：在向 Zep 系统添加记忆之后，我们观察到**立即进行记忆检索的尝试常常无法正确回答我们的查询**。有趣的是，**在数小时的延迟之后重新运行完全相同的搜索，结果明显更好**。这一滞后说明 Zep 的图构建涉及**多次异步 LLM 调用与大量的后台处理**，使得该记忆系统**不适用于实时应用**。

相比之下，**Mem0 的图构建即使在最坏情况下也能在一分钟内完成**，使用户能够立即利用新添加的记忆来回答查询。

这些发现凸显出：Zep 不仅在多个节点间**复制了相同的知识片段**，还引入了**显著的运维延迟**。我们的架构——Mem0 与 Mem0ᵍ——以**一小部分的 token 成本**保留了同样的信息，并且记忆可用速度**显著更快**，提供了一种**更节省记忆、运维响应更及时**的表示。

## 5. 结论与未来工作

我们提出了 **Mem0** 与 **Mem0ᵍ**——两种互补的记忆架构，它们克服了 LLM 固定上下文窗口的固有局限。通过动态地抽取、整合与检索**紧凑的记忆表示**，Mem0 在**单跳与多跳**推理上取得了最先进的性能，而 Mem0ᵍ 基于图的扩展则在**时序与开放域**任务上解锁了显著增益。

在 LOCOMO 基准上，我们的方法相对各问题类型上的最佳现有方法，在单跳、时序与多跳推理问题类型上分别取得了 **5%、11% 与 7% 的相对提升**，并且相比全上下文基线的 p95 延迟**降低了 91% 以上**——展现了**精确性与响应性之间的强有力平衡**。

- **Mem0 的稠密记忆流水线**擅长对直接查询的快速检索，把 token 使用与计算开销降到最低。
- 相比之下，**Mem0ᵍ 的结构化图表示**提供了细致的关系清晰性，使复杂事件排序与丰富的上下文整合成为可能，同时**不牺牲实际效率**。

二者共同构成了一个**多功能的记忆工具箱**，既能适应多样化的对话需求，又能保持可规模化部署。

**未来的研究方向**包括：

1. 优化图操作，以降低 Mem0ᵍ 中的延迟开销；
2. 探索**分层记忆架构**，把效率与关系表示融合起来；
3. 开发受人类认知过程启发的、**更精密的记忆整合机制**；
4. 把我们的记忆框架扩展到对话场景之外的领域，例如**程序性推理**与**多模态交互**，以进一步验证其更广泛的适用性。

通过解决固定上下文窗口这一根本局限，我们的工作代表着一次重要进展——向着"能够在长时间跨度上维持连贯、语境丰富的交互"的对话式 AI 系统迈进，就像它们的人类 counterpart（对应方）一样。

### 附录 B：算法

**算法 1：记忆管理系统——更新操作**

```
1:  输入：检索到的记忆集合 F，已有记忆库 M = {m1, m2, ..., mn}
2:  输出：更新后的记忆库 M'
3:
4:  procedure UpdateMemory(F, M)                       ▷ 更新记忆过程
5:      for each fact f ∈ F do                        ▷ 遍历每条候选事实
6:          operation ← ClassifyOperation(f, M)       ▷ 依据分类执行相应操作
7:          if operation = ADD then                   ▷ 新增：无语义等价记忆时
8:              id ← GenerateUniqueID()               ▷ 生成唯一标识
9:              M ← M ∪ {(id, f, "ADD")}              ▷ 以唯一 ID 加入新事实
10:         else if operation = UPDATE then           ▷ 更新：增补已有记忆
11:             mi ← FindRelatedMemory(f, M)          ▷ 找到相关记忆
12:             if InformationContent(f) > InformationContent(mi) then
13:                 M ← (M \ {mi}) ∪ {(idi, f, "UPDATE")}   ▷ 以信息量更丰富者替换
14:             end if
15:         else if operation = DELETE then           ▷ 删除：新信息与之矛盾
16:             mi ← FindContradictedMemory(f, M)     ▷ 找到被矛盾的记忆
17:             M ← M \ {mi}                          ▷ 移除矛盾信息
18:         else if operation = NOOP then             ▷ 无操作
19:             No operation performed                ▷ 事实已存在或不相关
20:         end if
21:     end for
22:     return M
23: end procedure
24:
25: function ClassifyOperation(f, M)                  ▷ 操作分类函数
26:     if ¬SemanticallySimilar(f, M) then            ▷ 记忆中不存在的新信息
27:         return ADD
28:     else if Contradicts(f, M) then                ▷ 与已有记忆冲突
29:         return DELETE
30:     else if Augments(f, M) then                   ▷ 对已有信息的增强
31:         return UPDATE
32:     else                                          ▷ 无需改变
33:         return NOOP
34:     end if
35: end function
```

> **中译说明**：`ClassifyOperation` 的四个判定谓词（SemanticallySimilar / Contradicts / Augments）在真实系统中由 LLM 通过工具调用（function calling）实现，而非硬编码规则；`InformationContent(f) > InformationContent(mᵢ)` 的条件意为"仅当新事实的信息量高于旧记忆时才替换"。

### 附录 C：所选基线说明

#### LoCoMo

LoCoMo 框架实现了一套精密的记忆流水线，使 LLM 智能体能够维持连贯的长期对话。其核心是把记忆划分为**短期**与**长期**两个组件。

在每个对话会话结束后，智能体会生成**摘要**（作为短期记忆存储），提炼该次交互的关键信息；同时，各个对话轮次被转化为"**观察**"（observations）——关于每位说话者人设与生活事件的事实性陈述，连同产生它们的**具体对话轮次的引用**一起存入长期记忆。

生成新回复时，智能体同时利用**最近的会话摘要**与从长期记忆中**选择性检索**出的相关观察。这一双记忆方法还因引入了**时间事件图**（temporal event graph）而进一步增强——该图追踪会话之间发生的、有因果关联的生活事件。

通过把回复条件化于：检索到的记忆 + 当前对话上下文 + 人设信息 + 中间发生的生活事件，该系统使智能体能够在跨越数百轮、数十个会话的对话中维持一致的人格并回忆重要细节。

#### ReadAgent

ReadAgent 通过一套精密的三阶段流水线——模拟人类处理长文本的方式——来解决 LLM 的根本局限：

1. ** Episode Pagination（情节分页）**：系统按**自然的认知边界**而非任意的截断点对文本进行智能切分。
2. **Memory Gisting（记忆要点化）**：把每个片段蒸馏为简明摘要，在大幅减少 token 数的同时保留核心含义——类似于人类记忆保留信息**要义**而非逐字回忆。
3. **Interactive Lookup（交互式查找）**：当需要回答问题时，该机制检查这些要点（gists），并策略性地只检索**最相关的原始文本片段**做进一步处理。

这种受人类启发的方法使 LLM 能够有效管理**长达其正常上下文窗口 20 倍**的文档。通过以 gists 获得全局理解、再以选择性注意力关注细节，ReadAgent 同时实现了计算效率与理解力的提升，证明了模仿人类认知过程能显著增强 AI 的文本处理能力。

#### MemoryBank

MemoryBank 系统通过一套精密的三段式流水线为 LLM 增强长期记忆：

- **记忆存储**（Memory Storage）组件：仓储详细的对话日志、**分层事件摘要**与不断演化的**用户人格画像**。
- 当新的交互发生时，**记忆检索**（Memory Retrieval）机制采用**双塔稠密检索模型**来抽取上下文相关的过往信息。
- **记忆更新**（Memory Updating）组件提供了一种**类人的遗忘机制**：记忆在被回忆时会增强，若长期不用则会随时间**自然衰减**。

这一综合方法使 AI 伴侣能够回忆相关信息、在长时间交互中维持语境感知，并发展出越来越准确的用户画像，从而带来更个性化、更自然的长期对话。

#### MemGPT

MemGPT 系统引入了一种**受操作系统启发**的方法来克服 LLM 固有的上下文窗口限制。其核心是一套由三个关键组件构成的精密记忆管理流水线：**分层记忆系统**、**自我导向的记忆操作**，以及**基于事件的控制流机制**。

系统把可用记忆划分为"**主上下文**"（类比传统操作系统中的 RAM）与"**外部上下文**"（类比磁盘存储）：

- 主上下文受 LLM 上下文窗口约束，包含系统指令、近期对话历史，以及可被模型修改的**工作记忆**。
- 外部上下文在模型即时上下文窗口之外存储无限量的信息，包括完整的对话历史与归档数据。

当 LLM 需要不在主上下文中的信息时，它可以发起**函数调用**来跨这些记忆层搜索、检索或修改内容，有效地在其有限上下文窗口中"**换页**"（paging）地换入换出相关信息。

这种受操作系统启发的架构使 MemGPT 能够：在长时间交互中维持对话连贯性、管理超出标准上下文限制的文档、并完成多跳信息检索任务——**而这一切都是在固定上下文模型上运行的**。该系统智能管理自身记忆资源的能力提供了"无限上下文"的假象，显著拓展了当前 LLM 技术的可能性边界。

#### A-Mem

A-Mem 模型提出了一种为 LLM 智能体设计的**智能体式记忆系统**（agentic memory system）。该系统通过**相互连接的笔记**（notes）来动态地结构化并演化记忆。

每条笔记捕获一次交互，并由 LLM 生成结构化属性加以丰富，如**关键词**、**上下文描述**与**标签**。当创建一条新记忆时，A-MEM 使用语义嵌入检索相关的已有笔记，然后采用 LLM 驱动的方法，基于**相似性与共享属性**建立有意义的链接。

关键的是，**记忆演化机制**会动态更新已有笔记——每当整合新的相关记忆时，就精炼它们的上下文信息与属性。因此，记忆结构**持续演化**，使记忆之间形成更丰富、语境更深的连接。

从记忆中检索是通过**语义相似度**进行的，从而在智能体交互过程中提供相关的历史上下文。
