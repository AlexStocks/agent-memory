## 1. MERIT：记忆评测选错了题

**When Does Memory Help? A Cost-Aware Evaluation of Long-Term Memory in Tool-Using LLM Agents**
Shweta Mishra、Shashank Mishra（Independent Research）· arXiv:2609.05441（v1 2026-07-26）· 代码 <https://github.com/smshweta/merit-bench>

### 1.1 它要解决的问题

作者指出当前 agent 记忆评测的三个盲区：

1. **对话式问答不等于任务执行。** LoCoMo、LongMemEval、BEAM 测的是「能不能回答关于一长串对话的问题」，但生产中的 agent 要用记住的事去**选对工具调用**：正确的客户 ID、先前约定的退款金额、上周事故里确认的配置修复项。前者能否转化为后者，此前没有实证答案。
2. **默认记忆「有帮助」，其危害却未被度量。** 对话场景下的记忆幻觉已有 HaluMem 等考察；但在任务执行中，一条陈旧记忆（旧地址、被回滚的配置）不只是「没用」，它会引发一个自信但错误的动作。而且还有一个更基础的失败没被量化过：agent 明明在上下文里持有正确事实、却仍不据此行动。
3. **报告了成本，却没报告边际效用。** 从业者面对的是经济性问题：加记忆是否足以提升任务成功率、从而证明每任务成本合理？此前没有跨记忆架构的「成本调整后边际效用」报告。

MERIT = **M**emory **E**valuation for **R**ealistic **I**nstrumented **T**asks，它同时回应这三个盲区。

### 1.2 基准怎么造的

**幕（episode）** 是一次 agent 会话，包含一名模拟用户、一个作用于可变世界状态（SQLite）之上的工具 API。幕被编组为**弧（arc）**，每条弧含 4—6 个共享实体的幕：

- **种植幕（plant）**：某一事实通过对话建立；用户当时**明确禁止**据此行动；
- **更新幕（update，可选）**：事实被修订；
- **探针幕（probe）**：成功依赖该事实，而该事实**不在本幕输入中**；
- **独立幕（independent）**：仅凭本幕即可求解。

**三个领域**：

| 领域 | 工具 | 涉及事实 |
|---|---|---|
| D1 客服（零售） | `get_order`、`refund`、`update_address`、`get_policy`、`send_message` | 约定好的部分退款金额、更新后的地址 |
| D2 IT 运维 | `search_logs`、`get_deploy_history`、`get_config`、`set_config`、`deploy`、`update_ticket` | 诊断出的配置修复项、安全的回滚版本 |
| D3 个人助理 | `get_calendar`、`create_event`、`send_email`、`get_preference`、`set_preference` | 固定的房间/时间偏好、晚餐约定（地点、日期、时间） |

**难度阶梯**：易 = 每个探针一条金标准事实；中 = 多事实探针（每个金标准值都必须出现在执行的工具调用里）；**难 = 更新事实探针**——值先被种植、在后续某幕被修订，而探针要的是最新值。难层是针对「覆盖式存储」与「累积式存储」这两种架构的定向压力测试。

**六种记忆条件**（统一接口 `write(episode)` / `read(context)`）：

| 条件 | 含义 | 起始实现 | 真实实现 |
|---|---|---|---|
| C0 | 无记忆 | — | — |
| C1 | 对先前转录文本的完整重放 | — | — |
| C2 | 检索 | 关键词重叠 | 嵌入检索（`text-embedding-3-small`） |
| C3 | 滚动摘要 | 抽取式截断 | LLM 摘要 |
| C4 | 带写时更新的结构化事实库 | 基于模式的抽取 | LLM 抽取 |
| C5 | 混合（C4 + C2） | — | — |

所有条件共享同一 agent 脚手架（ReAct 式工具循环）、相同提示词（记忆块除外）、相同工具与相同解码（temperature 0）。**这点很关键**：条件之间的差异只来自记忆，不来自 agent。

**两道不可或缺的防护机制**（都是因为早期运行没有它们而失败才补上的）：

- **泄漏检查（leak check）**：在生成时断言每个金标准事实值都不出现在探针幕的输入中、也不出现在初始世界状态中，且金标准值在整条弧内保持唯一。这保证了「除了记忆之外没有任何通路能拿到金标准事实」。
- **增量计分（delta scoring）**：只当某幕的校验谓词**在该幕内由假翻转为真**时才记为成功。早期运行里，过于急切的 agent 在种植幕就处理了退款，于是探针幕靠「继承来的世界状态」虚假成功；增量计分彻底消除了这条世界状态泄漏通道（9,940 幕里 22 个探针幕抵达时校验器已满足，被计为失败而非继承的成功）。

作者强调这是一条**方法学贡献**：任务执行型记忆基准拥有对话式问答基准无法表达的泄漏通道，建议把「针对世界状态、而非仅针对提示词」的泄漏检查作为标准实践。

**指标**：

- **TSR**：程序化最终状态检查得出的任务成功率，按依赖型/独立型拆分；
- **MUR（记忆利用率）**：在所有金标准值都出现在被检索记忆块中的依赖型幕里，每个金标准值都出现在执行的工具调用参数中的比例（值追踪）；
- **忽略率** = 1 − MUR；
- **SMH（陈旧记忆危害）** = TSR(clean) − TSR(corrupted)；
- **成本与 CAMU**：每幕计量的 token 与美元；CAMU = ΔTSR(相对 C0) / Δcost(相对 C0)，另报盈亏平衡任务价值。

MUR 追踪器是字符串包含式的，用一个冻结的、分层抽样的 100 幕审计样本做过验证：一名人类标注者盲标全部 100 条，追踪器在 **93%** 上与人类一致（Cohen's κ = 0.63，实质性一致）；7 处分歧方向全部一致，且都是追踪器**低估**利用率，因此报告的忽略率是**保守上界**。

**规模**：试点两代 9,940 幕 / $9.12；预先注册的完整网格 13,500 幕 / $33.45；合计 **23,440 幕 / $42.57**。模型为 gpt-4.1-mini（3 种子）、GPT-4.1、Claude Haiku 4.5，**记忆侧固定为 gpt-4.1-mini**，因此 agent 模型是唯一变量。

### 1.3 关键结果

**① 记忆确实有用，地板是真的。**

C0 在全部九个（领域 × 难度）格子上、两代中都取得依赖型任务 **0.000**——泄漏检查成立。在独立任务上 C0 取得 0.83—1.00，确认任务本身可解。加上记忆后被抬到 0.55—1.00。

**② 难层上，嵌入检索崩了，而且崩得不可预测。**

| 难层 TSR（依赖型） | Haiku 4.5 | GPT-4.1 | gpt-4.1-mini (±sd) |
|---|---|---|---|
| C2 嵌入检索 — D1 | 0.90 | 0.70 | 0.70 ± 0.23 |
| C2 嵌入检索 — D2 | 0.95 | 0.45 | 0.38 ± 0.08 |
| C2 嵌入检索 — D3 | 0.30 | 0.60 | 0.37 ± 0.03 |
| C3 LLM 摘要 — D1 | 1.00 | 1.00 | 0.98 ± 0.03 |
| C3 LLM 摘要 — D2 | 1.00 | 0.90 | 0.80 ± 0.10 |
| C3 LLM 摘要 — D3 | 1.00 | 1.00 | 1.00 ± 0.00 |
| C4 结构化事实库 — D1 | 1.00 | 1.00 | 0.93 ± 0.08 |
| C4 结构化事实库 — D2 | 1.00 | 1.00 | 0.90 ± 0.05 |
| C4 结构化事实库 — D3 | 0.70 | 0.90 | 0.90 ± 0.09 |

- **种子方差集中在嵌入检索上**：C2 的种子间最大两两差距平均 0.16（所有条件中最大），最差格子达 **0.45**（D1-难，三种子为 0.45 / 0.90 / 0.75）。也就是说，单种子评测如实报告出的数字可能落在 0.45 到 0.90 之间的任何位置。
- **崩溃跨模型复现，但位置因模型而异**：没有哪个模型幸免，每个模型都至少有一个领域 ≤0.60，跨「模型 × 领域」总跨度 **0.30—0.95**。
- **该区分对每个模型都统计显著**：难层合并各领域后按弧聚类的配对 bootstrap 给出 C3−C2 = **+0.44**[+0.36, +0.53]（gpt-4.1-mini）、**+0.38**[+0.23, +0.53]（GPT-4.1）、**+0.28**[+0.15, +0.43]（Haiku 4.5），全部 p ≤ 0.0002；Sonnet 5 抽检格子 **+0.25**[+0.10, +0.40]。
- 作者的归因：**检索把陈旧值与新鲜值并排返回，而返回内容里没有时效性信号可供仲裁**；写时更新在写入那一刻就把旧值覆盖掉，冲突根本不存在。所以 C2 的成败取决于「那个特定 agent 能否在上下文中自行解决新陈冲突」，而这能力随模型档次**非单调**变化。
- 一个反直觉的发现：**混合方案（C5）不如它「较好的那一半」**——难层上三个领域均为 0.50—0.80，而 C4 为 0.75—1.00。检索那一半把事实库已经消除的陈旧性重新引入了。
- C3（LLM 摘要）稳健的原因不是摘要更聪明，而是**它每一幕都重写状态**，因此天然保留最新值。同一个 C3 用截断式摘要（起始实现）时，难层只有 0.00 / 0.15 / 0.00。所以「摘要」这一族内部差得极远：问题不在「写了状态」，而在「写了一次之后不再动」。这一条直接限定了 ProMem 标题里 *Beyond Static Summarization* 的射程——「static」承担了全部论证重量。

**③ 一个此前没被量化过的失败面：agent 会忽略它已经拿到的记忆。**

- 难层合并各领域后，共有 55 个探针幕的记忆块里出现过正确（最新）值，agent 只对其中 30 个付诸行动，**忽略率 0.45**（起始代 0.53）。**提升检索质量几乎无济于事。**
- 即便 C1（记忆块就是一份干净完整的转录），在多事实的中层幕里也会忽略掉多达 **0.50** 的自己手里有的事实。
- 轨迹里两种模式：一是在检索条件下，陈旧值与新鲜值并存，agent 会「取平均」「追问」或干脆挑中陈旧的那个；二是需要组合多个事实时，agent 只对它认为离任务最近的那部分事实行动。
- 结论：**记忆的「呈现方式」——来源标记、时效标记、矛盾是否被凸显——和记忆的「存储」一样重要。**

**④ 起始实现 vs 真实实现：替换本身就有诊断价值。**

| 条件升级 | 变化 |
|---|---|
| C3 摘要：截断 → LLM | 难层 0.00 / 0.15 / 0.00 → **1.00 / 0.70 / 1.00** |
| C4 事实库：模式抽取 → LLM 抽取 | D2 中层 **1.00 → 0.40**（−60 分）；易层 0.60→0.55；难层 0.90→0.75；D1/D3 大致持平 |
| C2 检索：关键词 → 嵌入 | 处处小幅提升（难层 +0.10 至 +0.25），**难层崩溃依旧**（缺的是时效性仲裁，不是检索质量） |

**替换记忆的实现方式可以让任务成功率朝任一方向变动最多 1.00 TSR。** 作者由此提出「实现敏感度带」概念，并把它本身当作支持「以动作级评测取代记忆系统基准」的论据。

**⑤ 陈旧记忆危害落在最该防守的地方。**

| 条件 | SMH（ρ 与显著性） | 说明 |
|---|---|---|
| C5 混合 | **+0.25**（ρ = 0.3，Holm 校正后 p = 0.030） | 唯一达到统计显著性的危害 |
| C4（LLM 抽取） | +0.20（原始 p = 0.013，未过 Holm） | 通用抽取器会摄入刚性模式本来会拒绝的损坏记录 |
| C4（正则抽取） | ≤ 0.05 | 手工模式在这里是保护而非累赘 |

**⑥ 成本从来不是决定因素。**

D1-易层每幕成本：C0 $0.00046、C4 $0.00066、C2 $0.00073、C3 $0.00095、C5 $0.00111、C1 $0.00126（2,914 token/幕，是 C0 的 2.7×）。

- **CAMU 与准确率的排名在每个领域都不同**：D1 最优 C4（每边际美元 4,839 分）、D3 最优 C4（3,245），而 D2 最优是 C2（6,629）——在那里 LLM 抽取的准确率回归抹去了 C4 的优势。
- **全重放从来不是经济之选**（1,222—1,741 分/美元，比各领域最优差 **2.7—3.9×**）。
- **对所有条件，盈亏平衡任务价值都在「不到一美分」量级。** 所以在这些模型价格下，从业者真正在选的是**鲁棒性**，不是每幕省下的那点钱。（绝对 CAMU 数字与 2026 年中的 API 定价绑定，会随价格漂移；但「鲁棒性而非每幕成本是决定性因素」这一定性结论与价格无关。）

**⑦ 一个全新的维度：记忆来源怀疑（memory-provenance skepticism）。**

在 Claude Opus 4.8 上跑诊断格子（D1-难，6 条件 × 50 幕）时：无记忆地板依然成立（C0 = 0.00），但**全重放控制 C1 崩到 0.75**（三个网格模型均为 1.00）。轨迹显示原因不是记忆故障——模型**引用**了它记住的金额，然后拒绝据此行动，称更新线索「只能追溯回我自己的确认消息」，并为其视为「聊天升级型退款」的事项请求主管确认。作者把这归为安全姿态的产物，并给出两点启示：

1. 跨模型的原始 TSR 比较把「记忆使用」与「策略审慎」混为一谈，**C1 控制恰能检测这一混淆**，跨模型数字应相对于每个模型自身的 C1 来读；
2. 经过安全调优的模型可能越来越多地把记忆来源当作决策的一部分，只给任务完成打分的基准会把它误读为一个更弱的 agent。

同厂商的 Claude Sonnet 5 干净通过了该控制（C1 = 1.00）并复现了原模式（D1-难上 C2 0.75 vs C3/C4 1.00），说明**审慎混淆是特定安全姿态的属性，而非模型代际的属性**。

### 1.4 边界与短板

**构念**：程序化校验器可能无法捕捉所有真实世界的成功概念；MUR 追踪器是字符串包含式的，只对照**单一**人类标注者做过验证（κ = 0.63，方向保守），尚无独立双人标注。

**外部效度**：三个领域都是**程序化构造、配脚本化用户**（用 LLM 改写模式缓解 D1 上的措辞过拟合），每格 10 弧；每个真实记忆实现只是其家族中的一个代表——而论文自己量化了「换实现能差 60 分」。前沿与最新一代模型抽检只有诊断格子（一个领域、50 幕、两个模型），**不构成排行榜条目**。

**可复现性**：确定性的带种子生成、固定模型 ID、公开发布轨迹、$0 模拟模型（62 个单元测试覆盖）。API 模型弃用仍是局限，但框架接受任何 OpenAI 兼容端点，网格可重跑。

### 1.5 怎么用这篇

- **最适合**：论证「写入侧决定上限」、度量忽略率与陈旧记忆危害、给「换实现 = 换结果」提供量化依据。
- **不要拿来**：把它的绝对分数当排行榜；或把它的结论外推到非合成领域。它的**定性结论**（写时更新在事实演化场景胜出、全重放从不经济、成本不是决定因素）比绝对分数更值得引用。

## 2. LazyMem：写入时干脆什么也不做

**Retrieve Broadly, Construct Selectively for Efficient Long-Term Agent Memory**
Jing Yu、Yibo Zhao、Jiaming Zhang、Xiang Li（华东师范大学数据科学与工程学院）· arXiv:2607.22690（v1 2026-07-17 / v2 2026-07-28）· 代码 <https://github.com/allacnobug/LazyMem>

### 2.1 它要解决的问题

长期记忆让 agent 能复用过往交互，但原始对话历史冗长且信息稀疏。这造成一个两难：**噪声与碎片化使相关证据难以检索；而为提高覆盖而扩大召回池又会增加上下文负担、进一步稀释关键信息。**

主流做法（论文称为 **construct-then-retrieve**，先构造后检索）在存储前就把交互摘要、改写、聚合或链接成结构化单元。它便利了查询匹配、减轻了下游推理负担，但有一个结构性缺陷：**写入时的构造必然与查询无关（query-agnostic）**。既然还不知道未来要问什么，它就可能丢掉后来才显得关键的细节，**而丢掉是不可逆的**。

支撑材料相当硬：**AMA-Bench 的消融显示，即使把检索错误完全排除，拿到「构造后记忆」的模型也显著差于拿到对应黄金交互轮次的模型**——损失来自构造这一步本身。

### 2.2 方法

LazyMem 是 **retrieve-then-construct（先检索后构造）**：写入时原样存储、零处理；所有工作推迟到查询时刻。名字体现两种「懒惰」：写入时不做事，且把构造工作交给一个小模型，让主推理模型不碰原始记忆。

**三个阶段**：

1. **宽泛检索**：稠密（双编码器）与稀疏（BM25）检索器在 q 上并行运行，用倒数排名融合（RRF）合并，再由交叉编码器重排、保留前 n 条，构成高召回池 R_q。检索组件全是现成的，LazyMem 的贡献在候选池之后。
2. **选择性构造**：把候选池压缩为紧凑的、以查询为条件的记忆上下文 m_q。做法分两步——
   - **历史窗口化**：检索到的消息已剥离上下文，孤立处理会破坏对话连贯性（比如解析一个代词需要前几轮）。于是把每条消息 d_i 扩展为包含自身及左右各 w 条消息的片段；相邻片段重叠时合并为一个窗口（当 idx(d_{i+1}) − idx(d_i) ≤ 2w，按传递性应用得到最大无重复上下文窗口）；超长窗口再切成重叠子窗口，以约束单次模型调用的输入长度。
   - **记忆处理模型**：一个 4B 模型 π_θ 以单条消息为粒度独立处理每一对 (q, W_j)，对窗口内每条消息预测 **Keep / Drop**；Keep 的消息被改写成只含查询相关内容的压缩形式。重叠子窗口给出冲突预测时按位置去重、**优先 Keep**，平局按窗口顺序；存活结果按时间顺序拼成 m_q。
   - 窗口并行处理，让候选池增大时时延被约束住。
3. **作答**：作答模型接收 q 与 m_q，产出预测。

**训练**：SFT 打底，再用分组策略优化（GRPO）微调。

- **SFT**：从带「黄金 / 非黄金」标签的源交互构建样本。黄金消息含回答所需证据。用遵循指令的教师模型为每条消息标注 Keep/Drop 并生成压缩文本；若教师丢掉黄金消息、输出不可解析、违反 schema，或决策数量与窗口大小不符，则丢弃该样本。得到的检查点作为参考策略 π_ref。
- **GRPO（含 DAPO 改造）**：每个提示把查询与一条证据窗口配对，采样 G 个候选输出，优势按组内归一化；重要性采样比做**非对称裁剪**（ε_l / ε_h，遵循 DAPO）；与 DAPO 不同的是**保留 KL 惩罚**贴近 π_ref；代理项按整组 token 级归一化（除以总 token 数而非逐输出平均），使较长输出不被降权。
- **奖励 = 格式门控 × 复合量**：R = **1**[o ∈ V] · (λ_act·R_act + λ_qual·R_qual)。输出必须是一个匹配规定 schema 的单个 JSON 对象、对窗口内每条消息恰好一个决策、且为每条 Keep 消息提供压缩内容，否则**零奖励**。
  - **动作奖励 R_act**：复用数据集自身的黄金标注，逐条消息打分——黄金+Keep 得 r_g；黄金+Drop 罚 −p_g；非黄金+Drop 得 r_n；非黄金+Keep 罚 −p_n。这种**非对称设计**奖励「保留黄金、丢弃非黄金」并惩罚相反操作。分别在黄金与非黄金类别内取均值、再对出现的类别取平均，使两类权重相等、数量多的类别无法主导；最后按下界/上界重缩放到 [0,1]。
  - **质量奖励 R_qual**：只评判保留内容的质量（「保留是否为正确动作」交给 R_act）。LLM 评判器在两个维度上按 {0,1,2} 打分：**忠实度 f_x**（压缩内容是否被源消息支撑）与**效用 u_x**（对回答查询的有用程度）。逐条得分 Q(x) = **1**[f_x > 0] · (f_x + u_x)/4 ——**忠实度做门控**：完全不忠实的内容无论看起来多有用都得零分；部分忠实的留在门限之上但得分更低。分级得分比二元门控给 GRPO 的优势归一化提供更多信号。
  - **奖励课程**：约束 λ_act + λ_qual = 1 且均 ≥ 0（使奖励尺度固定）。第一阶段 (λ_act, λ_qual) = (1, 0)，只用格式门控与廉价的基于规则的动作奖励；一旦验证集格式有效率超过阈值 τ，**一次性切换**到固定的正权重预设并保持不变，以降低早期训练成本。

| 指标 | 结果 |
|---|---|

| LongMemEval，LazyMem-4B | LJ **0.85**，仅用 **213 个记忆 token** |

| 时延 | vs NanoMemory：LJ 0.80 → **0.85**，平均端到端 **55.35 s → 40.86 s** |

**为什么能超过黄金上下文**：收益集中在**聚合型与时间导向型**题型。单个 oracle 轮次或会话装不下散布于多个会话的证据，而提供完整会话又会引入噪声；查询时构造通过「以问题为条件过滤被检索上下文」同时规避两个问题——去噪的同时保留跨会话证据。在单事实题型（KU、SSA、SSU）上 oracle 已足够，两者都饱和在 1.00 附近。

**唯一落后 oracle 的题型是 SSP（0.50 对 0.67）**——基于用户历史的推荐，这种设定偏好**持久的用户画像**，而非按需组装证据：写入时方法（StructMem 0.83、Mem0 0.83）大幅优于所有查询时方法。

**效应出现在 LongMemEval 而非 LoCoMo 上的原因是召回差异**：LongMemEval 的近召回接近完整（All@50 = 0.99），瓶颈在噪声，**仅过滤就足以超过黄金上下文基线**；LoCoMo 召回较低（All@50 = 0.89），过滤有帮助但找不回缺失的证据，收益仅限于「追平」而非「超过」oracle。

**消融（累积式训练）**：

| MPM | LongMemEval LJ | 格式有效率 | LoCoMo LJ | 格式有效率 |
|---|---|---|---|---|
| Qwen3-4B（仅提示） | 0.41 | 0.397 | 0.56 | 0.622 |
| + SFT | 0.72 | 0.963 | 0.63 | 0.985 |
| + RL（GRPO） | **0.85** | 0.997 | **0.68** | 0.997 |

SFT 的增益有相当一部分来自消除畸形/错位的门控输出（格式有效率大幅提升），但**格式合规本身不保证语义正确**；RL 再提升 0.13 与 0.05，而格式已接近饱和，说明这些增益来自与任务相关的构造能力，而非格式改进。受益最大的是 SSP、TR 与 MS。

**错误归因**（按「首个出错的阶段」分类）：

| 基准 | 变体 | 检索遗漏 | 编辑损失 | QA 推理 |
|---|---|---|---|---|
| LongMemEval | 4B | 0 (0%) | **13 (87%)** | 2 (13%) |
| LongMemEval | 32B | 0 (0%) | **7 (100%)** | 0 (0%) |
| LoCoMo | 4B | 24 (40%) | 12 (20%) | 24 (40%) |

结论：**检索与作答模型阶段已基本饱和，剩余增益集中在构造阶段。** 4B 的多会话（MS）差距（0.93→0.67）也源于此：4B 编辑器更频繁地丢弃那些「单独看无关、合起来对跨会话聚合必要」的片段（MS 上编辑损失错误 8 处 vs 32B 仅 1 处）。

### 2.4 边界与短板

- **它按「相关性」构造，不按「时效性」仲裁。** 查询时构造同样可能挑中陈旧值——那正是 MERIT 里嵌入检索崩塌的成因。「哪个才是当前值」它答不了，仍得由写入路径回答。**LazyMem 解决的是「会不会丢」，没有解决「哪个是对的」。**
- **SSP 题型落后 oracle**（0.50 vs 0.67），说明持久用户画像仍需写入时维护。
- 它的 0.85 是 **LLM 评判准确率**，与本系列其它百分数不同源、不可相加。
- 标题里的「零构造」严格说是「写入时零有损构造」——写入仍然要存储并检索，只是不做压缩。

### 2.5 怎么用这篇

- **最适合**：论证「写时零构造」这条路线及其成本结构；以及为「查询分布未知、写入时判断更容易出错」的场景提供选型依据。
- **不要拿来**：当成「写时门控没用了」的证据。它和 P-2 的分歧并不在「写时 vs 读时」，而在**是否在写入时不可逆地丢信息**——P-2 把被拒绝的对象放进冷归档而非删除，两者在这一点上其实同侧。

## 3. UMA：把「写什么」交给学习

**Learning to Remember: End-to-End Training of Memory Agents for Long-Context Reasoning**
Kehao Zhang、Shangtong Gui、Sheng Yang、Wei Chen（理想汽车）、Yang Feng（通讯，中科院计算所 / 中国科学院大学）· arXiv:2602.18493（v1 2026-02-13）· EMNLP 2026 Main · 代码 <https://github.com/ictnlp/unified-memory-agent>

### 3.1 它要解决的问题

长上下文模型与 RAG 有一个共通的深层局限：**被动的信息处理**——把上下文当作静态原材料，把所有推理（状态追踪、矛盾消解、证据聚合）推迟到查询时刻。这在带有频繁更新的超长数据流下会变得脆弱。RAG 必须为每个查询重新处理检索到的原始段落；长上下文模型则受「上下文腐化（context rot）」影响——即便所有相关信息都已就位，随着输入长度增加性能仍显著退化。

记忆增强型 agent 提供了另一条路：**主动推理**——信息到来时就加以整合。但现有方法各有局限：

- **启发式方法**（Mem0、Zep）：依赖手工设计的提示与记忆模式，**缺乏任务适应性**；
- **解耦架构**（Memory-R1、Mem-alpha）：把记忆管理与任务执行分开训练，根本问题是——**任务结果产生的信用（credit）无法回流去塑造记忆决策**。做得对还是做得错，写记忆的那部分拿不到信号。

### 3.2 方法

**形式化**：把长上下文推理形式化为 MDP，输入分解为分块流 C = {c_1, …, c_n}。

- **状态** s_t = (M_t, x_t, h_t)。M_t = (m_core, B) 是双重记忆——高层核心摘要 + 结构化键值库；x_t 是当前输入焦点，在分块（维护阶段）与查询（问答阶段）之间切换；h_t 是即时交互历史，周期性清空以管理上下文长度。
- **动作空间统一在一个策略里**，只读工具两阶段都可用（确保 agent 随时能核验信念）：
  - 记忆操作 A_mem：**Add / Update / Delete**（改库 B）、**Retrieve / List**（改之前先查已有键值）、**UpdateCore**（特殊终止动作，把进度提交到 m_core 并触发向下一分块转移）；
  - 问答操作 A_qa：**BM25(query) / Embedding(query)**（对原始分块的混合检索）、**Retrieve(key) / List()**（访问结构化库）、**Answer(text)**（终止动作）。
- **转移动态是分层的**：**内层循环**是普通工具动作，更新 B 或追加 h_t，不推进输入流；**外层循环**由 UpdateCore 触发状态转移，推进到 c_{k+1} 并重置 h_t；**阶段转移**在处理完 c_n 后进入 QA 阶段，此时 x_t 变为从 P(q|C) 采样的查询。这个随机转移意味着**最优策略必须构建出一个足够稳健的记忆状态，以最大化对所有潜在未来查询的期望回报**。

**架构**：输入 = [I_sys, m_core, x_t, h_t]。阶段一（顺序记忆维护）对每个分块迭代采样动作直到输出 UpdateCore；阶段二（混合检索增强问答）同时用结构化库与原始文本检索收集证据，直到输出 Answer。

**训练：任务分层 GRPO（Task-Stratified GRPO）**。把 GRPO 视作无价值网络的蒙特卡洛优势估计器，改造成适配本任务的分层结构：

- **嵌套轨迹采样**：对给定上下文 C，先采样 N 条记忆轨迹得到 N 个最终记忆状态；对每个记忆状态采样 M 个问题；对每一对生成一条 QA 轨迹并计算最终奖励 R_{i,j}。每个更新步共产生 **N × M** 条完整轨迹。
- **奖励函数**：R = λ_tool · r_tool + r_outcome。其中 r_tool = N_valid / N_total（奖励有效的 API 用法、惩罚语法错误），r_outcome 评估最终答案与真值的一致性。
- **关键机制：「未来效用信号」。** 记忆步会收到一个由后续 QA 奖励导出的信号——这是让信用回流到记忆决策的具体通路。
- **分层归一化**：所有记忆步被聚合进一个全局池（G_mem）归一化，而 QA 步严格在其各自的查询组内归一化（G_qa,j）。作者的理由是：不加区分地把异构奖励（二值 QA 得分 vs 聚合的记忆效用）混在一起会**稀释学习信号**。

**Ledger-QA 基准**：答案由**累积更新导出的潜在值**决定，而不是靠检索某个局部片段就能拼出来——专门测连续状态追踪。这是它作为诊断基准的核心设计。

| 变体 | 平均 | Δ |
|---|---|---|

几条读法：

- **放弃端到端（2 Stage）掉 11 个百分点**，且仍低于 w/o RL 变体——这不只是「联合训练略有收益」，而是**记忆策略的价值主要来自端到端的信用回流**。作者归因于训练—测试错位：孤立优化阶段一无法预知在最终 QA 策略下哪些信息最有用，孤立优化阶段二也无法反过来塑造上游的记忆决策。
- **仅仅是赋予 agent「写入」能力就比被动检索更有利**：不用 RL 时，有记忆的 61.38% vs 无状态的 45.26%。
- **分层归一化本身是有效的**：全局组变体 73.58% < 76.46%/77.36%，证实混合异构奖励会稀释学习信号。

### 3.4 边界与短板

- **需要一个可自动判分的任务分布。** 奖励来自下游任务结果，所以「什么值得记」这个问题只有在下游可自动判分时才成立。「Ledger-QA 对得上账吗」可以算，「这段用户对话里什么值得记」不行。**在开放场景里这条路暂时接不上——它能学的，是有验证信号的那部分记忆。**
- **硬性上下文窗口上限**（例如 16k token，靠截断强制）。记忆库缓解了信息丢失，但「在没有任何原始上下文兜底的情况下管理跨越数百万 token 的记忆」仍是开放挑战。
- **Ledger-QA 是合成生成的**，真实记账/状态追踪场景可能包含更多非结构化噪声与歧义。
- **依赖一组特定工具**（CRUD + 检索），扩展到多模态记忆或更复杂工具使用模式仍需研究。
- ⚠️ 译文正文与表 1 在完整 UMA 的平均分上有细微不一致（正文多处写 **76.46%**，表 1 为 **77.36%**，应是论文两个版本间的差异）。引用时建议以表 1 的 77.36% 为准，或回到 arXiv 当前版本核对。

### 3.5 怎么用这篇

- **不要拿来**：当成开放场景的方案。它的适用边界就是「存在可自动判分的任务分布」。

## 4. Revoked：写对了还不够，撤销要能被执行

**Revoked but Still Authoritative: An Empirical Study of Revocation Enforcement in Agent-Memory Systems**
Yi Ting Shen、Kentaroh Toyoda、Alex Leung（Vulcan Research, AIFT，新加坡）· arXiv:2609.08258（v1 2026-09-08）· 代码 <https://github.com/VulcanLab/Memory-Rebirth-Attack>

### 4.1 它要解决的问题

这一代记忆系统普遍采用**软撤销（soft revocation）**——把被矛盾的事实标记为无效并保留，而不是删除。这个设计支持审计与时间点查询，也避免了破坏性更新的数据丢失。但论文问了一个此前没人测过的问题：

> **这个标记在检索时真的被执行了吗？** 把一条事实标记为无效，能否阻止存储系统把它返回给一个会据此采取行动的 agent？

### 4.2 方法

**符号体系**（这篇的形式化很干净，值得直接抄）：

- 记忆存储 M = {r_1, …, r_n}，每条记录带事实文本 txt(r)、时间戳 τ(r)，以及状态标志 **ρ(r) ∈ {1 已撤销, 0 当前, ⊥ 不对调用方暴露}**。
- 第三个取值的必要性在于：被测系统之一是**在内部把记录标记为已撤销却不对调用方暴露任何状态**，这直接限制了该系统上可表达的防御。所以「未能记录一次撤销的存储」与「本就没有可记录内容的存储」在 ρ 上无法区分——这正是三种失效形式中的第一种。
- 检索 R(q, M, k) 取 k = 10，**默认检索、不施加任何状态限制**。智能体只收到 txt(·)，因为 **ρ 与 τ 都是记录元数据，不会进入 prompt**。这是标准应用模式，也正是为什么**上下文中没有任何信息能指明两条相互冲突的策略哪条是无效的**。

**两阶段流水线**：

- **设置阶段**：在存储中放入两条相互矛盾的策略——v_1（较旧的已撤销记录）与 v_2（其替代项）。两种插入模式：**直接插入**（按系统原生格式写两条记录，已撤销状态有保证）与**间接插入**（让系统摄取存在矛盾关系的纯文本，**系统自身的抽取必须自行检测取代并自行撤销**，状态因此不确定）。两种模式检索完全相同，差异只在于存储如何达到该状态。
- **实验阶段**：就受影响主题提一个普通问题 → 默认检索返回最相近记录 → 智能体在安全动作与不安全动作之间决策。九种场景中的五种里，系统 prompt 额外禁止不安全动作。每个「场景—模型」组合在 temperature 0.7 下运行 10 次试验。

**覆盖范围**：5 个记忆系统 × 9 种策略场景 × 9 种模型 × 6 种防御条件。

| 系统 | 更新机制（实测） | 检索 | 插入方式 |
|---|---|---|---|
| Graphiti | 通过有效性时间戳进行软撤销 | **返回已撤销记录（默认）** | 两者皆可 |
| mem0（默认） | 过期标记（直接）；整合时新增而不淘汰（间接） | 默认扣留已撤销记录 | 两者皆可 |
| mem0（exp.） | 同上 | **返回已撤销记录（标志覆盖）** | 两者皆可 |
| langmem | 整合触发时原地覆盖，时有时无 | 默认不保留已撤销记录 | 两者皆可 |
| cognee | 剪枝—再摄取；无事实级矛盾步骤 | 默认不保留已撤销记录 | 两者皆可 |
| Zep CE | 软撤销，同一引擎；把一条策略拆分到多条边上只撤销部分 | **返回已撤销记录，但不向调用方暴露状态** | 仅间接 |

重点：**五款系统共享相同的嵌入模型与相同的抽取模型**，所以检索与抽取质量在系统间没有差异。另外论文发现**一些项目的撤销实现与其文档描述不同**，因此「更新机制」列报告的是**实测行为**而非文档声称的行为。

**九种模型**跨三个能力层级、七个家族、六家厂商：旗舰（GPT-5.5 / Grok-4 / DeepSeek-V4-Flash）、高效（GPT-5-nano / Gemini-2.5-Flash / Grok-4-Fast）、开放权重（GLM-5.2 / Gemma-3-27B-IT / Kimi-K2.6）。

### 4.3 关键结果

**① 没有任何系统在默认情况下强制执行撤销。** 五款里两款把已撤销记录送到 agent 面前，而且**每一次都排在替代它的新策略之上**（各 81/81）。

| 系统 | 暴露率 | 排名 | 无防御 | 存储级过滤 | 提示加固 | 输出过滤 | 过滤+提示 |
|---|---|---|---|---|---|---|---|
| Graphiti | 81/81 | 1 | **44.2%**（358/810） | 0.0% | 38.4% | 19.0% | 0.0% |
| mem0 (exp.) | 81/81 | 1 | **42.1%**（341/810） | 0.0% | 36.0% | 17.2% | 0.0% |
| cognee、langmem、mem0（默认） | 0/81 | 未返回已撤销记录 | — | — | — | — | — |

两款暴露系统合计：**1,620 次试验中 699 次（43.1%）采取了不安全动作**。按场景速率跨度 0.0%—94.4%，按模型 15.0%—60.0%。

**为什么已撤销记录总排第一**：已撤销策略的措辞往往比替代项更绝对（「必须被阻断」对比「被监控」），而**按相似度排序的检索器偏好这种措辞**。论文另引一项独立证据：在良性的带版本文档基准上，常规检索正确回答 58% 的问题，图基变体 64%。

**② 三种失效形态**：

1. **撤销从未被记录**（cognee、langmem，以及间接插入下的 mem0）。在间接插入下，这三者在 9 个场景中的 **0 个**里记录了撤销状态，却同时存储了两份策略。
2. **记录了，但状态对调用方隐瞒**，任何应用都无法执行撤销（Zep）。
3. **记录了、也可见，但在检索时不被执行**（Graphiti 默认，以及开启了过期标志覆盖的 mem0）。

只有第三种能被端到端量化。**间接插入的测量表明这一前置条件无需特权即可出现**：Graphiti 从纯矛盾文本中在 4/9 个场景记录了撤销，Zep 在 6/9 个场景记录。

**③ 防御条件的有效性差异极大。**

| 防御 | 作用位置 | 不安全动作率 |
|---|---|---|
| 无防御 | — | 43.1%（699/1,620） |
| 提示词加固 | 读取之后 | 37.2% |
| 输出过滤 | 读取之后 | 18.1%（且被额外告知了「哪条是已撤销的」） |
| 存储级过滤 | 读取之前 | **0.0%（0/1,620）** |
| 过滤器 + 提示词加固 | 两者 | 0.0% |

- **仅提示加固几乎无效（43.1% → 37.2%）**：提示要求模型忽略被取代的事实，**但被检索的上下文并没有指明哪条被取代了**，模型必须在缺少所需信息的情况下做判断。
- **输出过滤只在 18.1%**，而且是在没有任何部署都具备的优势下取得的：它在判定拦截什么时，**被给予了已撤销事实文本**。
- **存储级过滤彻底消除该效应**（0/1,620）。

**④ 失效在检索侧，不在存储侧。** 论文做了一个很干净的消融：**同一份 mem0 数据，只改一个检索标志**，81 个匹配单元中有 **39 个从安全翻成不安全，且从未反向**。两种配置之间的差异不过是**一个出厂产品中的一个布尔值**。互补比较也支持这个归因：两款被暴露系统是独立实现，但在相同场景与模型网格上**无法区分**（81 个匹配对上 p = 0.629；17 个单元意见不一致，10:7 的分裂与均等分裂相容）。

**⑤ 这和模型能力无关。**

| 模型 | 无防御 | 提示加固 | 输出过滤 |
|---|---|---|---|
| GPT-5.5 | 33.3% | 26.7% | 12.2% |
| Grok-4 | 52.2% | 47.8% | 33.3% |
| DeepSeek-V4-Flash | 58.9% | 50.6% | 21.1% |
| GPT-5-nano | 55.6% | 43.9% | 23.9% |
| Gemini-2.5-Flash | 60.0% | 46.1% | 9.4% |
| **Grok-4-Fast（非推理）** | **15.0%** | 9.4% | 11.7% |
| GLM-5.2 | 33.3% | 33.3% | 11.1% |
| Gemma-3-27B-IT | 38.9% | 43.3% | 34.4% |
| Kimi-K2.6 | 41.1% | 33.9% | 5.6% |

**九种模型全部中招（15.0%—60.0%），且能力层级与不安全动作率之间没有相关性**——旗舰组跨度 33.3%—58.9%，而整个集合里最抗的是一个快速的**非推理**模型。原因是两条策略在上下文里以平等的姿态出现，被撤销的那条通常措辞更绝对，模型手里没有任何可区分它们的依据。**推理质量并不决定结果。**

**⑥ 有规则 vs 无规则。**（论文明说这两组**不是受控比较**——场景、动作集与干扰项数量都不同，且从未在同一场景上测「有禁令」与「无禁令」两种情况。）

| 分组 | 无防御（合并） | 无防御（剔除离群） | 检索过滤 |
|---|---|---|---|
| 有规则 | 12.9%（116/900） | **4.6%**（33/720）ᵃ | 0.0% |
| 无规则 | 81.0%（583/720） | **86.7%**（468/540）ᵇ | 0.0% |

ᵃ 剔除备份删除；ᵇ 剔除已存储访问指令。

- 无规则组不安全动作率 81.0%，PII 导出达 94.4%；
- 有规则组 12.9%，但**由单一场景主导**：备份删除达 46.1%，贡献了 116 次绕过中的 83 次；剔除后其余四个场景合计 4.6%（保守数字）。
- 备份删除是唯一带条件例外的规则（要求 CISO 书面批准），也是唯一其已撤销文本主张优先权的规则——**两个特征无法分离**，高比率不能单独归因于其中任何一个。
- 效应在「不安全动作操作上看似合理」时最大，在「脱离策略也能被独立识别为有害」时最小（超限转账 3.9%、豁免 MFA 0.6%、日志删除 0 次）。这些低比率是**预训练拒绝而非提示规则**解释的。
- 携带规则的那一组只支持一个更窄的论断：**提示词里的禁令并不可靠地阻止不安全动作。**

**⑦ 守卫（guard）：在检索环节缓解该失效。**

设计要点：位于 agent 与任一记忆后端之间，拦截每一次读取，检查后端返回给普通调用方的事实，**扣留**那些能确定为已撤销或与替代项冲突的记录。分两阶段、从可靠到较不可靠：

1. 后端暴露显式状态字段时用这些字段——**精确，但需要厂商配合**；
2. 在剩余内容中，检测那些针对同一主题声明**互不兼容取值**的事实对，扣留较旧的那条——**不需要后端做任何事**，也是唯一能捕获「没有任何系统曾经标记过」的内容的阶段。

被扣留的事实与原因一起单独返回，应用可以报告冲突而非丢失历史；**存储中没有任何内容被删除**。

一个重要的设计教训：早期版本按**结果顺序**打破平局，这不稳健——**结果顺序是相关性排序而非时间顺序**。面对不暴露任何元数据的后端，它扣留了当前策略而保留了已撤销的那条，把 0% 的不安全率变成 **100%**。因此当前设计在守卫无法确定两条冲突事实哪条更旧时，**保留二者并报告冲突**。

评估结果（要说清哪里是独立证据）：

- 在存储暴露标记处，守卫与存储级过滤器一致（0/1,620；Graphiti 上扣留 18/18 条已撤销事实、mem0 上 12/12，当前记录零条）。**但这不构成独立证据**——守卫第一阶段读的是与过滤器相同的字段。这只表明守卫**可部署**，而非其设计稳健。
- **独立的结果出现在间接插入下**，那里没有任何标记可供任何过滤器读取：两个 mem0 配置上守卫为 **0/810**，而存储过滤器为 5/810 与 24/810；Zep 上 **315/810 vs 364/810**——而 Zep 的 API **根本无法表达一个过滤器**。这是本研究唯一一处守卫做了存储级过滤器所不能做的事的地方。
- 代价：守卫也会扣留当前事实。间接插入下它在 cognee 与 Graphiti 上略差于无防御（因为冲突测试也会匹配「并非已撤销策略与其替代项」的冲突对）；在 Zep 上只捕获 4/14，因为 Zep 把一条策略拆分到多条边上且只撤销其中部分，而返回文本没有说明哪一条是。

### 4.4 边界与短板

- **这是相关性研究，不是因果实验。** 场景分组之间在动作集、干扰项数量上都不同，论文明确说两组不是受控比较。
- **「有规则」组只支持一个更窄的论断**——提示词里的禁令不可靠，不能推出「规则无效」。
- **守卫与存储级过滤器的一致（0/1,620）不是独立证据**（读的是相同字段）；真正独立的证据只在间接插入条件下。
- **不应被当成某个产品的缺陷报告**——失效在检索范式本身，不是某一家实现的 bug。
- 覆盖率虽然跨 5 系统 × 9 场景 × 9 模型，但每个「场景—模型」组合只有 10 次试验，论文自己也说结论依赖于**跨单元差异**而非单元内抽样精度。

### 4.5 怎么用这篇

- **最适合**：论证检索层有效性闸门是必需品；为「归档而非删除」补上必要条件——归档只保证信息还在，**不保证陈旧信息不再指挥 agent**。
- **关键判据一句话**：**所缺失的控制是「检索时有效性」，而不是来源。** 来源检查（provenance）在这一设定下按构造就会放行——因为记录来自防御者本人，是系统随后把它标记为无效的。

## 5. MemoryLACE：中间路线的归档语义

**MemoryLACE: Memory Lifecycle-Aware Consolidation and Evidence Retrieval**
Meriem Yacoubi、Pia Schmidt、Nenad Petrovic、Ahmed Frikha、Martin Kirchhoff、Alois Knoll（慕尼黑工业大学 / inovex GmbH / Cerebras Systems）· arXiv:2609.03201（v1 2026-09-02）

### 5.1 它要解决的问题

现有的权衡是：**紧凑文本记忆**提供高效的存储与检索，却往往让记忆间的关系保持**隐式**；**结构化、层次化与反思式架构**显式表示这些关系，但可能需要更宽泛的图构建、抽象或反思。

聚焦的问题：agent 如何在**不构建完备全局结构**的前提下，既保留文本证据中的**变化**、又能**联合检索相互依赖的记忆**？

### 5.2 方法

**记忆表示**：m_i = (x_i, τ_i, z_i, p_i, a_i, R_i) ——原子化的自然语言重述、以证据为依据的时间元数据、轻量元数据（实体/关键词/主题/位置）、**溯源**（支撑该记忆的对话轮次标识符）、**活跃状态**、**生命周期关系引用集合**（零或多个合并/取代/矛盾）。

完整的记忆存储构成一个**稀疏关系图** G = (M, E)：E 由**有向的取代边**与**对称的合并、矛盾链接**组成。取代关系是双向表示的——较新记忆指向它替换的条目，较旧记忆指向它的后继者。

> 与通用知识图谱的关键区别：**MemLACE 只存储解释已存储证据所需的关系**，不编码实体、分类、因果或语义关系。

**阶段一：记忆构造与整合**（沿用 SimpleMem 的轻量滑动窗口构造：20 轮窗口 + 2 轮重叠）

1. **记忆构造**：每条原子条目捕获**一条**单一显式事实/偏好/计划/纠正/决策/事件/状态，带源轮次溯源。名称、日期、数量、否定与说话者归属**按原样保留，不推断未陈述信息**（例如提及去柏林旅行，并不意味着在那里居住）。这种原子粒度很重要：**更新或矛盾通常只影响一条断言**，从而让整合能精确作用于被影响的记忆。重叠窗口带来的重复抽取会被合并（溯源也合并），来自不同轮次的重复则保持分离。
2. **候选与关系选择**：记忆按时间顺序整合（使后续证据不会被当作先于其所修改的状态）。对每条 m_new，先用语义相似度与同实体匹配检索相关记忆，再用它们的**一跳生命周期邻居**扩展成候选集；cross-encoder 重排，保留生命周期相连的记忆并优先排列排名最高的剩余候选。**重排序只决定哪些记忆被纳入比较，不决定关系。** 随后整合模块**恰好选择一个策略与一个目标**（把每步限制为单一「关系—目标」对，比同时把关系分配给多个候选更可靠）：
   - **merge**：关于同一事实的重复证据；
   - **update**：同一状态的有序变化；
   - **contradict**：同一范围下不相容的断言；
   - **no_action**：相互独立的记忆。
   在指派关系之前，模型会评估候选的主题、属性、断言与时间范围，**防止仅凭主题相似性就改变生命周期状态**。
3. **生命周期状态更新**：默认配置下修改**活跃性**与**连接性**，**不删除源证据**。当 m_n 更新 m_o 时：a_o ← 0、a_n ← 1，并建立双向的 supersedes / superseded_by 链接。**相矛盾的记忆保持活跃**（现有证据无法消解冲突），被对称相连；no_action 的记忆保持可独立检索。
   - 合并有两种策略：默认的**链接式合并（linked-merge）**保留原始文本与溯源并加双向合并引用（每条原始证据仍可单独检索）；**紧凑式合并（compact-merge）**用一条合成记忆替换被合并条目，以丢弃原始条目为代价换更小的存储。
4. **局部批式记忆演化**：一组新记忆加入后，用一个**有界的局部演化步骤**把这组记忆作为整体考量，建立那些「只有把整组放在一起看才显现」的额外 update / contradict / merge 链接（例如一条记忆与多个更早条目相关）。这一步**只作用于生命周期结构**——更新关系链接与相应活跃状态，**不重写记忆文本、不增添事实内容**。

**阶段二：证据检索与上下文构造**

1. **混合活跃记忆检索**：语义相似度、关键词匹配、结构化模板相关性、主题相关性四条通道产生互补排序，用 RRF 融合（k = 60）。**把初始搜索限制在活跃记忆上**，减少来自被取代状态的竞争；不活跃记忆仍被存储，需要历史证据时可通过锚点的生命周期关系恢复。
2. **生命周期扩展与证据单元**：E_q = A_q ∪ L(A_q)，其中 L(A_q) 沿**取代谱系**追溯恢复先前状态、沿**一跳矛盾关系**呈现直接冲突证据。扩展**保持局部性**，不遍历整张记忆图。所得记忆被分组为**证据单元**：可以是单条独立记忆，也可以是由取代/矛盾/合并链接构成的**连通分量**。取代边把每个分量按**从较早到较新**排列，使历史证据与活跃状态都可见；**未解决的矛盾断言被一起保留**，而非过早以一方取代另一方。**先分组再重排序**，使解释依赖于关系的记忆能作为一个连贯单元被评估，而不是作为独立片段相互竞争。
3. **链式感知重排序与上下文打包**：重排序器对**证据单元**（而非单条记忆）整体打分，选出得分最高的单元；在上下文预算约束下纳入，更新链保持「从旧到新」顺序；单元超出剩余预算时**部分纳入**，保留高优先级记忆、丢弃其余（最终上下文上限 64 条记忆）。
4. **基于证据的答案生成**：被打包的上下文以**生命周期顺序**呈现，向 LLM 区分当前、被取代与相冲突的记忆。模型因此可以为「当前状态」类问题优先用活跃证据、为「历史或时序」类问题恢复更早状态、在矛盾未解决时保留竞争性断言——**它接收到的是关系相连且时间结构被保留的证据，而不是从无序片段中推断关系**。

- **增益不是均匀铺开的**：集中在偏好遵循、弃答、多跳推理、事件排序与指令遵循——**恰恰是正确答案需要把若干相关记忆放在一起（而非孤立）考虑的那几类**。
- **知识更新只是边际改善**（在意料之中）：单次活跃记忆查找已足够，并不因加入并分组相关条目而受益。
- **仍有落后**：Hindsight 在时间推理上保有 8.7 个百分点优势、信息抽取 5.2 个百分点、摘要 4.9 个百分点。原因是设计取舍——MemLACE 刻意使用**原子记忆、稀疏局部关系与有界证据打包**，以高效消解演化中的状态，而非重建完整对话或维护全局反思式表示；这换来了显著更高的效率，但更不适于**穷举式摘要与显式时间区间计算**。

**最重要的一处机制区分**（作者的解释，我认为是本篇最该抄下来的一句）：

> **连接性决定「检索到哪些相关记忆」，而时间 grounding 决定「它们之间的差异被读成真正的冲突，还是有序的变化」。**

没有后者，**一次正常的更新会被误判为矛盾**。所以两个组件**不可互换**——它们针对的是不同的失败模式（一个是「没找到」，一个是「读错了」）。

另外几条读法：

- **生命周期扩展的损失高度集中**在「需要较早与当前状态一起」的类别（知识更新、多跳、时间推理）；而**矛盾消解在报告精度上不变**（两者均 40.3），说明相关的冲突记忆即便没有矛盾链接扩展，也常作为活跃锚点被独立检索到。
- 这里「时间感知」指的是整合与排序时使用以证据为依据的时间元数据 τ_i（事件时间、有效期）。
- **合并策略的对比最具诊断意义**：紧凑式合并改善了矛盾消解（40.3→44.1），却大幅降低多跳（55.3→43.0），净降 1.43 个百分点。所以**当一条调和后的陈述即足够时，把证据合并为一条是有帮助的，但它丢弃了多跳问题所依赖的独立溯源与表述**——默认的链接式合并取得更好的权衡。
- **组合降幅小于各单项降幅之和**，说明组件存在部分重叠，同时也仍贡献可分离的效果。

### 5.4 边界与短板

- **计数类完全没解决（Count = 0%）**，推荐类只有 8.33%（问题级裁判显示它其实答对了 32.2% 的单个问题，但达不到场景级 50% 阈值）。作者自己指出需要**专门的聚合算子**（例如调用计算器或代码执行工具）来补充它产出的证据单元。
- **时间推理落后 Hindsight 8.7 个百分点**（原子记忆 + 有界打包不适合穷举摘要与显式时间区间计算）。
- **其结论的射程被作者自己限定为「在所评测的设置下」**——长期记忆的主要挑战并非更丰富的全局结构，而是保留证据随时间的演化方式。
- **一句话边界**：**生命周期关系管「证据的有效性」，不管「数值的累积」——这两件事不该由同一套机制扛。**

### 5.5 怎么用这篇

- **最适合**：论证轻量生命周期关系足以拿到大部分收益、证明「归档而非删除」可以不吃掉全局知识图或反思阶段的代价；以及作为「状态追踪 / 树结构推理」类能力的工程参照。
- **不要拿来**：用于计数/聚合类任务；或把它的总体分当成「比 Hindsight 全面更强」——它在时间推理、信息抽取、摘要三类的表现反而落后。

## 6. 五篇合起来看

### 6.1 它们各自修正了什么

| 第 5 篇正文原来的说法 | 五篇之后 |
|---|---|
| 质量判断应该前移到写入侧 | 在事实会演化的场景里成立（MERIT 独立复现）；但**不再是单向共识**——「写时零构造」是一条有分量的对手路线（LazyMem） |
| 写时门控优于读时过滤 | 要拆成两件事：读时的**质量判断**确实多余（P-2 实测叠加后 100%→93.8%）；读时的**有效性强制**不可省（Revoked，0/1,620 vs 43.1%） |
| 归档而非删除 | 仍是共识，但只是**必要**条件。必须再配一道检索层有效性闸门，否则旧版本继续指挥 agent |
| 召回天花板由写入决定 | 还要补一句：**检索正确 ≠ 行动正确**（MERIT 忽略率 0.45）；记忆的**呈现方式**与存储同等重要 |
| 三段回路是手工设计的 | 这条回路**可以被学出来**（UMA），但前提是有可自动判分的任务分布 |
| 两篇论文的实验规模偏小 | 已有第三方基准把结论放到 23,440 条真实轨迹与 $42.57 成本上重测（MERIT） |

### 6.2 三支路线的成本结构

| 路线 | 代表 | 成本付在哪 | 换来什么 | 代价 |
|---|---|---|---|---|
| **写时判断** | P-2、MERIT 的 update-on-write | 一次，被该存储的所有未来查询摊薄 | 候选池信噪比高、冲突在写时就消解 | 假阴性不可逆；元数据被污染时退化很快 |
| **写时不判断** | LazyMem | 每次查询 | 不丢任何细节，尤其适合查询分布未知 | 查询时延与算力；上下文预算管理变复杂 |
| **交给策略** | UMA | 训练 + 奖励设计的钱 | 任务适应性 | 需要一个可自动判分的任务分布 |

### 6.3 两条不许商量的下限

不管选哪一支，下面两条已经被独立实测过，属于**不可商量**的边界：

1. **不要在写入时不可逆地销毁信息** —— P-2 的 100% vs 0%（归档 vs 覆写的时间性查询能力）、MemoryLACE 的状态追踪 100% vs 57%（取代链接保留每个历史状态）。
2. **必须在检索时强制执行有效性** —— Revoked 的 0/1,620 vs 43.1%；且失效点在**检索**（只改一个检索标志就让 39/81 个单元翻车，且从未反向），修的地方是检索路径而不是换后端。

外加一条被两篇独立印证的负向结论：**不要指望更聪明的模型来替这两件事**。Revoked 的九款模型不安全动作率 15.0%—60.0% 且与能力层级无相关；P-2 的元数据污染实验（5% 污染掉约 20 个百分点）说的是同一件事——这两件事都是**工程问题**，不是模型能力问题。
