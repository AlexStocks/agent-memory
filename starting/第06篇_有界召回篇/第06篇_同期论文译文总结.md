# 七篇跟踪论文总结

> 本文是《Agent Memory 技术综述》第 6 篇《有界召回篇》的配套材料，逐篇认真总结第 6 节讨论的七篇 2026 下半年跟踪论文：**UtilityUnderAttack、RetainOrConsolidate、EvictionDestroys、RippleMem、MemSIF、CompressionCost、SelectiveForgetting**。
>
> 与公众号正文的分工：正文用这七篇论证「有界召回」这一章在 2026 年 9 月已经分岔——预算约束下「留什么、删什么、怎么召回」没有单一答案；这里回到每篇论文本身，补齐正文因篇幅省略的方法细节、消融数据和边界条件。所有数字均取自对应译文的论文自报结果，并已在译文正文中逐条核对；不同论文的百分数**不同源、不可相加**。

## 0. 一句话定位与阅读顺序

| 论文 | 一句话定位 | 在分歧轴上的位置 | 证据强度 |
|---|---|---|---|
| **UtilityUnderAttack**（2608.21230） | 用最弱的投毒（1.2% 语料）证明：写时筛查与读时来源加权在有界记忆里都挡不住，效用直接归零 | 站在「有界占用下的攻防」反面，给整组论文一个对抗地板 | 最强：真实复现、配对 McNemar、逐条机制拆解 |
| **RetainOrConsolidate**（2607.17545） | 把「留存 vs 整合」从信仰之争变成预算依赖的连续谱，并学出一个预算依赖的算子路由器 OAS | 站在「留/整」轴，给出交叉点（32 token 整合 +36pp，256 token 留存反超） | 强：4 档预算 × 3 算子 × bootstrap，但单基准、单 LLM 主干 |
| **EvictionDestroys**（2609.08279） | 用恢复反事实审计量化「驱逐」的不可逆代价，80k 预算下销毁占比 0.67—0.73 | 站在「删」轴，证明删除不是免费的 | 强：因果估计量 + 三箱分解 + 两种检索机制对照 |
| **RippleMem**（2608.13334） | 用事件图 + 查询时联想补全，把「一次性检索」换成「证据找回」 | 站在「图结构 + 查询时扩展」一侧，证明图的价值在召回时而非预压缩 | 中强：双基准、完整消融，但抽取/规划都用 LLM 中介 |
| **MemSIF**（2608.01742） | 诊断 TSM（时间—结构错配）与 DUM（效用延迟显现）两类错配，给出结构化交互记忆 + 双轨事实记忆 | 站在「写入结构」一侧，但把结构当成错配的疗法而非装饰 | 中强：5 骨干 × 2 基准 + 独立诊断子集 |
| **CompressionCost**（2608.16370） | 证明压缩压低了存储却抬高了再获取成本，完成度不变而检索调用激增 2—3× | 站在「成本核算」一侧，重框了整章的评估口径 | 中强：受控 oracle 干预，但环境依赖（IRBench 显形、ALFWorld 不显形） |
| **SelectiveForgetting**（2608.28978） | 直接验证「图记忆是否优于扁平 RAG」，结论是否定的（token F1 0.417 vs 0.468），但遗忘模块成功 | 站在「图 vs 扁平」轴的反例，同时给出遗忘模块的可行性证据 | 中：单基准、单一小抽取模型，作者自限为刻画流水线 |

**建议阅读顺序**：先 **UtilityUnderAttack**（它给整组论文定下「有界占用下什么会静默崩塌」的基调），再 **RetainOrConsolidate + EvictionDestroys**（这两篇合起来把「留/删」这张轴钉死：留多少、删多少都随预算和不可逆性变号），然后 **RippleMem + MemSIF + SelectiveForgetting**（三篇一起回答「结构（图/交互/双轨）到底比扁平强在哪、强多少」，其中 SelectiveForgetting 是必要反例），最后 **CompressionCost**（它把所有「压缩/整合省了空间」的乐观叙事重新记账，是收尾的审计视角）。

## 1. UtilityUnderAttack：写时筛查与读时加权都挡不住投毒

**Memory Utility Under Attack: Poisoning Long-Term Agent Memory at 1.2% Corpus Rate**
作者未署名机构（译文按 arXiv 2608.21230 v1）· arXiv:2608.21230（v1 2026-08）· 无公开代码（译文未提供）

### 1.1 它要解决的问题

作者要回答一个被长期回避的问题：长期 agent 记忆在面对**投毒（poisoning）**时到底有多脆？不是对抗样本、不是隐藏指令、不是嵌入触发词，而是最朴素的攻击——往记忆语料里塞普通句子，断言错误事实，单次生成完成，不做任何迭代优化。

核心论点是：记忆系统有两个天然的防御面——**写入时内容筛查（staged content screening）**和**读取时来源加权排序（provenance-weighted ranking）**——但这两道都在一个关键假设上失效：攻击者控制的是「被写入的事实」，而不是「写入通道」或「检索通道」。当投毒记忆以普通用户/助手轮次写入、并与真实证据竞争检索时，两道防御都失去了判别信号。

### 1.2 方法（基准怎么造的）

- **攻击构造**：对 LongMemEval 的 120 题子样本，让生成模型产出一条看似合理的虚假答案 + 三个断言该答案的简短对话轮次，复用该题关键措辞，使其能与真实证据竞争检索。得到 **360 条被投毒记忆，约占语料 1.2%**，以 `trust_level=untrusted` 写入。
- **两道防御**：① 写时四阶段内容筛查流水线（同一篇论文里在间接提示注入上被测为强）；② 读时来源加权排序 `score(m) = w_s·sim(q,m) + w_t·τ(m) + …`，按信任等级降权不可信内容。
- **度量**：检索效用（retrieval utility），即 LongMemEval 准确率，对照干净语料（0.850）与投毒无防御（0.300）。
- **来源加权的理论边界**：只有攻击者的语义相似度优势低于 `w_t·Δ_prior / w_s` 时加权才有效。已发布权重下边界仅 **0.175**，而措辞模仿查询的投毒获得 **0.32** 的相似度优势，每次都越过；修正权重下边界升到 **0.544**，投毒不再能越过。
- **信任等级机制**：投毒记忆以 `trust_level=untrusted` 写入，来源加权排序的打分形如 `score(m) = w_s·sim(q,m) + w_t·τ(m) + w_e·e(m) + w_d·d(m) + w_p·p(m)`。防御寄希望于「不可信带 ≈ 恶意」，但 Corpus M 里不可信带约 94% 其实是良性内容，标签在二十次里有十九次都判断错了恶意性——来源加权救得回 Corpus M，却救不回 Corpus N。

### 1.3 关键数字

**① 1.2% 语料投毒，效用损失三分之二。**

| 条件 | 准确率 | 保留效用 | 证据召回 | 投毒召回 | p |
|---|---|---|---|---|---|
| 干净语料（无攻击） | 0.850 | 100% | 0.0% | 0% | – |
| 投毒，无防御 | 0.300 | 35% | 20.0% | 100% | – |
| 投毒 + 来源加权排序 | 0.560（恢复到 56%） | 56% | – | – | 配对 McNemar 对无防御臂显著 |

- 来源加权排序能把效用从 35% 拉回 56%，但**没有恢复到安全区间**，且只在「不可信内容承载信息」的 Corpus M 上好看。

**② 写时筛查对虚假事实投毒是盲的。**

- 同一道筛查流水线在间接注入上召回率 **0.832**、对塞满触发词的良性文本假阳性仅 **1.5%**（比对比的 DeBERTa 检测器低一个数量级）；
- 面对 360 条被投毒记忆，**拒绝了 0 条**。不是低比率，是零。

**③ 来源加权在极端语料上既救不回也误杀。**

| 语料 | 条件 | 准确率 | 不可信内容召回 | 证据召回 | p |
|---|---|---|---|---|---|
| M（18.7% 良性 untrusted，对照 1.18% 投毒） | 无防御 | 0.3167 | 99.17% | 6.56% | – |
| M | 修正权重 w_t=0.35 | 0.7000 | 99.17% | 0.00% | 1.17×10⁻¹⁰ |
| N（不可信带全是非证据轮次） | 修正权重 w_t=0.35 | 0.0417 | 0.00% | 0.00% | 6.31×10⁻³⁰ |

- Corpus M 给「来源加权能救回多少」设了**上界**（0.7000）；Corpus N 给「代价」设了**下界**（0.0417，证据召回 0%）。两者框定了一个区间，但没有在其中定位到一个可用工作点。

### 1.4 边界与短板

- 攻击是该类攻击里**最弱**的一种（平实虚假陈述、单次生成），更强、更针对的攻击只会更糟；这不是上界。
- 结论针对「攻击者控制被写入事实」这一威胁模型；不覆盖后门、嵌入触发词等。
- 作者刻意把筛查做成稻草人对照，证明 0/360 是**方法层面的边界**（虚假事实在结构上无异常信号），而非某个实现的缺陷。

### 1.5 怎么用这篇

- **最适合**：论证「有界占用下的记忆需要对抗面评估」、给任何声称「写时门控已够安全」的系统泼冷水、作为第 6 篇讨论「信任等级 / 来源加权」时的反面教材。
- **不要拿来**：当作「来源加权完全无用」的证据——它在 Corpus M 上显著有效（0.3167→0.7000）；它只是**没有可用工作点**，不是零效果。

## 2. RetainOrConsolidate：留还是整，取决于预算

**Retain or Consolidate? Budget-Dependent Operator Selection for Bounded Agent Memory**
作者未署名机构（译文按 arXiv 2607.17545 v1）· arXiv:2607.17545（v1 2026-07）· 无公开代码（译文未提供）

### 2.1 它要解决的问题

第 6 篇正文常把「整合（consolidation，把候选压缩成摘要/抽象）」当成有界召回下的默认好事。这篇要问一个更尖锐的问题：**整合的价值会不会随记忆预算变号？** 在预算紧到塞不下原始条目时，压缩或许救命；在预算宽松时，整合会不会反而丢信息？更进一步，最佳整合算子（Merge / Abstract / Rewrite）是否也依赖预算？

作者用可证伪的命题 + 受控评估回答：在 32 token 这种极紧预算下，Abstract 把留存从 4.0% 抬到 40.0%（+36pp）；在 256 token 这种宽松预算下，留存反超所有整合算子（74.5%）。

### 2.2 方法

- **受控配对**：每个动作接收相同的 gold 证据，仅在「预算化表示」上不同。留存（retention）打包完整原始条目；Abstract / Merge / Rewrite 产生目标预算内的表示。这把「何时—哪个」决策与证据发现隔离开。
- **预算扫描**：LongMemEval 上评估 32 / 64 / 128 / 256 token 四档。
- **OAS（Offline Abstraction-Safety）**：一个轻量打分器，仅从生成前特征学习「何时整合、用哪个算子」的联合决策，含一个安全的校准阈值（Calibrated-safe）。
- **统计**：问题级 10,000 次配对 bootstrap；重复测量（4 预算 × 3 标签实现）先在问题内平均再推断。
- **命题与可证伪性**：全文围绕「整合价值随预算变号」的命题展开，把它写成效用函数的方向性预测而非二元准确率恒等式，因此预算扫描可以与预测一致或相反而不必 redefine 保真度。OAS 的 Calibrated-safe 变体只在校准折上用冻结阈值，其余超参仅用外层训练问题，避免泄漏测试。

### 2.3 关键数字

**① 交叉点真实存在，且方向明确。**

| 预算 | 留存 | 抽象（Abstract） | 配对增益 [95% CI] | 帮助/伤害 |
|---|---|---|---|---|
| 32 token | 0.040 | 0.400 | +0.360 [+0.240, +0.480] | 28/1 |
| 64 token | 0.240 | 0.413 | +0.173 [+0.040, +0.307] | 20/7 |
| 128 token | 0.427 | 0.453 | +0.027 [−0.107, +0.160] | 13/11 |
| 256 token | 0.480 | 0.453 | −0.027 [−0.147, +0.093] | 9/11 |

- 32 token 下整合是**碾压级**增益（CI 不含零，p<0.001）；256 token 下整合增益的 CI 含零，留存回到第一。

**② 宽松预算下留存的绝对水平。**

- 表 8 中留存（retention）在 256 token 达到 **0.745**（74.5%），与 Direct utility 路由器（0.745）持平，反超所有整合算子。
- 路由器对比：Direct utility 在 32/64/128 token 均最高（0.545 / 0.618 / 0.640），256 token 与留存并列 0.745；Calibrated-safe 在最紧预算更保守（32 token 0.487、64 token 0.403），牺牲一些上限换安全。

**③ 伤害集中在哪。** 256 token 按问题类型看，整合的伤害集中在知识更新（Abstract −0.125、Merge −0.233）与时间类（Abstract −0.154）；多会话是少数整合仍正向的类别（+0.051 / +0.179）。

### 2.4 边界与短板

- 仅 LongMemEval 一个主基准、DeepSeek-V3.2 单主干（GLM-5.2 跨模型复核了留存 vs 抽象的方向）。
- 「何时—哪个」决策与证据发现被人为解耦，真实系统里二者耦合，路由器的泛化未测。
- OAS 的 Calibrated-safe 在宽松预算下明显保守（256 token 仅 0.742），说明安全阈值会吃掉上限。

### 2.5 怎么用这篇

- **最适合**：给「有界召回下是否该整合」一个**量化交叉点**而非口号；论证预算依赖的算子路由是比「永远整合」更诚实的工程答案。
- **不要拿来**：当作「紧预算下整合永远赢」——256 token 这个交叉点已经翻面；也不要把 74.5% 当成无条件的留存上限，它是该受控评估下的读数。

## 3. EvictionDestroys：删除不是免费的

**Eviction Destroys: A Restore-Counterfactual Audit of Memory Deletion in Agents**
Megagon Labs（译文按 arXiv 2609.08279 v1）· arXiv:2609.08279（v1 2026-09）· 代码 <https://github.com/megagonlabs/restore-counterfactual>

### 3.1 它要解决的问题

第 6 篇正文若主张「驱逐（eviction）/删除是低成本的收纳手段」，这篇是直接反证。它要度量一个被所有驱逐论文忽略的量：**由一次删除决策造成的、不可逆的端任务准确率损失**。难点在于区分三种错误——金标准被删了（不可逆）、金标准还在但检索器漏了（可恢复）、金标准在场但读者仍答错（残余）。只有第一类是删除真正造成的。

方法学贡献是**恢复反事实（restore counterfactual）**：对每个被驱逐的查询，把金标准重新注入，看答案是否由错变对；若变对且金标准确实曾被驱逐，则该损失不可恢复。

### 3.2 方法（基准怎么造的）

- **三箱分解**：在 oracle 可答分母上把策略错误拆为不可逆（irreversible）/ 可恢复（recoverable）/ 残余（residual）。
- **受控研究**：LongMemEval-S，覆盖 4 种驱逐策略（FIFO、random、redundancy-aware、LLM-importance）+ 1 个 info-density 控制 + no-evict 参照；**三档预算（80k / 30k / 8k）**；**两种检索机制**（top-kk 真实检索；forced-gold 构造参照，可恢复箱恒为空）。
- **因果识别**：遵循因果测量模板，把目标量定义为「遗忘决策造成的准确率损失」，在既定假设下从可观测变量识别并给出估计量。
- **三箱定义（精读）**：不可逆（irreversible）= 恢复金标准使答案由错变对，且该金标准曾被驱逐销毁，只能靠保留修复；可恢复（recoverable）= 金标准还在存储里、但排序器漏掉了它；残余（residual）= 金标准在场、读者仍答错。只有第一箱是删除真正造成的。
- **两种检索机制**：机制 (a) 是构造参照（forced-gold，可恢复箱恒为空，双箱占比恒为 1.00）；机制 (b) 是真实 top-kk 检索（表 1 主结果所在）。不报告检索机制，预算—准确率前沿不可比。
- **控制臂**：info-density 控制（按信息密度而非重要性驱逐）在 80k 下不可逆率 0.61，比所有语义策略都高，说明「按重要性」至少不比「按密度」差。

### 3.3 关键数字

**① 80k 预算下，销毁在「不可逆+可恢复」分母上占主导。**

| 策略（80k, top-kk） | 不可逆 irr/(irr+rec) | 不可逆率 irr/N |
|---|---|---|
| FIFO | 0.71 | 0.16 |
| random | 0.73 | 0.17 |
| redundancy-aware | 0.67 | 0.15 |
| LLM-importance | 0.60 | 0.10 |

- 没有任何策略在匹配准确率下分化（描述性）；但**销毁占比全部 >0.5**，即「删错了」比「留着没检索到」更常见。

**② 预算一紧，删除几乎全是毁灭。**

- 30k 下四类驱逐策略的双箱占比升至 **0.98—0.99**；8k 下**全部 1.00**（不可逆率 0.75—0.88）。
- 即：预算越紧，被删除的证据越不可能靠「留着但没检索到」来解释——它就是被销毁了。

**③ 检索机制是混淆变量。** 同一预算下，比较各研究报告必须控制读取时的检索设置；不报告检索机制的预算—准确率前沿不可直接比较（作者复现了「12 个驱逐格中 4 个被假设 H3 拒绝」）。

### 3.4 边界与短板

- 研究的是**外部智能体记忆存储**的驱逐；KV-cache 驱逐（可能优于完整缓存）不在范围内。
- 三箱解释依赖因果假设（§3.3），不是纯观测；残余箱还随读者强弱变化（更强读者把残余从 59 降到 28）。
- 仅 LongMemEval-S 单基准；策略对比是描述性的，未声称显著分化。

### 3.5 怎么用这篇

- **最适合**：给「有界召回下的删除」做一个**不可逆性账单**；论证任何驱逐策略都必须配恢复反事实审计，否则报的准确率虚高。
- **不要拿来**：当作「LLM-importance 更好」——在匹配准确率下它没有显著分化，0.60 只是描述性最低；它真正的卖点是「可恢复箱更大」而非「更准」。

## 4. RippleMem：图的价值在召回时，不在预压缩

**RippleMem: From Isolated Retrieval to Associative Recollection for Long-Term Agent Memory**
Jingbo Ji 等（中国传媒大学）· arXiv:2608.13334（v1 2026-08）· 译文未提供公开代码

### 4.1 它要解决的问题

现有长期记忆的「访问」三件套都有缺口：full-context 做嘈杂长上下文搜索；扁平检索只返回孤立、不完整的记录；图记忆构建昂贵且压缩了事件上下文。核心痛点被作者点明——**当一条最初检索到的记忆相关却不完整时，访问应如何继续找回作答所需的缺失支撑？**

RippleMem 的回答是**自适应联想回忆（adaptive associative recollection）**：把被回忆起的记忆既当答案上下文，又当找回额外支撑的线索，沿事件图局部扩展。

### 4.2 方法

- **写入**：线索丰富的情景记忆单元（canonicalized event restatement + 稠密向量 + 参与者/地点/时间线索）；以事件为中心的稀疏带权图，语义边（余弦）与结构边（线索 Jaccard）分别打分到有界候选池。
- **读取**：混合初始回忆（语义 + 词汇 + 结构化线索）→ 回忆控制器规划锚点与缺失支撑目标 → 锚点局部 h 跳扩展 → 来源感知排序取前 K（K 跨基准固定，即证据预算）。
- 关键设计：扩展沿两个图通道，偏好「离锚点更近、经更强带权路径相连」的候选；循环到证据充足或无新支撑为止。
- **记忆单元模式**：`m_i = (r_i, v_i, P_i, L_i, T_i)`，其中 r_i 是可独立理解的规范化事件重述、v_i 是稠密向量、P/L/T 是锚定的参与者/地点/时间线索（无法锚定则留空而非推断）。图构建是增量稀疏的：新节点从语义近邻 + 线索索引取有界候选池，语义边（余弦）与结构边（线索 Jaccard，含时间衰减 `exp(−Δ/τ)`）分别打分到最多 K_sem / K_str 条。

## 5. MemSIF：结构是治疗错配的药，不是装饰

**MemSIF: From Structured Interactions to Dual-Track Fact Memory for LLM Agents**
作者未署名机构（译文按 arXiv 2608.01742 v1）· arXiv:2608.01742（v1 2026-08）· 无公开代码（译文未提供）

### 5.1 它要解决的问题

MemSIF 的切入点是两个被长期忽视的**错配模式**，并用与方法无关的诊断证实它们真实存在：

- **TSM（Temporal–Structural Misalignment，时间—结构错配）**：按时间邻近切分记忆，会把属于同一事件但时间上分散的证据切碎，又把时间邻近但主题无关的内容粘在一起——时间邻近只是主题/事件结构的不完备代理。
- **DUM（Delayed Utility Manifestation，效用延迟显现）**：写入时的「显著度」常常低估未来效用——影响至少含一条关键证据话语的 **43.71%** 的查询。

它主张：结构（结构化交互记忆 + 双轨事实记忆）是这两类错配的**疗法**，而不是为了好看。

### 5.2 方法

- **结构化交互记忆（Structured Interaction Memory）**：主题片段（topic segment，保留局部连贯单元）+ 事件轨迹（event trajectory，把非连续但同属一个演化事件的单元重新连接），直接对抗 TSM。
- **双轨事实记忆（Dual-Track Fact Memory）**：CoreFact（写入时锚定可复用背景知识）+ ActiveFact（查询驱动、按需形成的事实），直接对抗 DUM——低显著度但高未来效用的细节先留在交互记忆里，等查询揭示效用时再抽取。
- **独立诊断子集**：NCE（非连续证据，衡量 TSM）与 LSHU（低显著度—高效用，衡量 DUM），与方法输出无关地构建。诊断从 1,540 个非对抗性 LoCoMo 问题构建，问题 ID 与图 1/图 4 一致；显著度评分隐藏查询、效用评分隐藏 gold 答案，盲评减少方法输出偏倚。DUM 分析显示：写入时显著度低估未来效用，影响至少含一条关键证据话语的 **43.71%** 的查询。

### 5.3 关键数字

**① 总体增益（相对最强基线）。**

- LoCoMo 与 LongMemEval-S 每个设定下 Total ACC 均最高，相对最强基线超出 **2.29%—8.79%**（LoCoMo）与 **2.87%—6.15%**（LongMemEval-S）。
- 诊断子集上更尖：NCE 子集 +**8.30%**、LSHU 子集 +**10.48%**（相对最强基线）。
- 6 个「数据集—骨干」设定下，Total ACC 提升的 95% 置信区间**都不含零**（含 DeepSeek-v4-pro 在 LoCoMo 的 +2.29% [0.45, 5.03] 与 LongMemEval-S 的 +2.87% [0.32, 6.44]）。

**② 消融：两轨都不可或缺。**

| 变体（LongMemEval-S / M-hop） | 降幅 |
|---|---|
| w/o CF（去掉 CoreFact 轨） | Total −12.77%；多跳相关列显著下降 |
| w/o AF（去掉 ActiveFact 轨） | M-hop −13.23% |

- 在 Qwen3-32B 下，MemSIF ACC 82.99%、每查询 2.41K token、7.04s；相比最强基线 GAM（77.21%）少 40.6% token、少 19.4% 时间，ACC +5.78%；相比相近 token 预算的 SimpleMem（2.29K），运行时间少 42.8%、ACC +8.38%。

### 5.4 边界与短板

- 诊断与主干都依赖 Qwen3 系列嵌入/模型为主，跨模型泛化未充分覆盖。
- DUM 的显著度/效用评分由 GPT-4o 给出，存在评分者偏倚风险（作者用盲评缓解）。
- 「双轨」的边界未完全划清：哪些细节进 CoreFact、哪些等 ActiveFact，依赖写入时显著度判断，而 DUM 恰恰说显著度不可靠——这是方法内的一处张力。

### 5.5 怎么用这篇

- **最适合**：论证「结构化写入」应针对具体错配（TSM/DUM）而非泛泛的「更有结构」；作为第 6 篇讨论「主题片段 + 事件轨迹 + 双轨事实」的参照。
- **不要拿来**：把 +8.79% / +10.48% 当全局均值——它们是相对最强基线、且集中在特定骨干/子集；也不要忽略它同样依赖 LLM 抽取。

## 6. CompressionCost：压缩省了空间，却悄悄抬高了再获取

**The Hidden Cost of Compression: Reacquisition Overhead in Bounded Agent Memory**
作者未署名机构（译文按 arXiv 2608.16370 v1）· arXiv:2608.16370（v1 2026-08）· 无公开代码（译文未提供）

### 6.1 它要解决的问题

这篇是整组论文里最该被第 6 篇引用的「审计视角」。它的论点是：任务完成度（task completion）是上下文压缩的**不完整**度量——压缩会显著抬高 agent 的**再获取成本（reacquisition cost）**，即对被丢弃状态的重新查询，而在统计上**不改变任务完成度**。换句话说，「仅看完成度」的评估是对完整结局的一次有损投影，可能漏掉一笔巨大的交互成本。

它把评估结局形式化为三元组 `Y = (Q 完成率, C_R 检索调用, C_E 执行调用)`，并在受控设定（IRBench 确定性项目规划环境 + oracle 注入操纵可恢复性）中证明。

### 6.2 方法

- **测量协议**：完整/保真上下文 vs 滑动（压缩）上下文；缺失的执行状态分化为检索（再获取）与执行（任务工作）两条去向；并行 oracle 分支注入被丢弃状态，使可恢复性成为被操纵变量。
- **干预**：Reclaim Evaluation 测试从受损记忆恢复可纠正状态；oracle 恢复直接操纵可恢复性，验证「再获取确实由丢弃状态驱动」。
- **环境对照**：IRBench（状态需重新查询）vs ALFWorld（同样缺失不迫使额外再获取）。
- **oracle 干预的因果证据**：在 GPT-5.5 High 上，Sliding+D*（注入被丢弃状态）把工具调用从 72.9 降到 **35.8**（净 −37.1），完成度维持 80%；Full+R* 健全性检查为 85% / 32.1。即「恢复被丢弃状态 → 再获取成本下降」直接证实再获取由丢弃状态驱动，而非别的因素。
- **工具预算是成本标记**：Full 在 10/10 次运行都停留在参考执行预算内；Sliding 5× 与 10× 在 0/10 次停留其中——再获取开销大到足以突破参考执行预算，而全上下文智能体从未接近它。

### 6.3 关键数字

**① 完成度不变，检索激增（GPT-5.5, High-IR）。**

- 完成度 80% → 85%（配对 p=1.0，95% CI [−6, +21] 含零）——一个只看完成度的评估者会微弱偏好压缩版；
- 检索调用 21.0 → **63.9**（配对 p=0.002，Cohen's d=2.07，95% CI [+31, +55] 不含零）——约 **3×**。
- 汇总表（六「模型—体制」对比）中，检索调用**全部上升、6 中有 5 显著**；完成度基本持平。

**② 更低显著度的内容干预放大差距。**

- TypeAware（真实丢弃 D）vs D-Irrelevant 在预算 B=265 处形成约 **57%** 的检索差距，而完成度不变（p<0.001 级别的检索差）。

**③ 完成度只在极端的 10× 压缩才显著崩。**

- 在 Low-IR 的 DeepSeek 上，完成度直到 10× 都是 100%，仅 10× 时 97%——完成度退化只在 10× 显著（p=0.016），而检索早在这之前就升了。

**④ 环境决定显形与否。**

| 环境 | 算子 | Δ检索 | 备注 |
|---|---|---|---|
| IRBench（本文） | Sliding | 大且为正（2—3×） | 模型/体制依赖 |
| ALFWorld | Sliding | ≈0（配对对称） | 小 / 触及天花板 |

- 即再获取特征是**环境依赖**的：IRBench 丢弃的任务图状态必须重查；ALFWorld 同样缺失不迫使再获取。

### 6.4 边界与短板

- 成本用「工具调用次数 / 轮次」代理，不是墙上时钟或美元；依赖提供商的部分被有意剥离，可能掩盖部分结构性信号。
- 检索/执行分解是工具层面（按 schema 归类），不是语义意图层面；逐轮时间动态未装备日志。
- 结论环境依赖强——在 ALFWorld 这类状态易重查的环境里，压缩的再获取代价根本不显形。

### 6.5 怎么用这篇

- **最适合**：重框第 6 篇的评估口径——任何「压缩/整合省了空间且完成度不降」的乐观叙事，都必须补报检索/再获取成本；作为预算会计视角的收尾。
- **不要拿来**：当作「压缩一定有害」——它在 ALFWorld 不显形，且完成度确实常能保住；它反对的是「只看完成度」，不是「压缩本身」。

## 7. SelectiveForgetting：图记忆没赢扁平，但遗忘模块赢了

**Selective Forgetting: A Graph-Based Memory Framework for Long-Term LLM Agents**
Theo Rusu、Sourena Khanzadeh、Manar Alalfi（多伦多城市大学）· arXiv:2608.28978（v1 2026-08-29）· 代码 <https://github.com/skhanzad/Selective-Amnesia>（CC BY 4.0）

### 7.1 它要解决的问题

这篇是「图记忆 vs 扁平 RAG」轴上的**必要反例**。它不假设图结构总是有益，而是直接验证：把对话记忆组织为知识图谱，是否真的改善 LLM 智能体的检索与推理？同时考察：系统能否在长时间交互中通过**选择性遗忘**控制无界增长而不牺牲质量？

核心发现是分裂的：**图表示在匹配预算下没有超过扁平向量基线**（token F1 0.417 vs 0.468），但**遗忘模块成功了**——一次剪枝移除 9.8% 节点而质量无显著变化。

### 7.2 方法（基准怎么造的）

- **三阶段流水线**：检索（top-5 实体节点 + 2 跳子图扩展，最多 15 节点）/ 更新（GPT-4o-mini 单调用抽取实体—关系）/ 保留（遗忘模块）。
- **图模式**：9 种节点标签（Person/Organization/…/Skill）；边带类型与属性。
- **重要性打分**：`Score = w_r·recency + w_f·frequency + w_c·centrality + w_t·turns_decay`，权重 (0.35, 0.25, 0.20, 0.20)，半衰期 90 天 / 1000 轮；
- **遗忘**：每 400 轮剪除 score<0.10 的节点及其边。
- **两个实验**：实验 1 每题新建图比检索质量；实验 2 把 500 题 haystack 合并为单一持久图（27,021 节点）比有无遗忘。
- **预算对称性**：检索根数固定为 5，正是为了匹配扁平向量基线检索的分块数，使两系统在**相等候选生成预算**下比较——任何性能差异归因于表示而非检索命中次数。去重余弦阈值 0.92（保守，宁可漏合并也不误合并）、检索余弦下限 0.75、2 跳扩展、节点上限 15。LongMemEval haystack 跨约 33 个月真实时间戳，近因半衰期 90 天即据此设定。

### 7.3 关键数字

**① 实验 1：图记忆没有赢扁平（匹配 5 个检索根预算）。**

| 类型 | Graph RAG（token F1 / Judge） | Baseline RAG（token F1 / Judge） |
|---|---|---|
| Overall | 0.417 / 0.454 | 0.468 / 0.536 |
| Single (asst.) | 0.575 / **0.607** | 0.774 / **0.911** |
| Temporal | 0.328 / **0.293** | 0.334 / **0.278** |
| Knowledge-update | 0.456 / 0.513 | 0.511 / 0.590 |

- 总体 token F1 配对 bootstrap：Δ=**−0.050**，95% CI [−0.085, −0.016]，**显著**（图输了）。
- 唯一图赢的指标是时间推理 Judge（0.293 vs 0.278）——图天然契合带时间属性的事件节点。
- 最大赤字在单会话（助手）问题：判定 0.607 vs 0.911——把一轮对话分解为实体会丢掉逐字回忆所需的表层形式。

**② 实验 2：遗忘模块成功。**

| 变体 | 节点 | 边 | 大小 | token F1 | 判定 |
|---|---|---|---|---|---|
| No-forgetting | 27,021 | 46,538 | 440.6 MB | 0.292 | 0.300 |
| Forgetting | 24,368 | 43,978 | 398.6 MB | 0.293 | 0.284 |
| Change | −9.8% | −5.5% | −9.5% | +0.001 | −0.016 |

- 移除 2,653 节点（9.8%）、2,560 边（5.5%）、9.5% 字节（440.6→398.6 MB）；
- token F1 几乎不变（+0.001），判定 −0.016，95% CI [−0.038, +0.006]——**四项指标无一显著变化**，即「无质量损失」一半成立。

### 7.4 边界与短板

- 作者自限：抽取器是单一小模型、单一基准（LongMemEval）上评估，结论刻画的是「这一基于抽取的流水线」，而非一般意义上的图结构记忆。
- 遗忘的压缩—质量权衡只测了单点（剪枝阈值 0.10、间隔 400 轮未经扫描），不是整条曲线。
- 重要性函数的四个分量贡献未隔离；未做「匹配压缩的随机剪枝」对照来隔离重要性函数的贡献。

### 7.5 怎么用这篇

- **最适合**：作为「图记忆优于扁平」这一常见预设的**反例**；同时证明选择性遗忘（近因/频率/中心性/轮龄加权）是控制持久记忆增长的可行、低损手段。
- **不要拿来**：把「图输了」推广到所有图记忆——RippleMem（第 4 篇）在同一类基准上靠查询时扩展赢了；差异在「静态图抽取」vs「查询时联想补全」。SelectiveForgetting 输的是前者。

## 8. 七篇合起来看

### 8.1 它们各自修正了什么

| 第 6 篇正文原来的说法（常见预设） | 七篇之后的修正 |
|---|---|
| 有界召回下，整合/压缩优于留存原始条目 | **预算依赖**：32 token 整合 +36pp 碾压留存，256 token 留存反超（RetainOrConsolidate）。整合不是默认好事，是预算的函数 |
| 驱逐/删除是低成本的收纳手段 | **删除不是免费**：80k 预算下销毁占「不可逆+可恢复」的 0.67—0.73，8k 下全部 1.00（EvictionDestroys） |
| 图记忆天然优于扁平检索 | **分裂结论**：静态图抽取在匹配预算下输了扁平（token F1 0.417 vs 0.468，SelectiveForgetting）；但查询时联想补全能赢（RippleMem）。差异在「何时用图」，不在「有没有图」 |
| 压缩是净收益（空间省了、完成度不降） | **隐性再获取成本**：完成度不变而检索调用激增 2—3×（CompressionCost），且只在 IRBench 类环境显形 |
| 写时门控 / 来源加权可挡住污染 | **两者都挡不住朴素投毒**：写时筛查拒 0/360，来源加权无可用工作点（UtilityUnderAttack） |
| 更丰富的结构（图/分层）总能提升召回 | **结构是治疗错配的药才有效**：结构化交互 + 双轨事实只针对 TSM/DUM，且依赖 LLM 抽取（MemSIF） |
| 检索到正确证据 ≈ 任务成功 | 两篇独立印证的负向：检索正确 ≠ 行动正确 / 完成度 ≠ 召回成本（MemSIF 的 DUM、CompressionCost 的再获取） |

### 8.2 三条路线的成本结构

| 路线 | 代表 | 成本付在哪 | 换来什么 | 代价 |
|---|---|---|---|---|
| **留原始 + 删冗余** | EvictionDestroys 的 no-evict 参照、RetainOrConsolidate 的 retention | 存储与检索预算 | 信息零损、时效信号完整 | 无界增长；删错了不可逆（0.67—0.73） |
| **整合/压缩省空间** | RetainOrConsolidate 的 Abstract、CompressionCost 的 Sliding | 一次压缩 + 再获取调用 | 紧预算下召回救回（整合 +36pp） | 再获取成本 2—3×；松预算下整合反输 |
| **结构记忆（图/交互/双轨）** | RippleMem、MemSIF、SelectiveForgetting | LLM 抽取/规划 + 图构建 | 跨会话/跨时间证据重组 | 静态图抽取可能输扁平；抽取开销大 |

### 8.3 三条不许商量的下限

不管走哪条路线，下面三条已被独立实测，属于**不可商量**的边界：

1. **不要在写入时不可逆地销毁信息** —— EvictionDestroys 的 80k 不可逆 0.67—0.73、8k 全部 1.00；RetainOrConsolidate 也给出留存作为可逆选项的回撤空间。
2. **删除策略必须配恢复反事实审计** —— 否则报的准确率把「删错了」（不可逆）和「留着没检索到」（可恢复）混为一谈，虚高且不可比（EvictionDestroys，检索机制不报告则前沿不可比）。
3. **评估口径必须同时报完成度与再获取成本** —— 只看完成度会漏掉压缩/整合悄悄抬高的检索调用（CompressionCost，2—3× 激增而完成度不变）。

外加一条被三篇印证的负向结论：**不要指望「更有结构」或「更聪明的模型」自动解决对抗与错配** —— UtilityUnderAttack 的投毒在最弱攻击下就归零、与防御强度无关；MemSIF 的 DUM 说显著度判断本身不可靠；这两件事都是**工程与评估**问题，不是模型能力问题。
