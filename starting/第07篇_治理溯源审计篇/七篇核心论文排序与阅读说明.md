# 第 7 篇候选论文排序与阅读说明

> 主题：治理、溯源与审计
> 评估日期：2026-09-20

## 选文原则

本轮不预设“本地论文为主、外部论文补强”。所有候选论文放入同一个池子，按四项标准排序：

1. 是否直接回答治理、溯源或审计问题；
2. 是否有可复核的实验、协议或形式化约束；
3. 是否能改变记忆系统的架构决策，而不只是换一个检索技巧；
4. 是否能落到长期运行、多用户或多 agent 的真实风险。

本目录的“逐篇详细译文”覆盖每篇论文的摘要、问题定义、方法/协议、实验设置、主要结果、局限和工程含义；附录、参考文献以及不改变论证的逐图逐表重复说明没有逐句搬运。数字和边界条件按原文回查。

## 为什么这样选

前六篇分别覆盖“系统会不会失控”“谁有权看”“状态怎样合并”“授权边界在哪里”“记忆是否经过现实核验”“出了错能否定位”。Always-On 提供一个能把这些问题放在同一生命周期里的框架。它不是因为是路线图原定论文才入选，而是因为六轴和 AOEP 能把实验论文的发现转成设计检查表。

两篇立场文很有价值，但它们主要改变叙事角度，缺少与前六篇同等强度的实验或协议验证，因此不拿来支撑数字化结论。

## 核心结论

本轮最重要的判断不是“写时优于读时”，而是：

> 长期记忆的正确性，必须同时包括受众边界、来源链、传播记录、现实核验、失效处理和可定位审计。最终答案答对，只能证明最后一跳暂时成功，不能证明状态链条没有悄悄变形。
