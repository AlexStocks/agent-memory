# MELD：分布式 agent memory 合并协议

> 原文：*MELD: A Protocol for Merging Knowledge Across Distributed Agentic Memories*
> arXiv：2608.16357v1，2026-08
> 作者：M. Lovén 等

## 摘要与问题

当多个 agent 各自拥有记忆存储时，把文本复制到一个共享向量库并不能解决一致性问题：重复事实会挤占召回预算，冲突事实可能被最后写入者覆盖，分区和消息丢失还会让不同节点长期处于不同状态。

MELD 把记忆共享定义为“带语义和血缘的状态变更传播”。每个 agent 保留自己的 brain store，发布 Concepts、Claims 和 Evidence 的图增量；接收方判断新 claim 与已有 claim 是同一个事实、相关事实、冲突事实还是不可接受内容，并通过受认证 Patch 更新状态。

## 1. 五类合并结果

每个 incoming claim 进入候选集合后，MELD 给出五种处理结果：

- **insert**：新事实进入存储；
- **merge**：与已有 claim 是同一个事实，合并其证据和来源；
- **relate**：内容相关，但不能证明是同一个事实，建立关系而不覆盖；
- **conflict**：与已有 claim 矛盾，保留冲突状态；
- **reject**：不满足质量或权限条件，拒绝写入。

协议不会把语义分类器的判断当作事实真相。merge 只说明“在当前证据和阈值下足够相同”，冲突仍然可见，并等待更高权威或后续裁决。

## 2. Patch、权威和 CRDT

所有状态变化都通过带认证的 Patch 发布。Patch 携带 claim、来源、操作、前置状态和签名，接收方可以验证它是否针对当前版本、是否来自有权节点。

每条 claim 有自己的 status，并使用 per-claim status CRDT。多个节点在没有中央协调器的情况下可以同时更新，网络分区恢复后按可交换、可合并的状态规则重新收敛。权威 gate 防止普通 peer 静默改写 canonical brain；冲突和撤销也被表示为显式状态，而不是删除旧文本。

## 3. 评测环境

论文在三层 computing continuum 上测试：边缘节点、芬兰 CSC 超算和跨层 Kafka 部署。HotpotQA distractor 是主要记忆基准，LongMemEval 用于独立复核，另有 104 对构造的 gold claim 用于诊断 merge classifier。

召回实验使用 3 个 sovereign brains，每个节点看到部分支持段落并带 0.5 的重叠；系统比较集中式 store、MELD merge 和没有语义合并的 naive union/last-writer-wins。

## 4. 主要结果

### 4.1 分布式合并不损失召回

HotpotQA 上，MELD 的 recall@5 为 0.630，集中式存储为 0.619，差值 +0.011，满足预先设定的等价边界。相对 naive union，召回提高 0.035，同时 live store 小约 11%。

原因是 paraphrase duplicate 被合并后，不会挤占固定 top-k 的位置。集中式与 MELD 的 live footprint 几乎相同（38.6 对 38.2 个可召回单元），但 MELD 能减少重复造成的浪费。

实验还产生 117 个 contradiction flag，论文强调这些候选没有被静默合并；它们只是被送入后续 adjudication。

### 4.2 分区恢复

真实多主机 testbed 上做了 30 次有种子的 partition-heal 试验。MELD 的 CRDT 在 30/30 次恢复到一致状态；对照的 last-writer-wins 只有 11/30。跨层 Kafka 试验的平均恢复延迟约 2712 ms，主要受 WAN 重连和丢失 offset 影响。

### 4.3 路由与效率

语义路由只把 delta 发给可能相关的 brain，代表性 workload 为 195 个 delta/cell，而广播为 585 个，约减少 3 倍消息。同步延迟随 fan-out 和 RTT 增加，单一全局 sink 在约 54 merges/s 附近出现饱和拐点。

### 4.4 分类质量与边界

merge classifier 的 AUC 为 0.968，false-merge rate 为 0.013。论文把 false merge 视为最危险的错误，因为它会把两个不同事实压成一个状态；threshold 不能跨 encoder 直接迁移，分类器能力和阈值校准仍是部署前提。

## 5. 论文没有声称什么

MELD 的贡献是协议和机制，不是最强的推理模型，也不证明语义分类器能够判断事实真伪。实验中的数据和冲突结构有较强的构造性，拜占庭节点和恶意 Patch 不在当前范围内。分布式合并保持召回也不代表每次答案都正确，答案 token-F1 仍会受下游模型能力影响。

## 6. 工程启示

共享记忆不应设计为“把文本复制过去”。更稳妥的最小单位是：带来源的 claim、可认证的 Patch、显式的冲突/撤销状态、可重放的合并日志和能在分区后收敛的状态规则。对同一事实的合并、对相关事实的关联、对矛盾事实的保留，必须在数据模型中分开表示。
