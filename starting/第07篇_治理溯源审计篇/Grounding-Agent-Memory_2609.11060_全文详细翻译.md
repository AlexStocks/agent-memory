# Grounding Agent Memory：面向企业 Agent 的环境探测式记忆整理

> 原文：*Grounding Agent Memory: Environment-Probing Curation for Enterprise Agents*
> arXiv：2609.11060v1，2026-09-10

## 摘要

企业 agent 的记忆往往来自过去的任务轨迹。常见做法是在任务结束后总结“发生了什么”，但这样的总结未必告诉未来 agent 当前环境里应该怎么做：数据库 schema 可能变了，文件映射可能变了，流程和规则也可能已经更新。

本文提出环境探测式 curation。一个异步 curator 使用最小权限的只读环境工具，检查限定范围内的 schema、关系、文件地图和操作流程，再刷新候选记忆。它不需要重训模型，也不修改任务 agent、retriever、memory representation 或生产写权限。

## 1. 角色和边界

系统区分 task agent 和 curator。task agent 负责完成用户任务；curator 在任务之间异步运行，负责判断已有记忆是否仍然适用、缺少哪些环境事实、哪些记忆应该被更新或拒绝。

curator 的工具是只读的、最小权限的，并且探测范围受限。它可以查看 schema、字段关系、文件位置、配置和流程，但不能修改生产系统。这样做有两个目的：避免把“验证记忆”变成新的副作用来源，也避免让 curator 直接替代任务 agent。

## 2. 为什么轨迹总结不够

一段轨迹可能记录“我们查询了 orders 表”，却没有说明当前数据库里 orders 表是否仍存在、join key 是否发生变化，也不能保证未来任务处于同一个环境。只从轨迹总结，容易保留叙述而遗漏可执行约束。

环境探测式 curation 会把记忆写成更接近行动的记录：源表、连接键、过滤条件、文件路径、流程入口、已验证时间和探测证据。记忆不仅有来源，还附带“在什么环境观察到、用什么只读检查确认”的信息。

## 3. 实验设置

论文在 CLBench 上评估 40 个带 drift 的任务，第 20 个任务之后发生环境迁移；使用 GPT-5.4，5 次成对运行。另在 APEX 的 6 个世界、90 个任务上评估成本和奖励，比较 trajectory-only curation 与 environment-probing curation。

## 4. 结果

CLBench 中，环境探测记忆使：

| 指标 | 轨迹式记忆 | 探测式记忆 |
|---|---:|---:|
| 严格通过率 | 39% | 73% |
| pass-discounted reward | 8.60 | 22.60 |
| 平均查询次数 | 8.8 | 4.7 |
| task-agent 成本 | 3.38 美元 | 1.68 美元 |

APEX 的 6 个 world 中，18 个 memory-vs-baseline reward 对比全部为正。探测式记忆不仅提高成功率，还减少了 task agent 重复探查的次数，因为记忆中已经包含可验证的环境结构。

定性分析显示，轨迹式记忆更容易留下“曾经做过什么”的叙事；探测式记忆会留下下一次 agent 真正需要执行的 schema、关系、文件图和流程约束。

## 5. 局限

curator 的收益依赖只读工具质量、探测范围和环境变化类型；如果环境无法被工具观察，或者权限过窄，记忆仍可能过期。论文主要验证企业数据库、代码和流程场景，不等于所有开放世界的记忆都能用同样的探针核验。curator 本身也需要成本、调度和审计。

## 6. 工程启示

provenance 不能只回答“这条记忆来自哪一轮对话”。更完整的来源链还要包含：在哪个环境观察到、用什么查询或检查验证、验证时间、验证结果和适用范围。记忆的可信度不是一次写入时永久确定的，而应随着环境变化重新评估。
