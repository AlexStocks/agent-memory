# AIM：面向多 agent、多用户 LLM 系统的隐私感知互操作记忆框架

> 原文：*AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems*
> arXiv：2609.12320v1，2026-09-11
> 作者：Zachary Johnson 等，Microsoft

## 摘要

传统 LLM 以单个用户会话为边界，只知道当前对话里出现的内容，无法积累长期偏好。已有 agent memory 方案又往往只服务单个用户，错过了跨用户共享公共知识带来的协作收益。

AIM（Agentic Interoperable Memory）提出一个统一的隐私感知记忆框架，同时管理私有记忆和共享记忆。系统动态把信息分成 private 和 public，并在索引层执行访问控制：私有记忆只能由拥有者检索，公共记忆可以被所有用户使用。作者还提出 MUMBench，用多用户、多领域、包含隐私和共享信息的交互评估框架。

## 1. 框架目标

AIM 处理的是两个相反的需求：

- 用户偏好、私人事实和私下对话不能泄露给其他用户；
- 经过允许的公共知识需要跨 agent、跨用户共享，以改善协作和回答一致性。

它把记忆操作统一成 create、read、update、delete 和 no-op，并在写入、分类、去重和检索环节维护隐私标签。索引层过滤是安全边界，不能只依赖 prompt 告诉模型“不要使用私人内容”。

## 2. 处理流程

论文的端到端流程大致如下：

1. 接收用户输入和当前对话上下文；
2. 检测本轮应执行的 memory operation；
3. 抽取候选记忆；
4. 分类为私有或公共，并提取标签；
5. 与已有记忆去重或产生更新；
6. 写入带用户和可见性字段的存储；
7. 查询时做向量、关键词和重排融合；
8. 只返回当前用户有权访问的记忆。

系统不是把所有公共数据复制到每个用户空间，而是保留一个可互操作的共享存储，用索引层的 scope/visibility 条件限制读取。

## 3. MUMBench 与评测口径

MUMBench 覆盖编码、客服、教育和旅行四个领域，包含多用户交互、私有信息、可共享信息、冲突更新、删除和对抗性查询。作者特别指出，一个用户消息可能同时触发多个操作，早期漏掉 create 会导致后续 update、read 和 delete 级联失败，因此不能只用单步字符串匹配评分。

论文使用三种操作准确率：

- **严格准确率**：预测操作经过规范化后与 gold multiset 完全一致；
- **state-aware 准确率**：按系统实际已经创建、更新和删除的状态修正 gold，避免把前一步遗漏造成的级联错误全部算到当前步；
- **judge-LLM 准确率**：由评审模型结合上下文判断操作是否合理。

另有四类质量指标：内容质量、可见性匹配、标签重合和检索相关性。

## 4. 实验结果

实验使用 GPT-5.4、GPT-5.4-mini、DeepSeek-V3.2、Mistral-Large-3 和 Llama-3.3-70B-Instruct 五个模型。每个领域清空记忆库，顺序回放全部交互，所有 pipeline 阶段使用同一主模型；embedding 使用 text-embedding-3-large，每个模型每条交互跑 3 次。

表现最好的 GPT-5.4-mini 四领域平均结果为：

| 指标 | 平均值 |
|---|---:|
| 严格操作准确率 | 58.8% |
| state-aware 操作准确率 | 70.5% |
| 可见性分类准确率 | 95.0% |
| 内容质量 | 91.6% |

可见性分类是 AIM 最稳定的能力。不同模型的隐私分类平均都接近 90% 或更高，旅行领域有 3 个模型达到 100%。这说明规则与 LLM 分类结合后，能较稳定地区分私有和公共信息。

操作准确率则明显低一些。编码领域的 state-aware 分数最高可达 DeepSeek-V3.2 的 79.8%，旅行领域 GPT-5.4-mini 为 62.7%，论文把差异归因于旅行对话更长、更新链更复杂以及不同作者对操作边界的理解差异。

## 5. 局限

标签重合率在最佳模型上只有 35.5%，说明 tag extraction 仍需改进；检索相关性最高约 45.0%，隐私分类正确不代表最终检索就相关。LOCOMO 评测只做一次运行，而 Mem0 报告 10 次平均，统计可比性有限。更重要的是，LOCOMO 是单用户基准，不能覆盖 AIM 最有区别的多用户隔离和跨 agent 同步。

安全边界也有明显假设：公共记忆默认对所有用户可见，任何用户都可能写入或编辑一个事实错误的公共记忆。未来需要公共记忆的来源等级、审核和撤销机制。

## 6. 工程启示

AIM 说明“隐私”不是 prompt 里的一个标签，而应成为索引和检索的硬条件；同时，操作准确率应按实际 store state 评估，不能忽略级联错误。它没有解决事实真实性和公共记忆污染，但把“谁能读”从产品约定推进成了存储层约束。
