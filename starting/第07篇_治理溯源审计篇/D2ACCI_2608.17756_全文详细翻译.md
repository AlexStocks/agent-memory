# D²ACCI：保留证据的 Agent Memory 双循环诊断协议

> 原文：*D²ACCI: A Dual-Loop Diagnostic Protocol for Evidence-Preserving Agent Memory*
> arXiv：2608.17756v2，2026-08-19

## 摘要

端到端记忆评测通常只给出一个最终分数。分数下降时，团队不知道问题发生在写入、检索、过滤、上下文组装还是模型利用证据的阶段。D²ACCI 提出一个双循环诊断协议：内层 memory loop 运行系统，外层 diagnostic loop 保存成对证据、保护切片和可回放轨迹，用来定位失败并判断修复是否真的有效。

论文把 source ID、memory ID、top-k 分数、过滤项、预算和 judge 都作为诊断产物的一部分，而不是只保留最后的答案和总分。

## 1. 双循环结构

内层循环包含记忆系统已有的阶段：写入、组织、检索、过滤、预算控制、上下文组装和回答。每一阶段都产生带类型的 trace。

外层循环负责：

- 设计成对的 full/ablated 条件；
- 固定 benchmark slice，避免每次评测换题；
- 重放归档证据；
- 对修改做 gate/reject/accept 决策；
- 区分 ingestion miss、retrieval miss、reader failure 和 budget loss。

它的核心思想是：要证明一个改动有用，必须知道它修复了哪类失败，同时没有在另一个切片上引入回归。

## 2. 诊断指标与实验

论文在 LoCoMo、LongMemEval 和 PersonaMem-V2 三个公开基准上，将协议实例化到 MemStack。主结果是：

| 基准 | 端到端结果 |
|---|---:|
| LoCoMo | 93.59% |
| LongMemEval | 90.93% |
| PersonaMem-V2 | 57.20% |

更重要的是诊断覆盖：诊断产物达到 98%—100% 的 DCR@3；只记录结果、不保存轨迹的对照为 0%。这说明最终分数可以相同，但可定位性完全不同。

## 3. 成对消融和案例

一个典型案例是 LoCoMo conv1:q038。结果日志只能显示日期答案错误，无法判断责任在写入还是检索。D²ACCI 通过成对补入证据，发现记忆实际存在但被排序器漏掉，因此应该修复 retrieval，而不是重新训练 ingestion。

协议还归档常见反模式：过度合并、只优化聚合分数、没有 protected slice、修改后不重放旧案例。每次改动都要在固定切片上运行自动 gate；若整体分数上涨但关键切片退化，协议应拒绝该修改。

## 4. 证据包应包含什么

一个可审计的 memory run 至少需要：

1. 原始输入和 source ID；
2. 产生或更新的 memory ID；
3. 候选池和排名分数；
4. 被过滤的条目及原因；
5. 预算、top-k、上下文快照；
6. 触发的 action 或最终回答；
7. judge、版本、随机种子和运行配置。

如果只有最终答案，无法区分“没有写入”“写入但未召回”“召回但被过滤”“证据已给出但模型没用”。

## 5. 局限

D²ACCI 是诊断协议，不是新的记忆算法；它不能自动保证记忆真实，也不能替代人工判断或独立裁判。DCR 依赖 trace 的完整性和 benchmark adapter 的正确实现。额外记录、回放和成对运行也会产生存储与计算成本。

## 6. 工程启示

评测系统需要保存“为什么得出这个结果”的证据，而不是只保存结果。记忆系统每一次改动都应该能回答：它修复的是写入、检索还是利用？修复是否改变了受保护切片？如果无法回答，准确率提升还不能转化为可靠的工程决策。
