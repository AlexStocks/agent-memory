## 摘要（Abstract）

基于大语言模型（LLM）的智能体（agent）近来引起了研究与工业界的广泛关注。与原始的 LLM 相比，基于 LLM 的智能体以**自我进化（self-evolving）**能力为特征，而这一能力正是解决现实世界中需要长期、复杂"智能体—环境交互"问题的根基。支撑智能体与环境交互的关键组件，就是智能体的**记忆（memory）**。尽管先前的研究已经提出了许多颇有前景的记忆机制，但它们散落在不同的论文中，缺少一项系统性的综述来从整体视角总结与比较这些工作，也未能抽象出通用且有效的设计模式以启发未来研究。为弥合这一空白，本文提出了一项关于基于 LLM 的智能体记忆机制的全面综述。具体地，我们首先讨论基于 LLM 的智能体中记忆"是什么"以及"为何需要"。随后，我们系统性地回顾了先前关于如何设计与评估记忆模块的研究。此外，我们还呈现了许多记忆模块扮演重要角色的智能体应用。最后，我们分析了现有工作的局限，并指出了重要的未来方向。为跟上该领域的最新进展，我们在 https://github.com/nuster1128/LLM_Agent_Memory_Survey 创建了一个仓库。

## 1. 引言（Introduction）

> "没有记忆，就没有文化。没有记忆，就不会有文明、社会与未来。"
>
> —— 埃利·维瑟尔（Elie Wiesel），1928-2016

近年来，大语言模型（LLM）在从人工智能、软件工程到教育、社会科学的大量领域中都取得了显著成功 [1, 2, 3]。原始的 LLM 通常在不与环境交互的情况下完成各种任务。然而，要达到通用人工智能（AGI）的最终目标，智能机器应当能够通过自主探索现实世界并从中学习来实现自我提升。例如，如果一个旅行规划智能体想要预订机票，它应当向票务网站发送订单请求，并在采取下一步行动之前观察响应。一个个人助理智能体则应当根据用户的反馈调整自身行为，提供个性化回复以提升用户满意度。为了进一步把 LLM 的边界推向 AGI，近年来涌现了大量关于基于 LLM 的智能体的研究 [3, 4]，其中的关键是在现实环境里为 LLM 配备额外模块以增强其自我进化能力。

在所有新增模块中，**记忆**是区分智能体与原始 LLM 的关键组件，它使一个智能体真正成为"智能体"（见图 1）。记忆在决定智能体如何积累知识、处理历史经验、检索有信息量的知识以支撑其行为等方面扮演着极其重要的角色。围绕记忆模块，人们投入了大量精力来设计其信息源、存储形式与操作机制。例如，Shinn 等人 [5] 融合"试验内（in-trial）"与"跨试验（cross-trial）"两类信息来构建记忆模块，以增强智能体的推理能力。Zhong 等人 [6] 以自然语言的形式存储记忆信息，这种形式对用户可解释、友好。Modarressi 等人 [7] 设计了记忆的读写操作，以便智能体与环境交互并求解任务。

尽管先前研究已设计出许多有前景的记忆模块，但仍然缺少一项系统性的研究来从整体视角审视记忆模块。为弥合这一空白，本文全面回顾了先前研究，为设计与评估记忆模块给出清晰的分类型法（taxonomy）与关键原则。具体而言，我们讨论三个关键问题：(1) 基于 LLM 的智能体的记忆是什么？(2) 基于 LLM 的智能体为何需要记忆？(3) 如何在基于 LLM 的智能体中实现与评估记忆？首先，我们详细阐述基于 LLM 的智能体中记忆的概念，给出狭义与广义两种定义。然后，我们分析基于 LLM 的智能体中记忆的必要性，从认知心理学、自我进化与智能体应用三个视角说明其重要性。基于"是什么"与"为什么"的问题，我们进一步呈现设计并评估记忆模块的常用策略。就记忆设计而言，我们从三个维度讨论已有工作，即**记忆来源（memory sources）、记忆形式（memory forms）与记忆操作（memory operations）**。就记忆评估而言，我们介绍两种被广泛采用的方法：直接评估（direct evaluation）与通过特定智能体任务进行的间接评估（indirect evaluation）。接下来，我们讨论角色扮演、社会模拟、个人助理、开放世界游戏、代码生成、推荐与专家系统等智能体应用，以展示记忆模块在实际场景中的重要性。最后，我们分析现有工作的局限，并强调重要的未来方向。

本文的主要贡献可总结如下：(1) 我们正式定义了记忆模块，并全面分析了基于 LLM 的智能体对记忆的需求。(2) 我们系统性地总结了关于在基于 LLM 的智能体中设计并评估记忆模块的现有研究，给出了清晰的分类型法与直观洞见。(3) 我们呈现了典型智能体应用，以展示记忆模块在不同场景中的重要性。(4) 我们分析了现有记忆模块的关键局限，并给出潜在的解决思路以启发未来研究。据我们所知，这是**第一篇**关于基于 LLM 的智能体记忆机制的综述。

本文其余部分组织如下：首先，我们在第 2 节针对 LLM 与基于 LLM 的智能体领域提供系统性的"元综述"（meta-survey），对各类综述进行分类并总结其关键贡献。然后，我们分别在第 3 至 6 节讨论基于 LLM 的智能体中记忆"是什么""为何需要"以及"如何实现与评估"的问题。接着，我们在第 7 节展示记忆增强型智能体的应用。对现有工作局限的讨论与未来方向安排在最后的第 8、9 节。

## 2. 相关综述（Related Surveys）

> 图 2：关于 LLM 与基于 LLM 的智能体的相关综述的组织结构。

在过去两年里，LLM 引起了学术界与工业界的广泛关注。为系统性地总结该领域的研究，研究者撰写了大量综述论文。在本节中，我们简要回顾这些综述（总览见图 2），突出它们的主要关注点与贡献，以便更好地为我们的研究定位。

### 2.1 关于大语言模型的综述

在 LLM 领域，Zhao 等人 [70] 提出了第一篇全面综述，总结了 LLM 的背景、演进路径、模型架构、训练方法论与评估策略。Hadi 等人 [71] 与 Min 等人 [72] 也从整体视角开展了 LLM 综述，但它们对 LLM 给出了不同的分类型法与理解。在这些综述之后，人们深入 LLM 的特定方面，回顾相应的里程碑式研究与关键技术。这些方面可分为四类：LLM 的基础问题、评估、应用与挑战。

**基础问题。** 该类综述旨在总结可用于攻克 LLM 基础问题的技术。具体而言，Zhang 等人 [8] 对监督微调方法提供了全面综述，监督微调是更好训练 LLM 的关键技术。Shen 等人 [9]、Wang 等人 [10] 与 Liu 等人 [11] 呈现了关于 LLM 对齐（alignment）的综述，对齐是使 LLM 输出与人类价值观一致的关键要求。Gao 等人 [12] 提出了关于 LLM 检索增强生成（RAG）能力的综述，RAG 是为 LLM 提供事实性、最新知识并消除幻觉（hallucination）的关键。Qin 等人 [18] 总结了使 LLM 能够利用外部工具的最先进方法，这是 LLM 在需要专门知识的领域扩展能力的基础。Wang 等人 [13]、Yao 等人 [14]、Wang 等人 [15]、Feng 等人 [16] 与 Zhang 等人 [17] 呈现了 LLM 知识编辑（knowledge editing）方向的综述，知识编辑对于定制 LLM 以满足特定需求很重要。Huang 等人 [19]、Wang 等人 [20] 与 Pawar 等人 [21] 关注 LLM 的长上下文能力，这对 LLM 每次处理更多信息、扩展应用场景至关重要。Wu 等人 [22]、Song 等人 [23]、Caffagni 等人 [24] 与 Yin 等人 [25] 总结了多模态 LLM，把 LLM 的能力从文本扩展到视觉等模态。上述综述主要关注 LLM 的有效性。LLM 的另一个重要方面是训练与推理效率。为总结这方面的研究，Zhu 等人 [30]、Xu 与 McAuley [31]、Wang 等人 [32] 与 Park 等人 [33] 系统性地回顾了模型压缩技术。Ding 等人 [81] 与 Xu 等人 [29] 分析总结了参数高效微调的研究。Bai 等人 [26]、Wan 等人 [27]、Miao 等人 [28] 与 Ding 等人 [81] 则更多关注一般意义上资源利用的效率。

**评估。** 该类综述聚焦如何评估 LLM 的能力。具体地，Chang 等人 [34] 从整体视角全面总结了评估方法，涵盖不同的评估任务、方法与基准，它们是衡量 LLM 性能的关键组成部分。Guo 等人 [35] 更关心评估目标，描述了如何评估 LLM 的知识、对齐与安全控制能力，在性能指标之外补充了评估维度。

**应用。** 该类综述旨在总结借助 LLM 改进不同应用的模型。更具体地，Zhu 等人 [37] 聚焦信息检索（IR）领域，总结了基于 LLM 的查询处理研究。Xu 等人 [38] 更关注信息抽取（IE），为该领域基于 LLM 的模型提供了全面的分类型法。Li 等人 [50]、Lin 等人 [51] 与 Wang 等人 [52] 讨论了 LLM 在推荐系统领域的应用，其中他们利用智能体生成数据并提供推荐。Fan 等人 [39]、Wang 等人 [40] 与 Zheng 等人 [41] 聚焦 LLM 如何在软件设计、开发与测试方面惠及软件工程（SE）。Zeng 等人 [42] 总结了机器人学领域基于 LLM 的方法。Cui 等人 [43] 与 Yang 等人 [44] 关注自动驾驶应用，从不同视角总结了该领域基于 LLM 的模型。除上述人工智能领域之外，LLM 也被用于自然科学与社会科学。He 等人 [45]、Zhou 等人 [46] 与 Wang 等人 [47] 总结了 LLM 在医学中的应用。Li 等人 [48] 关注 LLM 在金融中的应用。He 等人 [49] 回顾了利用 LLM 改进心理学发展的模型。

**挑战。** 该类综述聚焦 LLM 的可信度问题，如幻觉、偏见、不公平、可解释性、安全与隐私。LLM 的幻觉指 LLM 可能生成错误认识或编造内容的问题，影响其在下游应用中的可靠性。Zhang 等人 [53]、Huang 等人 [54]、Rawte 等人 [55]、Ye 等人 [56]、Ji 等人 [57]、Tonmoy 等人 [58] 与 Jiang 等人 [59] 总结了缓解 LLM 幻觉问题的主流模型。偏见与不公平问题指 LLM 可能不平等地对待不同的人或对象，从而导致社会刻板印象与歧视的传播。Gallegos 等人 [60]、Kotek 等人 [61] 与 Li 等人 [62] 全面讨论了这些挑战，并总结了缓解它们的现有方法。可解释性问题指 LLM 的内部工作机制仍然不清楚。Zhao 等人 [63] 系统性地讨论了该问题，并总结了以往在提升 LLM 可解释性上的努力。安全与隐私同样是具有挑战性的问题，已在 Yao 等人 [64]、Shayegani 等人 [65]、Neel 与 Chang [66]、Smith 等人 [67]、Dong 等人 [68] 与 Das 等人 [69] 中得到全面综述。

### 2.2 关于基于 LLM 的智能体的综述

基于 LLM 的能力，人们开展了大量构建基于 LLM 的智能体的研究，这类智能体可以自主感知环境、采取行动、积累知识并实现自我进化。在该领域，Wang 等人 [3] 提出了第一篇综述论文，从智能体构建、智能体应用与智能体评估的视角系统性地总结了基于 LLM 的智能体。Xi 等人 [4]、Zhao 等人 [77]、Cheng 等人 [78] 与 Ge 等人 [80] 也从整体视角总结了基于 LLM 的智能体研究，但它们的关注点与分类型法不同，为该领域提供了更多样化的理解。除这些整体性综述外，还出现了若干篇回顾基于 LLM 的智能体特定方面的论文。就基础问题而言，Durante 等人 [79] 总结了多模态智能体的研究。Huang 等人 [74] 聚焦基于 LLM 的智能体的规划能力。Guo 等人 [75] 更关注多智能体交互的场景。就应用而言，Li 等人 [76] 对被用作个人助理的基于 LLM 的智能体进行了总结。

**本工作的定位。** 我们的综述总结了关于基于 LLM 的智能体的一个基础问题，即智能体的记忆机制。据我们所知，这是该方向的第一篇综述。我们希望它不仅能为未来更先进的记忆架构带来启发，也为新手提供全面的入门材料。

## 3. 基于 LLM 的智能体的记忆是什么（What is the Memory of LLM-based Agent）

与环境交互并向环境学习是基于 LLM 的智能体的基本要求。在"智能体—环境"交互过程中，存在三个关键阶段，即：(1) 智能体从环境中感知信息，并将其存入记忆；(2) 智能体处理已存储的信息，使其更可用；(3) 智能体基于处理后的记忆信息采取下一个动作。在上述所有阶段中，记忆都扮演着极其重要的角色。下面，我们先从狭义与广义两个视角定义智能体的记忆，然后基于记忆模块详细说明上述三个阶段的执行过程。

### 3.1 基础知识

为清晰呈现，我们先介绍若干重要的背景知识：

> **定义 1（任务，Task）**：任务是智能体需要实现的最终目标，例如为 Alice 预订机票、为 Bob 推荐餐厅等等。形式上，我们用 𝒯 表示一个任务，并在后续内容中用下标标注不同的任务。

> **定义 2（环境，Environment）**：狭义上，环境是智能体为完成任务而需要交互的对象。对于定义 1 中的例子，环境就是 Alice 与 Bob，他们对智能体的动作提供反馈。更广义地，环境可以是影响智能体决策的任何情境因素，例如预订机票时的天气、推荐餐厅时的时间与地点等等。

> **定义 3（试验与步骤，Trial and Step）**：为完成任务，智能体需要与环境交互。通常，智能体先采取一个动作，随后环境对该动作作出响应。最后，智能体基于该响应采取下一个动作。这一过程不断迭代直至任务完成。完整的"智能体—环境"交互过程称为一次试验（trial），每一次交互回合称为一个步骤（step）。对每次试验而言，智能体可以采取多个步骤以构成任务的一个潜在解决方案。对每个任务而言，智能体可以探索多次试验以完成任务 [5]。形式上，在步骤 t，我们用 aₜ 与 oₜ 分别表示智能体动作与观测到的环境响应。那么，一个长度为 T 的试验可表示为 ξ_T = {a₁, o₁, a₂, o₂, …, o_T, a_T}。

在上述定义中，任务与环境是最粗粒度的概念，而步骤是最细粒度的概念。它们共同描述了完整的"智能体—环境"交互过程。

> 图 3：(a) "智能体—环境"交互过程中潜在试验的示例。(b) 记忆读取、写入与管理过程的示意，其中虚线表示跨试验的信息可以被并入记忆模块。

**一个玩具示例（Toy Example）。** 基于上述定义，我们给出一个玩具示例，并在全文中反复使用它以提供更多直观感受。在该示例中，智能体有两个任务：
- (A) 为 Alice 制定 2024/5/1 至 2024/5/3 的北京旅行计划，其中智能体必须 (i) 购买往返机票；(ii) 根据 Alice 的偏好确定若干景点；(iii) 安排这些景点的参观顺序。
- (B) 在 2024/5/10 为 Alice 推荐一部电影，其中智能体必须 (i) 确定 Alice 有空看电影的时间；(ii) 根据 Alice 的观影偏好选择一部电影。

对每个任务，我们给出一个潜在试验如下（也由图 3(a) 示意）。对于任务 (A)，该试验为：

- **[步骤 1]** 智能体：我需要通过在线售票处预订 2024/5/1 上海→北京与 2024/5/3 北京→上海的机票。环境（在线售票处）：订单已确认。去程航班上午 9:00 起飞，您的票号为 EK240501SX9021。返程航班下午 4:30 起飞，您的票号为 LG240503FN6317。请准时到达机场登机。
- **[步骤 2]** 智能体：我从杂志《北京景点》（Attractions in Beijing）获取了外部知识。其中显示长城、故宫与颐和园很有名。根据 Alice 的偏好，我认为她偏爱古代建筑，因此确定故宫与颐和园为目的地。环境（Alice）：做得好！
- **[步骤 3]** 智能体：现在，我需要为 Alice 安排参观顺序。根据上述信息，我建议她抵达北京后先参观颐和园，因为那里适合花整个下午游玩并欣赏日落。随后，她第二天可以去故宫，这样时间充裕。最后，她第三天返回上海并休息。环境（Alice）：我爱这个计划。谢谢！

对于任务 (B)，该试验为：

- **[步骤 1]** 智能体：根据我之前为 Alice 推荐电影的经验，她偏好晚上 9:00 开始看电影，因为那时她已经下班。我应该询问 Alice 那个时间是否有空。环境（Alice）：当然，那是个不错的时间！
- **[步骤 2]** 智能体：现在，我需要找一些 Alice 在 Netflix 上标记"想看"的电影。环境（Netflix）：Alice 想看的影片：星际穿越（Interstellar）、恐怖星球（Planet Terror）、鬼吹灯之黄皮子坟（Candle in the Tomb）。
- **[步骤 3]** 智能体：既然 Alice 从不在夜里看恐怖片，星际穿越更适合她。现在，我需要与 Alice 确认影片。环境（Alice）：太好了！我喜欢！

### 3.2 智能体记忆的狭义定义

狭义上，智能体的记忆仅与同一试验内的历史信息相关。形式上，对给定任务，步骤 t 之前的试验历史信息为 ξ_t = {a₁, o₁, a₂, o₂, …, a₍ₜ₋₁₎, o₍ₜ₋₁₎}，记忆即基于 ξ_t 推导得出。在上述玩具示例中，对任务 (A)，智能体在 [步骤 3] 需要为 Alice 安排参观顺序；此时，其记忆包含 [步骤 1] 与 [步骤 2] 中选定的景点与到达时间信息。对任务 (B)，智能体在 [步骤 3] 必须为 Alice 选择电影；此时，其记忆包含已安排好的观影时间。

### 3.3 智能体记忆的广义定义

广义上，智能体的记忆可以来自更广泛的来源，例如跨试验的信息、超出"智能体—环境"交互范围的外部知识。形式上，给定一系列顺序任务 {𝒯₁, 𝒯₂, …, 𝒯_K}，对任务 𝒯_k，步骤 t 的记忆信息来自三个来源：
1. 同一试验内的历史信息，即 ξ_t^k = {a₁ᵏ, o₁ᵏ, …, a₍ₜ₋₁₎ᵏ, o₍ₜ₋₁₎ᵏ}，其中我们加上标 k 以标注任务索引。
2. 跨不同试验的历史信息，即 Ξ^k = {ξ¹, ξ², …, ξᵏ⁻¹, ξᵏ′}，其中 ξʲ（j ∈ {1, …, k−1}）表示任务 j 的试验（注：对每个任务，可以有多次试验以探索最终解决方案，它们都可以并入记忆），ξᵏ′ 表示任务 𝒯_k 之前探索过的试验。
3. 外部知识，记为 D_t^k。

智能体的记忆基于 (ξ_t^k, Ξ^k, D_t^k) 推导得出。在上述玩具示例中，对任务 (A)，如果存在若干次失败的试验（即 Alice 的反馈是负面的），则这些试验可以并入智能体的记忆，以避免未来再犯类似错误（对应 ξᵏ′）。此外，对任务 (B)，智能体可以推荐与 Alice 在任务 (A) 中参观过的景点相关的电影，以捕捉她最近的偏好（对应 {ξ¹, ξ², …, ξᵏ⁻¹}）。在智能体的决策过程中，它也曾参考杂志《北京景点》来制定旅行计划，这对当前任务 𝒯_k 而言就是外部知识（对应 D_t^k）。

### 3.4 记忆辅助的"智能体—环境"交互

如第 3 节开头所述，"智能体—环境"交互过程包含三个关键阶段。智能体记忆模块通过三种操作实现这些阶段，即记忆写入（memory writing）、记忆管理（memory management）与记忆读取（memory reading）。

**记忆写入。** 该操作旨在把原始观测投影为实际存储的记忆内容，后者信息量更大 [7]、也更简洁 [6]。它对应"智能体—环境"交互过程的第一个阶段。给定任务 𝒯_k，若智能体在步骤 t 采取动作 a_t^k，且环境提供观测 o_t^k，则记忆写入操作可形式化表示为：

> m_t^k = W({a_t^k, o_t^k})

其中 W 是投影函数。m_t^k 是最终存储的记忆内容，可以是自然语言或参数化表示。在上述玩具示例中，对任务 (A)，智能体应在 [步骤 2] 之后记住航班安排与景点决策。对任务 (B)，智能体应在 [步骤 1] 之后记住"Alice 希望晚上 9:00 看电影"这一事实。

**记忆管理。** 该操作旨在处理已存储的记忆信息以使其更有效，例如总结高层概念使智能体更具泛化能力 [6]、合并相似信息以减少冗余 [7]、遗忘不重要或不相关的信息以消除其负面影响。该操作对应"智能体—环境"交互过程的第二阶段。设 M₍ₜ₋₁₎ᵏ 是步骤 t 之前任务 k 的记忆内容，并假设 m_t^k 是基于上述记忆写入操作在步骤 t 存储的信息，那么记忆管理操作可表示为：

> M_t^k = P(M₍ₜ₋₁₎ᵏ, m_t^k)

其中 P 是迭代处理已存储记忆信息的函数。对狭义的记忆定义，迭代只发生在同一试验内，试验结束时记忆被清空。对广义的记忆定义，迭代发生在不同试验甚至不同任务之间，也包含外部知识的整合。在上述玩具示例的任务 (B) 中，智能体可以总结出"Alice 喜欢在晚上看科幻电影"，这可以作为未来为 Alice 提供推荐时的默认规则。

**记忆读取。** 该操作旨在从记忆中获取重要信息以支撑智能体的下一个动作。它对应"智能体—环境"交互过程的第三阶段。设 M_t^k 是步骤 t 任务 k 的记忆内容，c_t^k 是下一动作的上下文，那么记忆读取操作可表示为：

> M̂_t^k = R(M_t^k, c₍ₜ₊₁₎ᵏ)

其中 R 通常通过计算 M_t^k 与 c₍ₜ₊₁₎ᵏ 之间的相似度来实现 [82]。M̂_t^k 被用作最终提示（prompt）的一部分以驱动智能体的下一动作。在上述玩具示例的任务 (B) 中，当智能体在 [步骤 3] 决定最终推荐的电影时，它应当聚焦 [步骤 2] 中的"想看"列表并从中选择一部。

基于上述操作，我们可以推导出从 {a_t^k, o_t^k} 到 a₍ₜ₊₁₎ᵏ 的演化过程的统一函数：

> a₍ₜ₊₁₎ᵏ = LLM{R(P(M₍ₜ₋₁₎ᵏ, W({a_t^k, o_t^k})), c₍ₜ₊₁₎ᵏ)}

其中 LLM 是大语言模型。通过迭代展开该函数，即可轻松得到完整的"智能体—环境"交互过程（直观示意见图 3(b)）。

> **注（Remark）**：该函数提供了智能体记忆化（memorizing）过程的一般公式。以往工作可能采用不同的具体实现。例如，在 [5] 中，R 与 P 被设为恒等函数，且 P 仅在试验结束时生效。在 Park 等人 [83] 中，R 基于相似度、时间间隔与重要性三个准则实现，P 则通过反思（reflection）过程实现以获得更抽象的思想。在本节中，我们聚焦智能体记忆操作的整体框架。W、P、R 的更具体实现将推迟到第 5 节详述。

## 4. 基于 LLM 的智能体为何需要记忆（Why We Need the Memory）

上文已经介绍了基于 LLM 的智能体的记忆是什么。在全面呈现如何实现它之前，本节简要说明为什么记忆对构建基于 LLM 的智能体是必要的，我们从认知心理学、自我进化与智能体应用三个视角展开讨论。

### 4.1 认知心理学视角

认知心理学是对人类心理过程的科学研究，如注意、语言使用、记忆、知觉、问题求解、创造力与推理等。在这些过程中，记忆被广泛认为极其重要 [84]。它是人类以下能力的基础：通过积累重要信息并抽象出高层概念来学习知识 [85]；通过记住文化价值与个人经验来形成社会规范 [86]；通过设想潜在的正负后果来采取合理行为 [87]；等等。

基于 LLM 的智能体的一个主要目标是替代人类完成各种任务。为使智能体的行为像人，遵循人类的工作机制来设计智能体是自然且必要的选择 [88]。既然记忆对人类很重要，为智能体设计记忆模块也就意义重大。此外，认知心理学已被研究很长时间，积累了诸多有效的人类记忆理论与架构，这可以支撑智能体更高级的能力 [89]。

### 4.2 自我进化视角

为完成不同的实际任务，智能体必须在动态环境中自我进化 [90]。在"智能体—环境"交互过程中，记忆对以下方面至关重要：(1) **经验积累（Experience accumulation）**。记忆的一个重要功能是记住过去的错误规划、不当行为或失败经验，从而让智能体在未来处理类似任务时更有效 [91]。这对提升智能体在自我进化过程中的学习效率极其重要。(2) **环境探索（Environment exploration）**。为在环境中自主进化，智能体必须探索不同的动作并从反馈中学习 [92]。通过记住历史信息，记忆可以帮助更好地决定何时以及如何进行探索，例如更关注以往失败的试验或探索频率较低的动作 [93]。(3) **知识抽象（Knowledge abstraction）**。记忆的另一个重要功能是从原始观测中总结并抽象出高层信息，这是智能体对未见过的环境更具适应性与泛化能力的基础 [82]。总之，自我进化是基于 LLM 的智能体的基本特征，而记忆对自我进化至关重要。

### 4.3 智能体应用视角

在许多应用中，记忆是智能体不可或缺的组成部分。例如，在对话智能体中，记忆存储历史对话信息，这是智能体生成下一条回复所必需的。没有记忆，智能体就不知道上下文，无法继续对话 [94]。在模拟智能体中，记忆对于让智能体始终遵循角色设定非常重要。没有记忆，智能体可能在模拟过程中轻易跳出角色 [95]。以上两个例子都表明，记忆不是可选的组件，而是智能体完成给定任务所必需的。

从上述三个视角看，第一个视角揭示记忆构建了智能体的认知基础；第二与第三个视角表明记忆对智能体的进化原则与应用是必要的，为设计带记忆机制的智能体提供了洞见。

#### 5.1.1 试验内信息（Inside-trial Information）

在"智能体—环境"交互过程中，试验内的历史步骤通常是支撑智能体未来动作最相关、信息量最大的信号。几乎所有以往工作都把这类信息用作记忆来源的一部分。

**代表性研究。** Generative Agents [83] 旨在用基于 LLM 的智能体模拟人类的日常行为。智能体的记忆源于为实现目标而采取的历史行为，例如在调研某个特定主题时收集的相关论文。MemoChat [94] 旨在与人类聊天，其智能体的记忆基于一次对话会话的对话历史得出。TiM [97] 旨在通过在完成任务后自我生成多种想法来增强智能体的推理能力，这些想法被用作记忆以提供更具泛化性的信息。Voyager [99] 专注于构建基于《我的世界》（Minecraft）的游戏智能体，其记忆包含完成任务的初步与基本动作的可执行代码。应当注意，试验内信息不仅包括"智能体—环境"交互，还包含交互上下文，例如时间与位置信息。

**讨论。** 试验内信息是与智能体必须完成的当前任务高度相关的来源，因此是最明显、最直观的应当用于构建智能体记忆的信息。然而，仅依赖试验内信息可能阻碍智能体从各种任务中积累有价值的知识并学习更具泛化性的信息。因此，许多研究也在探索如何有效利用跨任务信息来构建记忆模块，这将在下面详述。

#### 5.1.2 跨试验信息（Cross-trial Information）

对基于 LLM 的智能体而言，在环境中多次试验间积累的信息也是记忆的关键部分，通常包括成功与失败的动作及其洞见，例如失败原因、成功所需的常见动作模式等等。

**代表性研究。** 最突出的研究之一是 Reflexion [5]，它为基于 LLM 的智能体提出了言语强化学习（verbal reinforcement learning）。它以言语形式从过去的试验中提炼经验，并在后续试验中应用这些经验以提升同一任务的表现。此外，Retroformer [103] 对反思模型进行微调，使智能体能更有效地从过去的试验中提取跨试验信息。在 Synapse [91] 中，智能体聚焦于解决计算机控制任务。它们的记忆可以通过成功的示例（exemplar）记录跨试验信息，这些示例会在相似试验中作为参考。在 ExpeL [82] 中，智能体需要解决环境中一系列复杂的交互任务。它们存储并组织已完成的轨迹，并为新任务召回相似的轨迹。在被召回的轨迹中，成功案例会与失败案例进行比较，以识别成功的模式。

**讨论。** 凭借积累的跨试验信息记忆，智能体能够积累经验，这对它们的进化很重要。基于过往经验，智能体可以根据整个过程的整体反馈调整自身动作。与充当短期记忆（short-term memory）的试验内观测相比，试验经验可以被视为长期记忆（long-term memory）。它利用不同试验的反馈来支撑更大范围的智能体试验，为智能体提供更持久的经验支持。然而，局限在于：试验内与跨试验信息都要求智能体亲身参与"智能体—环境"交互，外部经验与知识并不包含在内。

#### 5.1.3 外部知识（External Knowledge）

基于 LLM 的智能体的一个重要特征是可以用自然语言直接与其交流和控制。因此，基于 LLM 的智能体可以轻松整合文本形式的外部知识（例如维基百科）来辅助决策。

**代表性研究。** 在 ReAct [104] 中，智能体需要通过多步推理回答关于常识知识的问题。若在这些步骤中缺乏信息，它们可以调用维基百科 API 获取外部知识。GITM [93] 旨在设计《我的世界》中的智能体，使其能够在复杂且奖励稀疏的环境中探索。智能体从在线 Minecraft Wiki 与合成配方中取材，为其导航提供源源不断的知识。CodeAgent [114] 聚焦仓库级（repo-level）代码生成任务，这类任务通常需要复杂的依赖与大量文档。它设计了一种网络搜索策略来获取相关外部知识。ChatDoctor [115] 把基于 LLM 的智能体适配到医疗领域。它微调了一个获取流程，用于从维基百科与医学数据库检索外部知识。

**讨论。** 外部知识可以从私有与公共来源获得。它为基于 LLM 的智能体提供了超出其内部环境的大量知识，而这些知识是智能体难以甚至不可能通过"智能体—环境"交互获取的。此外，大多数外部知识可以通过根据任务需求实时、动态地访问各种工具的 API 来获取，从而缓解知识过时的问题。将外部知识整合进基于 LLM 的智能体的记忆，显著扩展了它们的知识边界，为决策提供了无限、最新且有据可依的知识。

#### 5.2.1 文本形式的记忆

文本形式是目前表示记忆内容的主流方法，其特点是更好的可解释性、更容易实现、读写效率更快。具体地，文本形式既可以是无结构表示，如原始自然语言，也可以是结构化信息，如元组、数据库等等。一般而言，以往研究用文本形式记忆存储四类信息：(1) 完整的"智能体—环境"交互；(2) 近期的"智能体—环境"交互；(3) 被检索的"智能体—环境"交互；(4) 外部知识。前三种方法利用自然语言描述"智能体—环境"交互回路内的信息，最后一种利用自然语言存储交互回路外的信息。

**完整交互（Complete Interactions）。** 该方法基于长上下文（long-context）策略 [116] 存储"智能体—环境"交互历史的全部信息。以第 3.1 节中的示例为例，任务 (A) 中智能体在步骤 2 之后的记忆可以通过拼接步骤 2 之前的所有信息来实现，最终的文本形式记忆是："您的记忆是 [步骤 1]（智能体）……（在线售票处）……[步骤 2]……请基于您的记忆进行推断。"

在以往工作中，不同模型用不同策略存储记忆信息。例如，在 LongChat [116] 中，智能体专注于理解长上下文场景中的自然语言。它微调基础模型以更好地适应记忆完整交互。Memory Sandbox [117] 旨在缓解对话中无关记忆的影响。它设计了一种透明、可交互的方法来管理智能体的记忆，在把记忆拼接成提示之前移除无关记忆。此外，一些努力致力于增强 LLM 处理更长上下文的能力 [118, 119]。

虽然存储全部"智能体—环境"交互能保留完整信息，但在计算成本、推理时间与推理鲁棒性上存在明显局限。首先，由于注意力计算的时间复杂度随序列长度呈二次增长，实践中快速增长的长上下文记忆在 LLM 推理期间会造成很高的计算成本。这需要更多的计算资源并显著增加推理延迟，阻碍其实际部署。此外，随着记忆快速增长，记忆长度很容易超过 LLM 预训练时的序列长度上界，这使得必须对记忆进行截断。因此，它会因智能体记忆不完整而导致信息丢失。最后，它还会导致 LLM 推理的偏差与非鲁棒性。具体地，先前一项研究 [120] 表明，长上下文中文本片段的位置会极大影响其被利用的程度，因此长上下文提示中的记忆不能被平等、稳定地对待。上述所有缺点都表明，需要为基于 LLM 的智能体设计额外的记忆模块，而不是简单地把所有信息拼接进提示。

**近期交互（Recent Interactions）。** 该方法用自然语言存储并维护最近获得的记忆，从而依据局部性原理（Principle of Locality）[121] 提升记忆信息利用的效率。在第 3.1 节示例的任务 (B) 中，我们只需记住 Alice 最近三年的偏好并截断更远的部分，其中"最近三年"可视为记忆窗口大小。

在以往研究中，存储近期文本记忆有各种策略。例如，SCM [98] 提出一种基于缓存机制的"闪存（flash memory）"，保留最近 t−1 个时间步的观测，旨在增强信息的时新性。MemGPT [100] 把智能体视为操作系统，可通过自然接口与用户动态交互。它设计了保存近期历史的工作上下文（working context），作为虚拟上下文管理的一部分。在 RecAgent [95] 中，智能体被设计用来模拟电影推荐中的用户行为。它把一些时间信息作为中间缓存存储在短期记忆中，可以模拟人脑的记忆机制 [122, 123]。这些代表性方法能基于近期交互动态更新记忆，更关注对当前阶段重要的近期上下文。

按时新性缓存记忆是提升记忆效率的有效途径，它使智能体能更聚焦于近期信息。然而，在长期任务中，这种方法无法访问遥远记忆中的关键信息，可能导致处于即时缓存窗口之外、却可能至关重要的信息丢失。换言之，强调时新性会天然忽略更早但关键的信息，从而在需要全面理解过往事件的场景中带来挑战。

**检索交互（Retrieved Interactions）。** 与上述基于时间截断记忆的方法不同，该方法通常基于相关性、重要性与主题来选择记忆内容。它确保遥远但关键的记忆也被纳入决策过程，从而解决"只记忆近期信息"的局限。在第 3.1 节示例的任务 (A) 中，Alice 的偏好在本次任务之前已经存入记忆。在 [步骤 2]，智能体会基于查询关键词"旅行"从记忆中检索与 Alice 偏好最相关的部分，得到她偏爱古代建筑的景点偏好。一般而言，检索方法会在记忆写入时生成嵌入（embedding）作为记忆条目的索引，并记录辅助信息以协助检索。在记忆读取时，会为每条记忆计算匹配分数，得分最高的 top-K 条将被用于智能体的决策过程。

在现有研究中，大多数智能体利用检索方法来处理记忆信息。例如，Park 等人 [83] 首先通过余弦相似度计算当前上下文与记忆条目之间的相关性，再根据辅助信息得到重要性与时新性。MemoryBank [6] 采用双塔密集检索模型从过往对话中找到相关信息。每条记忆都被编码为嵌入，随后由 FAISS [124] 建立索引以提升检索效率。读取记忆时，当前上下文被编码为表征以获得最相关的记忆。此外，RET-LLM [7] 旨在设计一个通用的写读记忆模块。它利用局部敏感哈希（Locality-Sensitive Hashing, LSH）检索数据库中带有相关条目的元组以提供更多信息。另外，ChatDB [96] 设计利用符号记忆（symbolic memory），并提出生成 SQL 语句从数据库检索以获取存储的信息。

检索方法在很大程度上依赖"获得期望信息的准确性与效率"。不准确的检索策略可能获取无关信息，对智能体推理无益；而笨重的检索系统会导致巨大的计算成本与长时间延迟，尤其是在处理海量信息时。此外，检索方法通常在环境内存储同质信息，所有信息形式一致；对环境中异构的外部信息，难以直接套用同一方法进行记忆存储。

**外部知识（External Knowledge）。** 为获取更多信息，一些智能体通过调用工具获取外部知识，旨在把额外相关知识转化为自身记忆以供决策。例如，通过应用程序编程接口（API）访问外部知识是一种常见做法 [104, 5]。如今，丰富的公共信息（如维基百科、OpenWeatherMap 等）都可在网上获取（免费或付费），并能方便地通过 API 调用访问。例如，在第 3.1 节示例任务 (A) 的 [步骤 2] 中，来自数字杂志的外部知识就是通过工具方式获得的。

在现有模型中，Toolformer [125] 提出教 LLM 使用工具，从而获取外部知识以更好求解任务。此外，ToolLLM [126] 赋予 Llama [127] 使用 RapidAPI 中更多 API 的能力并支持多工具使用，为扩展智能体能力提供了通用接口。在 TPTU [110] 中，智能体同时参与任务规划与工具使用以解决复杂问题；后续工作 [111] 进一步大幅提升了其检索等能力。在 ToRA [128] 中，智能体需要求解数学问题，它们利用模仿学习（imitation learning）提升使用基于程序的工具的能力。

上述方法允许智能体从多样来源访问最新、真实的外部信息，显著推进了智能体的能力。然而，由于潜在的不准确与偏差，这些信息的可靠性可能存疑 [18]。此外，把工具整合进智能体需要全面理解以在不同上下文中解读检索到的信息，这可能带来更高的计算成本，并使外部数据与内部决策过程的对齐复杂化。另外，使用外部 API 还引发隐私、数据安全与使用政策合规方面的担忧，需要严格的管理与监督 [18]。

#### 5.2.2 参数形式的记忆

另一类方法是以参数形式表示记忆。它们不占用提示中的额外上下文长度，因此不受 LLM 上下文长度限制的约束。然而，参数形式的记忆仍研究不足，我们把以往工作分为两类：微调方法与记忆编辑方法。

**微调方法（Fine-tuning Methods）。** 把外部知识整合进智能体的记忆，有利于在通用知识之上丰富领域专属知识。为了把领域知识注入 LLM，监督微调是常见做法，它赋予智能体领域专家的记忆，显著提升智能体完成领域专属任务的能力。在第 3.1 节示例的任务 (A) 中，来自杂志的景点外部知识可以在任务开始之前被微调进 LLM 的参数。

在以往工作中，Character-LLM [105] 聚焦角色扮演场景。它利用带角色相关数据（如经历）的监督微调策略，赋予智能体该角色的特定性格与特征。Huatuo [107] 旨在赋予智能体生物医学领域的专业能力，它尝试在中文医学知识库上微调 Llama [127]。此外，为创造人工智能医生，DoctorGLM [129] 用 LoRA [131] 微调 ChatGLM [130]；Radiology-GPT [132] 通过在带标注的放射学数据集上监督微调来提升放射学分析的领域知识。另外，InvestLM [113] 收集投资数据并微调，以提升金融投资领域的专属能力。

微调方法能有效弥合通用智能体与专用智能体之间的差距，提升智能体在需要领域信息高精度、高可靠性的任务上的能力。然而，针对特定领域微调 LLM 可能导致过拟合，也会引发灾难性遗忘（catastrophic forgetting）的担忧——LLM 可能因为参数更新而忘记原有知识。微调的另一局限在于计算成本与时间消耗，以及需要大量数据。因此，大多数微调方法适用于离线场景，很少能处理在线场景，例如基于智能体观测与试验经验进行微调。由于"智能体—环境"交互频繁，对在线动态交互的每一步都进行反向传播微调，成本难以承受。

**记忆编辑方法（Memory Editing Methods）。** 除微调方法外，另一类把记忆注入模型参数的方法是知识编辑（knowledge editing）[133, 134]。与从特定数据集中提取模式的微调方法不同，知识编辑方法只针对并调整需要改变的事实，确保无关知识不受影响。知识编辑方法更适合小规模记忆调整，通常计算成本更低，因此更适合在线场景。以我们示例中的任务 (B) 为例：根据智能体的记忆，Alice 总是在晚上 9:00 看电影，但她可能最近换了工作、晚上 9:00 没空。若如此，相关的记忆（例如晚上 9:00 的惯例）应当被编辑，这可以通过知识编辑方法实现。

在以往研究中，MAC [106] 旨在为在线场景设计有效且高效的记忆适配框架，它利用元学习（meta-learning）替代优化步骤。PersonalityEdit [135] 聚焦编辑 LLM 与智能体的性格，基于大五人格（big-five factor）等理论改变其特质。MEND [134] 利用元学习思想训练一个轻量模型，它能为基础语言模型的模型参数生成修改。APP [136] 研究添加一个新事实是否会导致现有事实的灾难性遗忘，它关注邻居扰动（neighbor perturbation）对记忆添加的影响。此外，KnowledgeEditor [133] 基于"学习更新"（learning-to-update）的问题形式化，训练一个超网络（hyper-network）来预测注入记忆时模型参数的修改。Wang 等人 [137] 提出一个新的优化目标来改变 LLM 的有毒知识，同时保持通用性能。对基于 LLM 的智能体而言，智能体可以通过知识编辑改变不良记忆，这可以被视为一种遗忘（forgetting）机制。

知识编辑方法提供了一种创新的方式来更新存储在 LLM 参数中的信息。通过精准定位并调整事实，这些方法能确保更新期间非目标知识不受影响，从而缓解灾难性遗忘问题。此外，精准调整机制允许更高效、更省资源的更新，使知识编辑成为高精度、实时修改的有吸引力的选择。然而，尽管有这些有前景的进展，元训练的计算成本与无关记忆的保持仍然是重大挑战。

#### 5.2.3 文本记忆与参数记忆的优缺点

文本记忆与参数记忆各有优劣，适用于不同的记忆内容与应用场景。本节我们从多个方面讨论这两种记忆形式的优缺点。

**有效性（Effectiveness）。** 文本记忆存储关于"智能体—环境"交互的原始信息，更全面、更细致。然而它受 LLM 提示的 token 限制约束，使智能体难以存储海量信息。相比之下，参数记忆不受提示长度限制，但把文本转化为参数时可能遭受信息丢失，复杂的记忆训练也会带来额外挑战。

**效率（Efficiency）。** 对文本记忆而言，每次 LLM 推理都需要把记忆整合进上下文提示，导致更高成本与更长处理时间。相比之下，参数记忆把信息整合进 LLM 参数中，省去了这些上下文的额外成本。然而参数记忆在写入过程中有额外成本，而文本记忆写入更容易，尤其是对小数据量。简言之，文本记忆写入更高效，参数记忆读取更高效。

**可解释性（Interpretability）。** 文本记忆通常比参数记忆更可解释，因为自然语言是人类理解最自然、最直接的方式；而参数记忆通常在潜在空间（latent space）中表示。然而，这种可解释性是以信息密度为代价获得的。这是因为文本记忆中的词序列在离散空间中表示，不如参数记忆中的连续空间稠密。

总之，两类记忆之间的权衡使它们适用于不同应用。例如，对需要召回近期交互的任务（如对话与上下文特定任务），文本记忆似乎更有效；对需要大量记忆或成熟知识的任务，参数记忆可能是更好的选择。

#### 5.3.1 记忆写入（Memory Writing）

当信息被智能体感知后，其中一部分将通过记忆写入操作被智能体存储以供后续使用，因此识别哪些信息值得存储至关重要。许多研究选择存储原始信息，另一些则把原始信息的摘要也放入记忆模块。

**代表性研究。** 在 TiM [97] 中，原始信息会被抽取为两个实体之间的关系，并存储进结构化数据库；写入数据库时，相似内容会被存放在同一分组。SCM [98] 设计了一个记忆控制器（memory controller）来决定何时执行操作，该控制器充当整个记忆模块的向导。在 MemGPT [100] 中，记忆写入完全自主驱动，智能体可以基于上下文自主更新记忆。在 MemoChat [94] 中，智能体通过抽象出各对话片段主要讨论的主题来总结每一片段，并将这些主题作为键（key）存储以索引记忆片段。

**讨论。** 以往研究表明，在记忆写入操作中设计信息抽取策略至关重要 [94]。这是因为原始信息通常冗长且有噪声。此外，不同环境可能提供各种形式的反馈，如何抽取并把信息表示为记忆，对记忆写入同样意义重大。

#### 5.3.2 记忆管理（Memory Management）

对人类而言，记忆信息在大脑中不断被处理与抽象。智能体的记忆也可以通过反思（reflecting）生成更高级的记忆、合并（merging）冗余记忆条目、遗忘（forgetting）不重要或较早的记忆来管理。

**代表性研究。** 在 MemoryBank [6] 中，智能体把对话处理、提炼为日常事件的高层摘要，类似于人类回忆自身经历关键方面的方式。通过长期交互，它们持续评估并完善自身知识，生成关于个性特质的每日洞见。在 Voyager [99] 中，智能体能基于环境的反馈完善自身记忆。在 Generative Agents [83] 中，智能体可以反思以获得更高级的信息，抽象思想由智能体生成；当积累的事件足够多、值得处理时，反思过程会被激活。GITM [93] 为建立适用于各种情境的公共参考方案，会把多个方案中的关键动作在记忆模块中进一步总结。

**讨论。** 大多数记忆管理操作都受到人脑工作机制的启发。借助 LLM 模拟人类心智的强大能力，这些操作能帮助智能体更好地生成高层信息并与环境交互。

#### 5.3.3 记忆读取（Memory Reading）

当智能体需要信息进行推理与决策时，记忆读取操作会从记忆中提取相关信息以供使用。因此，如何访问与当前状态相关的信息很重要。由于记忆实体数量庞大，且并非全部与当前状态相关，需要精心设计，以基于相关性及其他面向任务的因素提取有用信息。

**代表性研究。** 在 ChatDB [96] 中，记忆读取操作由 SQL 语句执行，这些语句由智能体预先以一系列"记忆链（Chain-of-Memory）"的形式生成。在 MPC [101] 中，智能体可以从记忆池中检索相关记忆，该方法还提出提供思维链（Chain-of-Thought）示例来忽略某些记忆。ExpeL [82] 利用 Faiss [124] 向量库作为记忆池，获取与当前任务相似度得分最高的 top-K 条成功轨迹。

**讨论。** 从某种程度上说，记忆读取与写入操作是协同的，记忆写入的形式会极大影响记忆读取的方法。对文本记忆形式，大多数以往工作使用文本相似度及其他辅助信息进行读取；对参数记忆形式，现有模型可能直接利用更新后的参数进行推理，这可以被视为一种隐式的读取过程。

## 6. 如何评估基于 LLM 的智能体中的记忆（How to Evaluate）

如何有效评估记忆模块仍是一个开放问题，以往工作根据不同应用提出了多样的评估策略。为清晰呈现不同评估方法的共性思想，本节总结了一个通用框架，包含两大类评估策略（总览见图 5），即：(1) **直接评估（direct evaluation）**，独立地衡量记忆模块的能力；(2) **间接评估（indirect evaluation）**，通过端到端的智能体任务来评估记忆模块。如果任务能被有效完成，则说明记忆模块是有用的。

> 图 5：记忆模块评估方法概览。

### 6.1 直接评估（Direct Evaluation）

这类方法把智能体的记忆视为独立组件，单独评估其有效性。以往研究可分为两类：主观评估与客观评估。主观评估旨在基于人的判断衡量记忆有效性，可广泛用于缺乏客观真值（ground truth）的场景。客观评估则基于数值指标衡量记忆有效性，便于比较不同记忆模块。

#### 6.1.1 主观评估（Subjective Evaluation）

在主观评估中，有两个关键问题：(1) 应当评估哪些方面；(2) 如何进行评估过程。首先，以下两个方面是评估记忆模块最常用的视角。

**连贯性（Coherence）。** 这一方面指被召回的记忆是否自然、是否适合当前上下文。例如，如果智能体正在为 Alice 制定旅行计划，那么记忆应当与她的旅行偏好相关，而不是工作偏好。在以往工作中，Modarressi 等人 2023 [7] 研究了记忆模块能否在不断变化的知识中提供合适的参考。Liang 等人 2023 [98] 给出一些示例来展示当前查询与历史记忆之间的关系。Zhong 等人 2023 [6] 与 Liu 等人 2023b [97] 通过评分标签评估融合了上下文与检索记忆的回复的连贯性。Lee 等人 2023 [101] 关注被召回记忆与上下文之间的矛盾。
