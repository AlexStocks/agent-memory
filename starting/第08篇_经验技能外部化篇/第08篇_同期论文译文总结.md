# 十一篇跟踪论文总结

> 本文是《Agent Memory 技术综述》第 8 篇《经验技能外部化篇》的配套材料，逐篇认真总结第 8 篇讨论的十一篇 2026 年论文：**Externalization、SkillEvolBench、SkillShadowing、ASSAY、Ratchet、SkillMisevolve、SkillDAG、SE-GoS、HarnessCL、Recuris、MA-Memory**。
>
> 与公众号正文的分工：正文用这十一篇论证「经验与技能的外部化」这一章在 2026 年下半年已经从一个叙事议题变成了一个有实验证据的系统工程问题——扩容有代价、抽象有损耗、演化有风险，而且三者互相独立；这里回到每篇论文本身，补齐正文因篇幅省略的方法细节、消融数据和边界条件。所有数字均取自对应译文的论文自报结果，并已在译文正文中逐条核对；不同论文的百分数**不同源、不可相加**。

## 1. Externalization：外化不是一个词，是四层

**Externalization in LLM Agents: A Unified Framework for Memory, Skills, Protocols and Harness**
arXiv:2604.08224（路线图第 4 轮原定论文）

### 1.1 它要解决的问题

「外部化」在 2026 年被反复提及，但很少有人把它拆开。这篇要回答的是：**当模型权重不再是唯一的适应载体，能力到底迁到了哪里、分了几层、这几层怎么互相咬合。**

它给出的核心判断是：能力正在经历两次迁移——**从权重层迁到上下文层**（微调 → 提示工程），**再从上下文层迁到 harness 层**（提示工程 → 上下文工程 → harness 工程）。第三次迁移才是这一篇的对象，也是整个系列第 8 篇的起点。

### 1.2 方法（框架怎么搭的）

四层外化 + harness 作统一层：

| 外化层 | 外化的是什么 | 典型载体 |
|---|---|---|
| 记忆 | 状态与事实 | 单体上下文 → 检索存储 → 分层编排 → 自适应记忆 |
| 技能 | 程序性专长 | 原子执行原语 → 大规模原语选择 → 技能作为能力包 |
| 协议 | 交互结构 | Agent–Tool / Agent–Agent / Agent–User / 其他 |
| harness | 上面三者的工程化装配 | 任务接口、记忆、能力地图、路由器 |

论文把整个框架归一为 Norman 的**认知制品（cognitive artifact）理论**：人类靠外部制品扩展认知（笔记、清单、仪表盘），agent 靠记忆、技能、协议扩展能力。这个类比的实用价值在于它继承了一条已知结论：**制品库的维护成本与认知收益是两件事，且收益不随库容线性增长。**

技能那一层有一个三阶段划分很值得单独记住：**原子执行原语 → 大规模原语选择 → 技能作为能力包**。第二阶段和第三阶段之间的区别是整篇文章的关键——第二阶段的问题是怎么从一堆原语里选，第三阶段的问题是怎么把一组原语当成一个包来治理。

### 1.3 关键数字

框架论文没有独立实验，但它的作用是把后续论文的钱花在刀刃上。以下三组对照是它提供的坐标：

- **技能 vs 工具的载荷差异**：调用技能是把**指令性文本注入上下文**，随后智能体自己驱动执行；调用工具是执行代码并返回计算结果。这解释了为什么错误的技能比错误的工具调用更危险——后者往往因 schema 不匹配而报错，前者会被当作权威。
- **技能作用域的重叠问题**：技能依赖自然语言描述，其作用域比强类型工具模式**更宽、重叠更多**。这直接对应第 2 节 SkillShadowing 的遮蔽机制。
- **harness 的模块交互**：提示、记忆、工具、技能、路由规则**共同塑造后续执行**——这条在 HarnessCL（第 9 篇）里被变成了可测量的实验主张。

### 1.4 边界与短板

- 无独立实验，所有判断基于文献梳理，不能作为数字化结论的证据。
- 四层划分的边界在某些系统上不完全清晰（例如「技能」与「协议」在 Agent–Tool 场景下会重叠）。
- 认知制品类比是启发性而非约束性的——它提示了问题，但没有给出可证的命题。

### 1.5 怎么用这篇

- **最适合**：给你的技能库/记忆系统做一次定位盘点——你的能力到底外化在哪几层、这四层有没有互相矛盾；作为第 8 篇乃至整个系列的坐标系。
- **不要拿来**：当作「外化一定更好」的论据。它只描述了迁移的方向，没有声称迁移的方向是收益更高的方向——这个问题要交给后面十篇。

## 2. SkillEvolBench：把轨迹压成技能这件事本身在丢信息

**SkillEvolBench: Benchmarking the Evolution of Skill Libraries for LLM Agents**
俄亥俄州立大学 / 芝加哥大学 / UCL / 密歇根大学 / 香港中文大学 / 凯斯西储大学 / Amazon · arXiv:2605.24117

### 2.1 它要解决的问题

技能演化（skill evolution）领域的评测长期处于「各自报涨点」的状态：每篇论文换一个基准、换一组指标、换一套基线，无法横向比较。更深的问题是**没有人验证过一个隐含前提**：把成功的轨迹蒸馏成技能，这个动作是否真的保住了信息？

SkillEvolBench 的核心发现直接否定了这个前提：**原始轨迹复用经常优于蒸馏技能**（Raw-Trajectory 基线均值 RSR 48.2%、ESR 37.6%、ARSR 44.7%、CompSR 25.7%）。这就是**有损抽象瓶颈（lossy abstraction bottleneck）**——抽象动作本身在丢信息，而丢失的部分在后续任务上会显形。

### 2.2 方法（基准怎么造的）

- **规模**：180 个任务、6 个环境、30 个任务族、6 类角色。
- **六个环境**：E1 Code、E2 Tool/API、E3 Data、E4 Docs、E5 Research、E6 Comm。
- **六个指标**：LSR（库规模）、RSR（检索）、ESR（执行）、CSSR（跨会话）、ARSR（抽象复用）、CompSR（组合）。
- **三条 harness 形态**：No-Skill / Curated-Static / Raw-Trajectory，作为技能库的三种供给方式。
- **三个 Tier 资源**：Tier-1 = `SKILL.md` 本体，Tier-2 = 内联片段，**Tier-3 = `scripts/`、`references/`、`assets/`**（即技能的附属资源）。
- **评测矩阵**：10 个模型 × 3 种 harness 形态 × 6 个指标。

### 2.3 关键数字

**① 环境方差远大于模型方差。**

| 对比维度 | 最大差距 |
|---|---|
| 最容易 vs 最难环境，LSR | **67.3 pp** |
| 最容易 vs 最难环境，ESR | **42.1 pp** |
| 跨基线，LSR | 仅 1.9 pp |
| 跨基线，ESR | 仅 5.4 pp |

**选错环境比选错模型代价大一个数量级。** 这条修正了一个常见做法：在单一环境上比较技能演化方法。

**② 技能库擅长单点复用，几乎不会组合。**

- E2 Tool/API：CSSR 均值 84.7%（跨会话复用很强）；
- E3 Data：ARSR 69.8%，但 CompSR 仅 **4.5%**；
- E6 Comm：CompSR 是 **0.0%**。

CompSR 衡量把几个技能拼起来完成任务，六个环境里有环境直接是零。**「技能库能自组织」这个假设在组合维度上没有证据支持。**

**③ 静态精选技能库比没有技能更差。**

| 供给方式 | 平均 ESR 变化 | 明细 |
|---|---|---|
| Curated-Static | **−2.44 pp** | 改善 2、打平 1、**伤害 7** |

成本还增加 $0.077/任务。**精心挑过的技能库，平均而言劣于 No-Skill。** 这不是「没用」，是「有害」——精心挑选意味着每条技能都有合理的外观，因而更难被智能体忽略。

**④ Tier-3 资源的效果取决于模型强弱。**

| 模型 | 无 Tier-3 | 有 Tier-3 | 结论 |
|---|---|---|---|
| Opus 4.6 | 37.8% | **40.0%** | 正向 |
| Gemini 3.1 Pro | 35.6% | **40.0%** | 正向 |
| Gemini 3 Flash | 35.6% | **27.8%** | 过载 |
| Sonnet 4.5 | 35.6% | **30.0%** | 过载 |

同一批资源，强模型吃下去变增益，弱模型吃下去变负担。论文把 35.6% 这个共同起点和 27.8% 这个落点对上，排除了「起点差异」这一解释。

### 2.4 边界与短板

- −2.44pp 是 **10 个对照的平均值**，不是普遍性伤害；改善 2、打平 1、伤害 7 说明存在正向对照组。
- 180 任务 / 6 环境的覆盖面虽广，但每个环境内的任务族数量不均衡，环境间的绝对值不可直接比较。
- Raw-Trajectory 的优势部分可能来自「原始轨迹更长、信息更全」这一朴素原因，论文未完全隔离长度这一混淆变量。
- 结论刻画的是作者构造的三种 harness 形态，不代表生产系统中所有技能供给方式。

### 2.5 怎么用这篇

- **最适合**：论证「技能演化需要统一基准」；给「把经验总结成技能」这个动作本身加上一条验证要求——**必须和原始轨迹复用作对照**，否则你测不出有损抽象瓶颈。
- **不要拿来**：当作「技能库无用」的证据——它在 E2（CSSR 84.7%）上表现很好；它反对的是**默认抽象优于原始**这个未经验证的假设。

## 3. SkillShadowing：不是选不出，是被遮蔽

**More Skills, Worse Agents: Examining Skill Libraries in LLM Agents**
arXiv:2605.24050（v2 2026-06-23）

### 3.1 它要解决的问题

业界正在快速装配技能库：Anthropic 发布 Agent Skills 并开放规范，OpenAI 为 Codex 采用同样的 `SKILL.md` 约定，Atlassian / Stripe / Figma 的伙伴技能进入精选目录。但**大多数既有工作都是逐个评估技能的**——如何编写一个技能、如何检索一个技能、某个技能的边际贡献是多少。

作者指出这种「单技能视角」危险地不完整，并给出一条来自工具使用文献的对照：**工具选择准确率会从候选数少于 30 个时的 90% 以上，掉到 11,100 个候选时的 13.6%。** 技能会放大这些失效模式，因为技能的作用域更宽、重叠更多，而且一个错误的技能会被当作权威。

### 3.2 方法（基准怎么造的）

- **基准**：SkillsBench，88 个任务，覆盖文档处理、金融、科学计算、数据分析。
- **筛选**：只纳入「对应技能相对无技能基线至少有 4% 通过率提升」的任务，得到 **38 个（任务, 模型）对**（Haiku 4.5 占 21 个、Sonnet 4.6 占 17 个）——**确认有神谕技能**。这是关键设计：如果基线本身没有收益，退化就无从归因。
- **条件**：基线（只有神谕技能，$S = S^\star$）+ 三个扩展库（$|S| \in \{52, 102, 202\}$）。
- **规模**：**2,545 条轨迹**。
- **分解**：把总降幅 $\Delta$ 精确分解为 **上下文开销 $\Delta_{ctx}$** 与**技能遮蔽 $\Delta_{shd}$**（$\Delta_{ctx} + \Delta_{shd} = \Delta$ 精确成立）。
- **技能遮蔽的定义**：类比编程语言的变量遮蔽（variable shadowing）——与神谕技能描述重叠的**干扰技能**可以**隐藏正确选项**，把智能体引向错误技能或没有技能。条件通过率被固定在它们的完整技能库取值上，只有事件概率发生变化。
- **统计**：95% 两阶段聚类自助法置信区间；结构上区分四种调用事件（仅神谕 / 混合—用了神谕 / 混合—没用神谕 / 未调用技能）。

### 3.3 关键数字

**① 通过率单调下降，且主导项是遮蔽。**

| 技能库规模 | Δctx | Δshd | Δ |
|---|---|---|---|
| 52 | .06 [−.11, .22] | **.03** [−.01, .07] | **.08 [.02, .15]** |
| 102 | .06 [−.11, .23] | **.08 [.02, .15]** | **.14 [.09, .19]** |
| 202 | .07 [−.13, .25] | **.14 [.06, .26]** | **.21 [.15, .27]** |

- 202 条技能时总降幅 **21%**。
- $\Delta_{shd}$ 是**唯一置信区间不包含零**的分量；在最大技能库下占 $\Delta$ 的多数（0.14 / 0.21 ≈ **68%**）。
- $\Delta_{ctx}$ 的点估计始终为正，但**任何规模下都未与零分离**——只能说「提示性的」。

论文的理论上界（引理 1 与引理 2）印证同一结论：上下文开销上界**始终很小、与零不可区分**，而遮蔽上界**急剧增长且全程显著为正**。

**② 行为偏移：从「仅神谕」塌到「未调用技能」。**

| $S$ 条件 | 仅神谕 | 混合—用了神谕 | 混合—没用神谕 | 未调用技能 | $n$ |
|---|---|---|---|---|---|
| $S = S^\star$ | 88.0% | 0.0% | 0.0% | 12.0% | 552 |
| $\lvert S \rvert = 52$ | 80.3% | 0.9% | 2.8% | 16.1% | 542 |
| $\lvert S \rvert = 102$ | 64.4% | 1.4% | 5.9% | 28.3% | 988 |
| $\lvert S \rvert = 202$ | 52.6% | 1.6% | 7.3% | 38.5% | 494 |

「仅神谕」从 88.0% 塌到 52.6%，质量流进「未调用技能」（12.0% → 38.5%）与「混合—没用神谕」（0.0% → 7.3%）。**两种失效并存：放弃（质量流入未调用）与选错（质量流入混合）。**

**③ 一个反直觉的细节。** 在事件 o 内部——即智能体**选择正确**的那部分——二元通过率仍随技能库增长而下降。这提示上下文开销**是真实的，但样本量太小无法确证**。作者据此明确限定：**遮蔽是下降的主导效应，上下文开销只能视作提示性证据。**

### 3.4 边界与短板

- 两个模型来自**同一家供应商**（Haiku 4.5 / Sonnet 4.6），无法排除供应商特有的技能选择行为。
- 只覆盖 **202 条技能**；论文自述，当技能库扩容一个数量级或跨越不同架构家族时，这些模式是否仍成立仍开放。
- 这个规模下**上下文开销仍然不大**——这恰恰是 $\Delta_{ctx}$ 不显著的一部分原因，不能推广到「上下文开销永远不显著」。
- 「神谕技能」的筛选门槛（≥4% 提升）会裁掉一部分弱正增益技能，可能低估真实退化幅度。

### 3.5 怎么用这篇

- **最适合**：论证「技能库扩容的代价主要不是塞不下、是选不出来」——这条直接改变工程优先级：**先做检索侧结构化，再考虑压缩技能文本**。
- **不要拿来**：当作「上下文开销不存在」——它在每个规模下点估计都为正，只是样本量不足以与零分离；当技能库扩容一个数量级时它很可能成为主导。

## 4. ASSAY：90% 以上的技能是因果异质的

**ASSAY: Measuring and Governing Causal Heterogeneity in Skill Libraries**
arXiv:2606.15390 · 代码 <https://github.com/aiming-lab/assay>

### 4.1 它要解决的问题

前两篇都是宏观的。这一篇扎到单个技能这一层，反对的做法很明确：**当前系统把「保留哪些技能」与「如何使用它们」的每一个决策都单独托付给 LLM 的判断。**

作者指出这**混淆了两种截然不同的角色**：

- **从经验中生成一个技能是一种创造性行为**，判断（judgment）很擅长处理；
- **判断该技能是否真的有帮助需要跨大量任务的实证证据**，判断不擅长。

它发现这种「不受检查的累积」有系统性坏处：那些在「它们被学习时的任务」上必不可少的技能，在「它们不适用时的任务」上变成了**纯粹的开销**。AppWorld 上，用于多步购买的规则会**耗尽简单单动作任务的步数预算**；τ-bench retail 上，来自复杂换货的规则会让**直白的取消**操作脱轨。

### 4.2 方法（测量怎么做的）

- **随机掩码（randomized masking）**：在留出任务上逐技能测量**因果贡献**。默认掩码数 $K = 12$。
- **三种情形划分**：用行统计量 $\bar{C}(j)$（平均因果效应）与 $H(s_j)$（异质性）把技能分为**一致有益**（$\bar{C}(j)$ 为正、$H(s_j)$ 小）、**可忽略**（$|\bar{C}(j)|$ 小、$H(s_j)$ 小）、**因果异质**（$H(s_j) \geq \tau_{\text{split}}$）。
- **三种操作，顺序固定以防信息丢失**：**拆分**（把异质技能解析为条件变体）→ **淘汰**（移除可忽略技能）→ **合并**（对拆分引入的近似相同技能去重）。
- **三阶段框架**：在小开发集上算逐技能因果归因 → 离线重构技能库 → 测试时为每个任务**抑制掉预测效应为负的技能**。
- **核心机制是「按任务掩码」**，不是「全局移除坏技能」——这两者的区别被消融实验明确切开了。

### 4.3 关键数字

**① 因果异质性是普遍现象，且对全局治理不可见。**

- **超过 90% 的技能**存在因果异质性：单个技能经常在某些任务类型上有帮助、在另一些上有害。
- 这些**相反效应在聚合时相互抵消**，使得它们对**全局式治理方法完全不可见**。
- **任何单任务判断器都无法检测到这一点**，因为反转只有在跨大量任务聚合证据时才可见。

**② 一个可自查的实例。**

论文图 1 追踪了完整实例：一条 Spotify 播放验证规则（vc-00043）与一条副作用检查规则（vc-00021b），在 Amazon 购买任务中把智能体的注意力从尺寸约束（6.3×6.3 英寸台面、卖家评分 ≥4.5）上引开。**vc-00043 在开发任务上的平均因果效应是 −0.067**——一致的危害。按任务掩码抑制这两条，智能体成功。

**③ 七模型两基准上的结果。**

| 基准 | 模型 | 结果 |
|---|---|---|
| AppWorld 最难划分 | DeepSeek-V3 | 任务目标完成率 **69.3%**，相对提升 **47.4%**，**在所有已发表方法中含权重微调方法中创最好成绩** |
| τ-bench retail | GPT-4.1 | 相对提升 **8.7%**，**不改任何权重**超过 o4-mini、o1 与 GPT-4.5 |

跨四家供应商的七个基础模型一致优于先前的技能治理方法。

**④ 消融把增益定位到了推理时匹配。**

主要增益追溯到**按任务掩码**，这直接证实：**瓶颈在于推理时把技能匹配到任务，而不是全局地移除坏技能。** 也就是说，一个「平均效应为零」的技能可能同时是 A 类任务的资产和 B 类任务的负债——全局移除它会同时丢掉 A 类的收益。

### 4.4 边界与短板

- 「90% 以上因果异质」依赖阈值 $\tau_{\text{split}}$ 的选取，换阈值会改变这个比例。
- 随机掩码数 $K = 12$ 是精度与成本的折中，$K$ 越小异质性估计噪声越大。
- 逐技能因果归因需要一个有代表性的**开发集**；开发集分布偏移会让归因失效。
- 框架假设技能效应在任务类型内相对稳定（否则「按任务掩码」本身就成了耦合过强的选择器）。

### 4.5 怎么用这篇

- **最适合**：论证「聚合指标会骗人」——一条技能在 A 类 +10、B 类 −10，全局看是零，全局治理会判它「可忽略」，但它实际让 A 受益、B 受害；这是技能治理里最容易被漏掉的一类失败。
- **不要拿来**：当作「LLM 判断不可用」——论文的立场是**分工**（判断生成技能、测量治理技能），不是替代；生成环节仍应交由判断。

## 5. Ratchet：一条下限，和一条边界

**Ratchet: Governing Skill Libraries without Unbounded Drift**
arXiv:2605.22148

### 5.1 它要解决的问题

技能库如果长期不维护会怎样？「库漂移」（library drift）在业界是一个有名字但没有定义的现象。这篇要把它变成一个**可证伪的命题**，并且回答一个更尖锐的问题：**当治理依赖一个会出错的 LLM 裁判时，治理本身还能不能给出保证？**

它是一篇**理论 + 实证**混合论文：核心贡献是两条命题——一条给出受治理技能库的性能下限，另一条把该下限推广到有噪声的裁判，并暴露出一条**精确的可靠性边界**。

### 5.2 方法（推导怎么做的）

**命题 1（受治理书架有下限）。** 它界定受治理技能库**最多能跌到无技能对照组以下多少**。关键不是数值本身，而是**哪些量出现在其中**：书架宽度 $C$ 与阈值余量 $\tau$——**二者按构造都是有限的**。把任一个拿掉，这个陈述就**没有什么可说的了**。论文的表述是：**正是在这个意义上，把回路开环运行是发散的。**

两个条件做不同的工作，且都承重：

- **宽度 $C$**（默认 $C = 50$，至多 $C$ 个技能处于 `ACTIVE`）：技能为固定宽度的书架竞争，所以**检索精度不随技能库增长而衰退**；$C$ 是使命题 1 说得出话的两个有限量之一。
- **阈值 $\tau$**：决定**哪些技能是候选**；证据下限 $N_{\min}$ 决定**什么时候可以据估计行动**。

两条杠杆也不是冗余的：**基于证据的退役只在已经挣到 $N_{\min}$ 次试验的技能上触发**（对一个年轻技能什么都没说）；**基于宽度的驱逐不考虑证据就触发**——更粗钝，但正是它界定了命题 1 的联合界所运行的集合。所以：**宽度是保持下限有限的东西，基于贡献的驱逐才是让书架能上升的东西。**

**命题 2（易错奖励下，保证不连续失效）。** 命题 1 需要贡献估计**无偏**，单元测试免费提供这一点，但**真正要部署的场景不提供**——它们是无参考的，用一个 LLM 裁判打分，而**裁判的误差是结构性的而不是随机的**。

二进制信道模型：

$$\Pr[\tilde{y}=1 \mid y=0] = \rho_{F\to P}, \quad \Pr[\tilde{y}=0 \mid y=1] = \rho_{P\to F}, \quad \kappa := 1 - \rho_{F\to P} - \rho_{P\to F} > 0$$

打分形式为 $p_{sc}(s) = \kappa\, \bar{p}(s) + \rho_{F\to P}$。驱逐要求真实通过率低于 $(\pi_\tau - \rho_{F\to P})/\kappa$。

### 5.3 关键数字

**① 可治理区域是一个矩形。**

| 边界 | 条件 | 后果 |
|---|---|---|
| 假通过率 $\rho_{F\to P} = \pi_\tau$ | $\pi_\tau = (1-\tau)/2$ | **无论样本量多大，什么也不会被驱逐**（「治理器已死」） |
| 幻影失败率 $\rho_{P\to F} = 1-\pi_\tau$ | — | **所有东西都可被驱逐**（「饿死」） |
| 理想单元测试评分器 | 位于**原点** | 安全且在分辨率上不受限 |
| 被审计的真实裁判（§6.1） | 以很大余量清过假通过阈值，但位于饿死边的另一侧 | 安全于致命方向，**并为此在分辨率上付出代价** |

定义可治理区域的两个精确不等式**都与坐标轴平行**，所以可治理区域是一个**矩形**，角点位于 $(\pi_\tau, 1-\pi_\tau)$。

**② 机制的方向性危害。**

- 一个**真实失败被判为通过**，会把**驱逐统计量推向唯一能阻止驱逐的方向**；
- 而且**恰恰对那些最需要被驱逐的技能位移最大**——最有问题的技能最容易被放过。

**③ 一条不能忽略的实测。**

**一个很低的证据下限配上一个零阈值，会把回路驱动到无技能对照组之下，比完全不做维护还糟。** 这否定了「先别设阈值，攒够证据再说」这个看似保守的做法。

**④ 特征审计。** 表 1 在**十六个系统与八条设计轴**上核查「编写得到了良好服务、维护没有」这一主张，显示的形状是：**编写列大体填满，治理区块几乎全空，其最右列由一个并行系统独自承担。** 请把它读作**特征存在性**，而不是**正面对比性能**。

### 5.4 边界与短板

- 二进制信道模型假设误差只在两个方向上、且不随条件变化；真实裁判的误差是**结构性**的，实际假通过率需要**单独测量**。
- 命题 2 在零误差时**退化为命题 1**——所以**保证与它的前提无法分开阅读**，引用时必须带上误差假设。
- 表 1 是特征存在性核查，不构成性能对比；论文自己也说明后者由第 5.1 节消融确立。
- 命题 1 的「下限」是一个界，不是一条预测曲线——它不说你会跌到哪，只说不会无限跌。

### 5.5 怎么用这篇

- **最适合**：给「技能库必须治理」提供形式化依据（**未维护技能库没有任何界，是推论不是断言**）；给「用 LLM 裁判决定技能去留」的团队提供验收清单——**先测 $\rho_{F\to P}$，因为它决定你的治理机制到底活着还是已经死了**。
- **不要拿来**：当作「治理一定有效」——命题 2 说的正是**治理不是单调有效的，存在一个悬崖**；也不要忽略「低证据下限 + 零阈值比不维护更糟」这条反向结论。

## 6. SkillMisevolve：21 组全部写出不安全技能

**Practice Makes Unsafe: Skill Misevolution in LLM Agents**
香港城市大学 / 阿德莱德大学 · arXiv:2608.12851

### 6.1 它要解决的问题

第 5 节讲的是「治理够不够强」，这一篇讲更冷的问题：**自演化这个动作本身，会不会生产危害。**

答案是：会，而且在论文测的 21 组（模型 × 场景）组合里，**全部都发生了**。

### 6.2 方法（基准怎么造的）

- **规模**：21 组组合，让智能体从经验中演化技能。
- **三道闸门**：**authoring（编写）/ retrieval（检索）/ execution（执行）**。
- **SAFEEVOLVE**：写入时 + 复用时**双重治理**。
- **机械设计**（推论）+ **配对删除器**（只能删除或收窄，不能新增）+ **复用归因** + **安全退役** + 三条结构不变式之外的**软隔离 / 退役 / 驱逐**。
- **测量**：独立裁判 + 人类两两一致性对照。
- **关键指标**：BU（良性效用）、M-ASR / B-ASR / C-ASR（攻击成功率，按暴露类型/会话位置区分）、U-A（不安全可用性）、URR（不安全复用率）、C-Util（跨会话效用）。

### 6.3 关键数字

**① 三个计数，一个比一个冷。**

| 阶段 | 结果 |
|---|---|
| 写出不安全技能 | **21/21 组全部** |
| 后续任务中检索到它 | **19 组** |
| **把危害带入新会话** | **15 组**（独立裁判下 14 组） |

**② 收益和危害同时发生。**

| 维度 | 演化有提升的组合数 |
|---|---|
| BU（良性效用） | **15/21** |
| M-ASR（攻击成功率） | **17/21** |

**「演化让智能体更强」和「演化让智能体更危险」是两个同时为真的陈述。**

**③ 危害来自暴露内容，不是演化机制。**

| 条件 | C-ASR | C-Util |
|---|---|---|
| 恶意暴露 | 13.1% | 50.1% |
| **替换为良性暴露** | **1.5%** | **52.9%** |

**几乎不损失效用（52.9% vs 50.1%）就消掉了绝大部分危害。** 这条直接指向缓解路径。

**④ 危害随轮次累积，效用同步上升。**

| 轮次 | C-ASR | C-Util |
|---|---|---|
| 无恶意暴露 | 16.0% | 30.0% |
| 一轮后 | **35.3%** | — |
| 三轮后 | 41.3% | **55.3%** |

**效用和危害同步上升，这是最坏的一种增长曲线。**

**⑤ 时间维度：写得越早越危险。**

| 暴露时机 | B-ASR |
|---|---|
| Early（早期暴露） | **40.7%** |
| Late（晚期暴露） | 19.8% |

危害写入得越早，越容易被后续良性任务复用——它已经变成库里的「常识」了。另有一个对照：Fully Mixed 在 Batched 模式的 2.5pp 以内。

**⑥ SAFEEVOLVE 的效果与代价。**

| 指标 | 无防御 | SAFEEVOLVE | 变化 |
|---|---|---|---|
| U-A | 37.4% | **18.8%** | −18.6 pp |
| URR | 35.3% | **8.7%** | −26.6 pp |
| C-ASR | — | **4.0%** | — |

消融验证三部件各自承重：

| 消融 | 指标变化 |
|---|---|
| −配对删除器 | C-ASR 4.0 → **7.3** |
| −复用归因 | B-ASR 4.4 → **8.2** |
| −安全退役 | URR → **17.3** |

**代价必须被点出**：SAFEEVOLVE 削掉 **17.3pp** 的 C-ASR，**同时损失 12.7pp** 的 C-Util；改进版 **SAFEEVOLVE-UP 削 16.0pp 只损 1.3pp，挽回了 11.3pp**。另有一个纯效用对照：Utility-only 策略 C-Util 72.0% 但 C-ASR 8.0%。

**⑦ 裁判可靠性的另一面。**

- 独立裁判一致性 **93.56%**，人类两两一致性 **93.78%**——裁判已经和人类一样可靠。
- 但请对照 Ratchet 命题 2：**一致性高不等于假通过率低。**

### 6.4 边界与短板

- 21 组组合是**构造性实验**，用于证明风险路径存在，**不代表 21/21 是生产环境的发生率**。
- SAFEEVOLVE 的效用损失（−12.7pp）与安全收益（−17.3pp）在同一量级，实际部署需要按场景权衡。
- 独立裁判一致性 93.56% 是在该论文的评分任务上测得的，跨任务外部效度未知。
- 「良性暴露替换」实验说明危害来源可隔离，但它测的是单一替换强度，未扫曲线。

### 6.5 怎么用这篇

- **最适合**：论证「技能演化必须配安全门」；给任何只报效用提升的技能演化工作一个必答问题——**你的 C-ASR 是多少**；同时它提供的「良性暴露替换」给出了一个近零成本（−0.9pp 效用）的缓解方向。
- **不要拿来**：当作「不应该做技能演化」——15/21 组 BU 提升是真的；它反对的是**只报收益不报安全的评估惯例**，不是演化本身。

## 7. SkillDAG：agent 可调用的图检索接口

**SkillDAG: Structured Retrieval over Skill Graphs for LLM Agents**
复旦大学 / 新加坡国立大学 / A\*STAR · arXiv:2606.03056（v2 2026-07-02）

### 7.1 它要解决的问题

第 3 节说技能库扩容的主因是**选不出来**。这一篇回答：怎么用结构化的方式把「选」这件事修好。

它的判断是：**图作为路由决策的接口，比作为一个不透明的策略更为有效。** 也就是说，不要把图当成内部策略让 agent 去猜，而要把它做成一个 **agent 可以调用**的结构化检索接口。

### 7.2 方法

- **五种边类型**：`depends_on`、`specializes`、`composes_with`、`similar_to`、`conflicts_with`。
- **三条结构不变式**：**无环性**（acyclicity）、**无矛盾性**（non-contradiction）、**仅追加可回滚**（append-only & rollback-able）。
- **两条操作约束**（配套不变式）。
- **agent 可调用结构化检索接口**：`search` 三字段（含 `matches` 字段的余弦）、三项能力。
- **在线图演化**：**propose-then-commit 两阶段**——提出与提交分离。
- **冷启动图构造**：**双视角嵌入**。

### 7.3 关键数字

**① 主结果：MiniMax-M2.7 上增益最大。**

| 模型 | 基准 | GoS 基线 | SkillDAG | 增益 |
|---|---|---|---|---|
| MiniMax-M2.7 | ALFWorld | 54.3 | **67.1** | **+12.8** |
| MiniMax-M2.7 | SkillsBench | 18.7 | **27.3** | **+8.6** |
| gpt-5.2-codex | ALFWorld | 93.6 | 93.6 | 打平 |
| gpt-5.2-codex | SkillsBench | 34.4 | **36.8** | **+2.4** |

论文给这条差异一个很清楚的解释：**「路由辅助」的签名在骨干无法越过一个糟糕的包进行推理时很大，而一旦它能，该签名就消失。** 也就是说，结构化检索救的是「模型不够强以致于选错就完蛋」的那部分损失。

**② 内在检索增益（在任何 agent 侧执行之前隔离）。**

| 指标 | GoS | SkillDAG |
|---|---|---|
| **Ret@K** | 65.5 | **78.2** |
| **Ret@1** | 50.6 | **66.7** |
| **MRR** | 57.3 | **71.3** |

在嵌入与查询固定的情况下，SkillDAG 基于**带类型图节点嵌入的 `matches` 字段余弦**，比 GoS 的 HNSW 播种 + PPR 扩散**排序得更准**。这隔离出一条**离线检索流水线**的增益。

**③ 规模鲁棒性：10 倍池扩张只丢 3.5 点。**

| 技能池规模 | SkillDAG 相对 GoS 的增益（Ret@5 / Ret@1 / MRR） |
|---|---|
| 200 | +16.1 / +17.2 / +17.2 |
| 500 | +4.6 / +6.9 / +6.3（**差距最窄**——GoS 的 PPR 拉力恰好与金标语目标对齐） |
| 2000 | +13.8 / +16.1 / +16.3 |

**整个 10 倍池扩张中，SkillDAG 的 Ret@5 只损失 3.5 个点（78.2 → 74.7）**，且**每个技能池规模的每个检索指标上都胜过 GoS**——**尽管不使用任何扩散步骤**。

**④ 已提交的边是持久结构，不是训练噪声。**

| 阶段 | MiniMax-M2.7 | gpt-5.2-codex |
|---|---|---|

训练与 test-initial 的差距在 **2.1 个百分点以内**，且 **test-edited 恢复到训练的数字**——迁移在留出切分上成立。

另外，ALFWorld 冷启动图有 **2,359 条边**（Mean GT/q 1.915），编辑后 **2,386 条边**（**1.984**），**+27 条在线编辑**。

### 7.4 边界与短板

- 增益高度依赖骨干：MiniMax-M2.7 +12.8 vs gpt-5.2-codex 打平——**强骨干上收益趋近于零**，这是选择是否引入图结构的直接判据。
- +16.1 / +4.6 / +13.8 的非单调形态说明 GoS 的 PPR 在特定规模会**偶然对齐**金标，规模扫描的样本量限制了这个结论的精度。
- 「10 倍池扩张」测试的是**离线检索流水线**，不是 agent 执行期间使用的带类型边 `neighbors`/`conflicts` 字段——两者不要混为一谈。
- 在线编辑量（+27 边）相对初始图（2,359 边）很小，长期演化下的图规模控制策略未被充分评估。

### 7.5 怎么用这篇

- **最适合**：论证「检索侧结构化能对抗规模退化」——它是第 3 节遮蔽问题的直接解法；给「要不要引入技能图」提供一条判据：**看你的骨干在选错技能时能不能自己恢复**。
- **不要拿来**：当作「图一定赢」——在 gpt-5.2-codex 上 ALFWorld 完全打平；也不要把它和 SE-GoS 的 +7.0 直接比较，两者基线设定不同（一篇对 GoS 带类型图，一篇从纯语义冷启动图出发）。

## 8. SE-GoS：离线图演化，和它的轮次上限

**SE-GoS: Self-Evolving Graph of Skills from Execution Traces**
腾讯 / 北京大学 / 爱丁堡大学 / 西北工业大学 / 清华大学 · arXiv:2609.08228

### 8.1 它要解决的问题

与 SkillDAG 同题不同路：SkillDAG 做**在线结构化检索**，SE-GoS 做**离线轨迹驱动演化**。它要回答的是：能不能**不训练模型、不改技能文件**，只靠执行轨迹把技能图演化得更好。

它的三类更新有一个共同特征：**节点更新只重写图节点的面向检索的描述字段，所以被改变的是检索器对某个技能的看法，而不是技能本身。**

### 8.2 方法（三类免训练更新）

| 通道 | 更新内容 | 证据来源 | 权重公式 |
|---|---|---|---|
| **拓扑** | workflow / dependency / avoid 边 | 执行证据归纳 | $\min(0.9, 0.6 + 0.05(c^r_{uv}-1))$，avoid 边权重 **0** |
| **边权** | 软语义衰减 + 正向强化 | 奖励信号 | $\eta \cdot r_t$ 累加，失败不贡献正向信用 |
| **节点描述** | 单轮文本梯度 | 检索包外被使用的技能 | 只改描述字段 |

关键设计细节：

- **四类关系**：semantic（确定性 token 重叠相似度图）、workflow（稀疏 LLM 关系验证器，每节点预算 $k=8$）、dependency（生产者输出与消费者输入匹配）、avoid（**SE-GoS 新增**）。
- **avoid 边**：在失败尝试中至少被共用 $\theta_{\text{avoid}}$ 次、且从未在成功尝试中共用。权重为零、永不被遍历，**不增加扩散质量**，只在执行包组装阶段影响检索。若候选的 avoid 伙伴已被选中，该候选被丢弃，且**不从预排序 top-$N$ 列表之下回填**——所以最终包可能小于 $N$。
- **无矛盾不变式**：一个已拥有任何导航关系（包括语义边）的无序对，不会再被赋予 avoid 边。这会漏掉语义相似技能之间的有害配对，但避免在同一对上放置互相矛盾的信号。
- **avoid 边的撤回**：只有在当前演化窗口内该对至少被共用出现在**两条不同的成功任务轨迹**中才撤回。**单纯的未使用绝不删除边。**
- **检索**：词法播种 + 反向感知 Personalized PageRank（top-$N=5$ / seed-$K=4$、每技能 1,800 字符 / 全局 9,000 字符预算），运行在官方 **1,000 技能节点（863 条语义边）**的确定性 token 重叠 $k=1$ 图上。
- **不使用 GoS 的 `alternative` 关系**——理由是「一个技能能否替代另一个」是关于一次**并未发生**的执行的主张。

### 8.3 关键数字

**① 单轮演化的主结果。**

| 方法 | SkillsBench |
|---|---|
| Vanilla | 46.2% |
| Vector | 38.7% |
| 原始 GoS 图 | 52.4% |
| **SE-GoS（一轮）** | **59.4%（相对 GoS +7.0）** |
| SkillDAG | 55.3% |

每次尝试 **3.45M 输入 token（比 Vanilla 低 32%）**，且领先平铺检索、向量检索与自演化基线。

跨骨干：

| 骨干 | 相对 GoS 提升 |
|---|---|
| minimax-m2.7 | **+9.8**（18.7 → 28.5） |
| gpt-5.2-codex | **+3.7**（34.4 → 38.1） |

**增益在静态图得分最低处（18.7%）最大**——与 SkillDAG 的观察一致：结构化检索救的是本来选错就完蛋的那部分。

**② 留出切分证明它累积的是结构，不是记忆。**

| 切分 | SkillsBench | 输入 token |
|---|---|---|
| 原始 | 52.9% | — |
| 演化后 | **58.3%（+5.4）** | 3.30 → **3.19M** |

**同一张图把一个它从未见过的留出切分提升了 5.4 个百分点**，token 还降了——所以它累积的是**可迁移的结构**，而不是记住了轨迹。

**③ 多轮演化：第三轮崩。**

| 轮次 | SkillsBench | 边数 |
|---|---|---|
| r1 | 59.4% | 1,118 |
| r2 | 59.8% | 1,375 |
| **r3** | **54.0%** | 1,502 |

**边数还在涨（1,118 → 1,502），性能却塌了 5.8 个点。** 论文的表述是「重复该轮次没有帮助」——数据比这个说法更严厉：**第三轮是负面的**。这说明演化有轮次上限，**单轮一次性收益最好**。

**④ 组件消融：边权贡献最大。**

| 组件 | 贡献 |
|---|---|
| 边权 | **+6.5** |
| 拓扑 | +3.3 |
| 节点描述 | +2.8 |

**⑤ 边界条目审计：最诚实的一处。**

- `avoid` 通道：51 个提议 − 24 个扣下 = **27 条 avoid 边**；
- `dependency` 通道：68 个有序对中只有 26 对有 I/O 字段，最大重叠 **0.500 < ζ = 0.6**，**最终零条 dependency 边**；
- 1,000 条技能库中只有 **332 条有 inputs、337 条有 outputs**。

**技能库的元数据完整度本身就是瓶颈**——一半以上的技能连 I/O 字段都没有，dependency 通道因此在原理上无法工作。这条发现的价值不亚于主结果：它说明**结构化检索的上限受限于技能库的元数据卫生**。

### 8.4 边界与短板

- 第三轮下降是**单次实验**的结果；多轮演化的最优轮次可能随任务分布与技能库初始状态变化，不能直接推广为「永远只做一轮」。
- 主表比较中的 GoS 基线用**原始带类型图**，而 SE-GoS 从**纯语义冷启动图**出发——两者不是同一个起点，+7.0 的解释需要带上这个前提。
- 正向强化是对目标入边的**全局**更新，**不是对某个被检索源的因果归因**——所以它会把「恰好一起成功」的关系也强化。
- dependency 通道因元数据缺失而**零产出**，所以论文实际上只验证了两类关系（workflow、avoid），第三类未被有效检验。
- 只在 SkillsBench 与官方 1,000 技能节点上评估。

### 8.5 怎么用这篇

- **最适合**：论证「轨迹驱动演化可以免训练、不改技能文件」；同时它给出一个反直觉的运维结论——**演化要做，但只做一轮**；以及一条容易被忽略的前置要求——**先把技能库的元数据补全，否则结构化检索有通道会直接哑火**。
- **不要拿来**：当作「SE-GoS 优于 SkillDAG」——55.3% vs 59.4% 是在 SkillsBench 单基准上的读数，且两者对 GoS 的处理不同；也不要忽略第三轮 54.0% 这个数字，它是对「持续演化」这个叙事的直接反驳。

## 9. HarnessCL：把持续学习对象整体挪走

**Harness Continual Learning: Continual Learning Beyond Model Parameters**
arXiv:2608.19013 · 项目页 <https://boringkey.github.io/Harness-Continual-Learning>

### 9.1 它要解决的问题

持续学习研究「一个系统如何从序列经验中习得能力，同时保持此前学到的行为」。既有形式化主要通过**改变模型参数、表示或架构组件**来实现——论文称之为**以模型为中心的持续学习**。

但现代智能体还有另一个适应来源：**harness**。而 harness 有一个模型参数不具备的危险性质——**一次 harness 更新可以在模型冻结的情况下破坏此前可靠的行为**。因为提示、记忆、工具、技能规范、路由策略**共同塑造后续执行**。

所以这篇要回答的新问题是：**一个智能体如何能在模型之外持续改进它的状态，同时保留早先习得的行为？**

### 9.2 方法

- **形式化 HCL**：harness 围绕一个**冻结的基础模型**演化。
- **harness 级遗忘（harness-level forgetting）**：由此产生的「早先行为损失」。
- **四个面向执行的组件**：**任务接口（Task Interface）、经验记忆（Experience Memory）、能力地图（Capability Map）、自适应路由器（Adaptive Router）**。
- **受守卫的 harness 演化**：把「更新的生成」与「状态的提交」分开——**持续优化器（Continual Optimizer）**从执行后反馈中提出候选 harness，**持续评估器（Continual Evaluator）**只有在检查了**当前改进、历史保持与有效性**之后，才提交候选。

这个「提出—守卫—提交」的结构与 SkillDAG 的 propose-then-commit、SE-GoS 的「单轮离线应用」形成三处呼应：**三条独立路线都收敛到「生成与提交必须分离」。**

### 9.3 关键数字

**① 主结果：Plasticity-HCL 62.98% vs Static 47.12%。**

| 方法 | 最终平均成功率 | 平均遗忘 |
|---|---|---|
| Static Harness | **47.12%** | – |
| **Plasticity-HCL（本文）** | **62.98%** | 10.94% |
| 最好的非 HCL 基线 | 55.56% | – |

**15.86 个百分点的差距**，代价是 **10.94% 的平均遗忘**——这就是**可控的稳定性—可塑性权衡**。

**② 更强模型放在哪里：位置比强度更重要。**

| 配置 | 最终四任务性能 | 在线推理延迟 |
|---|---|---|
| Base-HCL（纯 Qwen3-4B 驱动） | 35.10% | 9.95 s/样例 |
| **Opt-HCL**（强模型放优化器位置） | **45.75%** | **9.72 s/样例** |
| Online-HCL（强模型放在线推理位置） | 44.80% | **39.31 s/样例** |

**Opt-HCL 相对 Base-HCL 提升 10.65 个百分点，在线延迟几乎不变（9.72 vs 9.95 秒/样例）。** 对比之下，把强模型放到在线推理位置（Online-HCL）性能更低（44.80%）而延迟高 4 倍（39.31 秒）。

**这是本轮最可操作的一条工程结论：算力应该花在优化器上，不是花在在线推理上。**

**③ 能力累积与失败恢复。**

- 在**开放世界能力累积、文本推理与多模态感知**上的实验展示了能力累积与**失败恢复**，在多个设定中相对对应基线达到**超过 10%** 的相对增益。
- 补充实验考察了**通过 harness 演化的知识迁移**；分量消融评估了每个 harness 组件的贡献；**受控的保持扫描揭示了可测量的 harness 级遗忘**，并演示了一个可控的稳定性—可塑性权衡。

**④ 一条关键对照。** Static Harness 在 Minecraft 中**跟随 HCL 15 个任务后进入平台期**——这直接说明静态 harness 的问题不是「起点低」，而是**不会累积**。

### 9.4 边界与短板

- 「超过 10%」是**相对增益**，不是绝对百分点；与第 3 节的 21% 之类的绝对降幅不可直接比较。
- 62.98% vs 47.12% 是各方法在其评测上的最终平均成功率，训练配置与评测协议不同源。
- 10.94% 的平均遗忘是**已付款**的代价，论文没有给出「零遗忘」的配置——稳定—可塑性权衡是可控的，但不是可消除的。
- harness 级遗忘的定义依赖「早先习得行为」的判定口径，换口径会改变遗忘数值。
- 评估集中在 Minecraft 类开放世界与部分文本/多模态任务，跨域泛化未充分覆盖。

### 9.5 怎么用这篇

- **最适合**：论证「持续学习的对象是 harness，不是模型参数」——它把 Externalization 的「harness 是统一层」从框架命题变成了**可测量对象**；并给出最可操作的一条配置建议：**强模型放优化器，不放在线推理**。
- **不要拿来**：当作「harness 演化没有代价」——10.94% 的遗忘是实测代价；也不要把 62.98% 与其他论文的成功率横比，口径不同源。

## 10. Recuris：程序化记忆与技能选择的链路

### 10.5 怎么用这篇

## 11. MA-Memory：多 agent 记忆的体系结构视角

**Multi-Agent Memory from a Computer Architecture Perspective**
arXiv:2603.10062（路线图第 4 轮原定论文，3 页愿景文）

### 11.1 它要解决的问题

当 LLM 智能体演进为协作式多智能体系统，它们的记忆需求迅速复杂化。这篇立场文把多智能体记忆**框定为一个计算机体系结构问题**，并指出一个类比：**在计算机系统中，性能与可扩展性常常不是被计算限制，而是被内存层次、带宽与一致性限制。多智能体系统正走向同一堵墙——只不过它们的「内存」不是原始字节，而是用于推理的语义上下文。**

因此上下文不再是静态提示词，而是一个**带有带宽、缓存与一致性约束的动态记忆系统**。

### 11.2 方法（框架怎么搭的）

- **两种范式**：

| 范式 | 优点 | 需要 |
|---|---|---|
| **共享内存** | 知识复用容易 | **一致性支持** |
| **分布式内存** | 隔离性与可扩展性 | **显式同步** |

缺少协调时，共享内存下智能体会**互相覆写、读到过期信息，或依赖于同一共享事实的不一致版本**；分布式内存下**状态分叉**会变得常见。大多数真实系统位于两个极端之间：**本地工作记忆 + 有选择地共享的制品**。

- **三层记忆层次结构**：**I/O 层、缓存层、内存层**。
- **两个协议缺口**：**跨智能体的缓存共享**，以及**结构化的记忆访问控制**。
- **最紧迫的开放挑战**：**多智能体记忆一致性**。

### 11.3 关键数字

**这是一篇 3 页立场文，没有实验。** 它提供的对照是概念性的——传统内存体系结构 vs 智能体记忆 vs 多智能体记忆：

| 维度 | 映射对象 | 关键性质 | 目标 |
|---|---|---|---|
| 体系结构内存一致性 | 内存地址 → 共享信息 | 硬件级保证；定义良好的模型（Sequential、TSO 等）；原子性、同步原语、重排序约束 | 读写顺序 |
| 智能体记忆一致性 | 语义上下文 | 时间一致；与上下文相关的检索；对新信息的更新 / 对旧信息的删除；冲突解决；个性化 | 维持连贯的上下文 |
| 多智能体记忆一致性 | 共享信息 | 共享内存 / 分布式内存；一致性模型支持；智能体间通信；冲突解决 | 协调共享信息 |

### 11.4 边界与短板

- **无实验**，所有主张为论证性的；不能用来支撑任何量化结论。
- 体系结构类比是启发性的——CPU 内存一致性有硬件保证的强语义，而语义上下文的一致性没有对应的形式化定义，类比在这一点上会失效。
- 三层结构（I/O / 缓存 / 内存）的切分与现有 agent 系统的实际模块划分不完全对齐。
- 与第 7 篇的 MELD（per-claim CRDT 合并）属于同一问题域，但本篇停留在框架层，未提供协议。

### 11.5 怎么用这篇

- **最适合**：为跨 agent 记忆提供**元层语言**——用「共享 vs 分布式」「层次」「一致性模型」「协议缺口」这四个词，能让跨 agent 的讨论从「同步不同步」推进到「一致性模型是什么」。
- **不要拿来**：作为任何数值结论的依据；也不要指望它给出协议——它明确指出这是**开放挑战**。

## 12. 十一篇合起来看

### 12.1 它们各自修正了什么

| 第 8 篇正文容易出现的预设 | 十一篇之后的修正 |
|---|---|
| 技能库越大，能力越强 | **单调下降**：52 → 102 → 202 条技能，通过率降幅 8% → 14% → **21%**（SkillShadowing）。且扩容一个数量级后模式是否成立仍开放 |
| 技能库退化的主因是上下文塞不下 | **主因是被遮蔽**：Δshd 是唯一置信区间不含零的分量，占 68%；Δctx 点估计为正但任何规模下都未与零分离（SkillShadowing） |
| 把成功轨迹蒸馏成技能是净收益 | **有损抽象瓶颈**：原始轨迹复用常优于蒸馏技能；静态精选技能库平均 ESR **−2.44pp**，比 No-Skill 还差（SkillEvolBench） |
| 一条技能要么有用要么没用，可以全局淘汰 | **因果异质**：90%+ 技能在不同任务类型上帮助/伤害方向相反，相反效应聚合时相互抵消，**对全局治理完全不可见**（ASSAY） |
| 有了阈值和证据下限，技能库就不会退化 | **治理有悬崖**：命题 1 给下限（有限性来自宽度 $C$ 与余量 $\tau$），命题 2 说假通过率达到 $\pi_\tau=(1-\tau)/2$ 时**无论样本量多大什么都不会被驱逐**（Ratchet） |
| 技能库能自演化是能力，不是风险 | **演化会生产危害**：21/21 组写出不安全技能，19 组检索到，**15 组带入新会话**；且 15/21 组 BU 提升与 17/21 组 M-ASR 提升同时发生（SkillMisevolve） |
| 图结构检索一定优于基线 | **取决于骨干**：MiniMax-M2.7 +12.8，gpt-5.2-codex 打平（SkillDAG 的 ALFWorld）——**路由辅助的签名在骨干无法越过糟糕的包时很大，一旦能就消失** |
| 持续演化越久越好 | **有轮次上限**：SE-GoS 单轮 52.4 → 59.4，第 3 轮**掉回 54.0%**（边数还在从 1,118 涨到 1,502） |
| 持续学习的对象是模型参数 | **对象整体挪走了**：harness 围绕冻结模型演化，Plasticity-HCL **62.98%** vs Static **47.12%**，代价是 10.94% 遗忘（HarnessCL） |
| 技能库有元数据是常态 | **元数据是瓶颈**：SE-GoS 的 1,000 技能库中只有 332 条有 inputs、337 条有 outputs，**dependency 通道零产出** |
| 多 agent 记忆只是「同步问题」 | **是一致性问题**：共享内存需要一致性支持、分布式内存需要显式同步，最紧迫的开放挑战是**多智能体记忆一致性**（MA-Memory） |

### 12.2 三条路线的成本结构

| 路线 | 代表 | 成本付在哪 | 换来什么 | 代价 |
|---|---|---|---|---|
| **扩容技能库** | SkillShadowing 的 202 条库 | 检索侧选择开销 | 覆盖更多任务类型 | 通过率 −21%，其中 68% 是遮蔽；扩容一个数量级后模式未知 |
| **抽象/蒸馏技能** | SkillEvolBench 的 Curated-Static、Raw-Trajectory | 一次性蒸馏 + 元数据维护 | 紧凑表示、可组合性 | 有损抽象瓶颈；静态精选平均 −2.44pp；CompSR 在 E6 为 **0.0%** |
| **结构化管理（图/接口/演化）** | SkillDAG、SE-GoS | LLM 抽取/验证 + 图构建 + 元数据补全 | 检索 Ret@K +12.7；规模鲁棒（10× 只丢 3.5 点）；离线演化 +7.0 | 强骨干上增益趋零；演化有轮次上限；元数据不全会哑火 |
| **治理与安全** | Ratchet、SkillMisevolve 的 SAFEEVOLVE | 证据下限 $N_{\min}$ + 裁判成本 | 有下限、可审计 | SAFEEVOLVE 削 17.3pp C-ASR 同损 12.7pp C-Util；改进版削 16.0pp 只损 1.3pp |

### 12.3 三条不许商量的下限

不管走哪条路线，下面三条已被独立实测，属于**不可商量**的边界：

1. **技能库必须有治理，且必须知道治理器还活着。** Ratchet 命题 1 说未维护技能库**没有任何界**（这是推论不是断言）；命题 2 说假通过率达到 $\pi_\tau$ 时治理器已死。**部署前必须测 $\rho_{F\to P}$。**
2. **不要默认抽象优于原始。** SkillEvolBench 的 Raw-Trajectory 常常赢过蒸馏技能、静态精选比 No-Skill 还差 2.44pp；任何「我们把经验总结成了技能」的声明，**都必须附上和原始轨迹复用的对照**。
3. **演化必须配安全门，而且只做有限轮。** SkillMisevolve 的 21/21 与 15/21 说明危害产生是路径性的不是偶然的；SE-GoS 的第 3 轮 54.0% 说明演化有轮次上限——**「持续演化」不是一个可以无限运行的过程。**

外加一条被两篇独立印证的负向结论：**不要指望「更强的模型」自动解决选择与安全问题。** SkillDAG 在 gpt-5.2-codex 上 ALFWorld 完全打平（增益消失），SkillEvolBench 里 Tier-3 资源在 Gemini 3 Flash 上从 35.6% 掉到 27.8%（过载）。**结构化的收益与模型的强度是替代关系，不是叠加关系**——这既是坏消息（不能靠换模型解决），也是好消息（弱模型上结构化收益最大）。

### 12.4 三处独立收敛的设计模式

十一篇里有三处独立收敛，值得单独记为模式：

| 模式 | 出处 | 形式 |
|---|---|---|
| **生成与提交分离** | SkillDAG 的 propose-then-commit、HarnessCL 的「持续优化器提候选 / 持续评估器提交」、SE-GoS 的「单轮离线应用」 | 提出更新的通道 ≠ 接受更新的通道 |
| **按条件而非全局做决策** | ASSAY 的按任务掩码、SkillShadowing 的遮蔽诊断、SE-GoS 的 avoid 边 | 全局平均会掩盖方向相反的效应 |
| **用结构换规模** | SkillDAG 的带类型边、SE-GoS 的关系归纳、Ratchet 的固定宽度书架 $C=50$ | 结构化的检索/容量约束把「更好」变成「不退化」 |
